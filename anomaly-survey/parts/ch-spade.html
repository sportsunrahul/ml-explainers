Pretrained features already know what normal looks like

Chapter 1 used hand-made toy features. SPADE takes its features from a network pretrained on ImageNet photos. It then finds and outlines defects by nearest-neighbor search alone, with no training at all.

Select a patch on the scratch: its best match among the retrieved caps is still far away, so the scratch lights up. Now inspect the cap with a hole and predict: will SPADE flag the hole? It does not. The hole patch finds an almost perfect match, and the line shows where: a bolt hole on another cap. SPADE asks only "does this patch look like some normal patch?", and never "does it belong here?". Chapter 5 adds that second question.

Why ImageNet features work on defects

A convolutional network trained to classify ImageNet photos learns a general vocabulary of edges, textures and parts. Its feature maps describe every region of an image with a vector. Two clean patches of brushed metal get similar vectors; a scratch gets a vector that no clean patch has. The network never saw a defect, but it does not need to: it only needs to describe patches well enough that "unlike anything normal" shows up as distance. DN2 (arXiv 2002.10445) showed this for whole images. SPADE (Cohen and Hoshen, first posted 2020-05-05) extends it to every pixel.

Stage 1: find the most similar normal images

SPADE runs each image through a Wide-ResNet50x2 pretrained on ImageNet, after resizing to 256 pixels and cropping to 224. The output of the last block is averaged over all positions into one 2048-dimensional vector per image. For a test image, SPADE finds the K nearest normal images by this vector (K = 50 on MVTec AD). The image score is the mean squared distance to them:

\htmlData{step=1, link=img}{d(\htmlClass{t-yellow}{y})} = \htmlData{step=2, link=knn}{\frac{1}{K} \sum_{\htmlClass{t-blue}{f} \in N_K(f_{\htmlClass{t-yellow}{y}})}} \htmlData{step=3, link=dist}{\big\lVert \htmlClass{t-blue}{f} - f_{\htmlClass{t-yellow}{y}} \big\rVert^2}

Eq. 2 in SPADE v3.

  • \htmlClass{t-yellow}{y} is the test image and f_{\htmlClass{t-yellow}{y}} its pooled feature vector.
  • N_K(f_{\htmlClass{t-yellow}{y}}) is the set of the K nearest pooled features of normal training images; \htmlClass{t-blue}{f} is one of them.
  • The score is their mean squared Euclidean distance. A high score flags the whole image. This is exactly DN2's score.

This image score comes from pooled features, not from the pixel map. PaDiM and PatchCore later take the image score as the maximum of the map instead.

Stage 2: match every pixel against the retrieved images

For localization, SPADE keeps a feature vector for every pixel position, taken from the ends of the first three blocks, at 56, 28 and 14 positions per side. The fine block sees small detail; the coarse blocks see more context. All pixel vectors of the K retrieved images form a gallery G. Each test pixel is scored against that gallery only, which keeps the search small:

\htmlData{step=1, link=pix}{d(\htmlClass{t-yellow}{y}, p)} = \htmlData{step=2, link=gallery}{\frac{1}{\kappa} \sum_{\htmlClass{t-blue}{f} \in N_\kappa(F(\htmlClass{t-yellow}{y}, p))}} \htmlData{step=3, link=match}{\big\lVert \htmlClass{t-blue}{f} - F(\htmlClass{t-yellow}{y}, p) \big\rVert^2}

Eq. 3 in SPADE v3.

  • F(\htmlClass{t-yellow}{y}, p) is the pyramid feature of the test image at pixel p.
  • N_\kappa picks its \kappa nearest features in the gallery G. The paper uses \kappa = 1 in all experiments, so the score is the squared distance to the single nearest gallery feature: the red segment in the figure.
  • The map is then smoothed with a Gaussian filter of width 4 pixels.

The nearest gallery feature is a correspondence: it names one pixel in one normal image that looks like the test pixel. That is the "deep pyramid correspondences" of the title, and it is what the figure's line draws. Using all three blocks matters. With only the finest block the PRO score on MVTec AD falls to 87.74, against 91.7 with all three (Table 6).

How well it works, and what it costs

On MVTec AD, SPADE reaches a pixel AUROC of 96.0 and a PRO of 91.7 (Tables 2 and 3). Its image AUROC, from stage 1, is 85.5 (Table 1). Chapter 2 explains these three metrics. The weak spot is cost: every test image needs a search over pixel features of normal images. PaDiM's authors re-ran SPADE and measured 7.10 seconds per image on a CPU, an Intel i7-4710HQ (the PaDiM paper reports no GPU timing; chapter 6 gives the PatchCore authors' GPU re-run) and 1.4 GB of memory on MVTec AD (PaDiM, Tables VII and VIII).

Inside SPADE: forward, then backward

Related work in this branch: Patch SVDD (arXiv 2006.16067) trains patch features with a patch-level SVDD loss plus a self-supervised task and scores each patch by its distance to the nearest normal patch; it reports an image AUROC of 0.921 on MVTec AD (Table 1). The MVTec AD paper itself evaluated reconstruction baselines, among them an autoencoder trained with a structural-similarity loss, the method of arXiv 1807.02011 (MVTec AD, Sec. 4.1). Feature-based scores overtook them: in SPADE's Table 3, that autoencoder has a PRO of 69.4 against SPADE's 91.7 (SPADE copies this baseline row from the Uninformed Students paper, which re-evaluated the autoencoder with PRO).
