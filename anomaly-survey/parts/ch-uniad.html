One model for every product

Every method so far trains one model per product, and a factory has hundreds of products. One model for all of them sounds easy, but a single reconstruction model fails in a specific way: it learns to copy its input, defects included.

Start with full attention and select a token on the scratch. Predict first: if a token may look at itself, where will it look? At itself, and at the overlapping tokens beside it that look almost the same: nothing is more similar to a token than the token. So every token is rebuilt from itself, the scratch is copied, and the error map stays nearly blank. Now press "Neighbor mask". The token cannot see itself or its neighbors, so it must rebuild itself from look-alikes elsewhere on the mesh. Normal texture has look-alikes everywhere; the scratch has none outside its own window, so it lights up.

One model per product does not scale

The setting so far has been separate: one model per category, trained on that category's good images. UniAD (NeurIPS 2022, first posted 2022-06-08) asks for the unified setting: one model trained on good images of all 15 MVTec AD categories together, with no category label at training or test time. The benchmarks now call this the multi-class setting.

UniAD is a reconstruction method. A network learns to rebuild the features of good images; at test time, whatever it fails to rebuild is anomalous. That works only if the network rebuilds normal content and nothing else. In practice it can learn a shortcut: return the input unchanged. The paper calls this the identical shortcut. The model then rebuilds defects as well as anything else, and the error map goes blank. Learning the joint appearance of fifteen products is hard, so in the unified setting copying becomes the easy way out. The paper shows the effect directly: its baseline networks drive the training loss toward zero while the test AUROC peaks early and then falls.

A query trained on normal data cannot point at an anomalous token, so the anomaly is not copied.

Three ways to stop the copy

UniAD rebuilds frozen CNN features with a transformer that is built so that it cannot copy:

  1. A learned query in every decoder layer. Each of the 4 decoder layers starts from its own learned query embedding and reads the encoder output through attention, so no output is a direct function of its own input token.
  2. Neighbor-masked attention. In every attention map, a token may not attend to keys in its own 7 by 7 neighborhood, itself included, on the 14 by 14 token grid. The figure's mask is this rule.
  3. Feature jittering. During training, Gaussian noise is added to the input tokens, while the target stays the clean feature. Training becomes denoising, and a copy of a noisy input is a bad answer.
\htmlData{step=1}{D \sim \mathcal{N}\!\Big(\mu = 0,\ \sigma^2 = \big(\alpha\,\tfrac{\lVert \bm{f}_{tok} \rVert_2}{C}\big)^2\Big)}

Eq. 3 in UniAD v3. \bm{f}_{tok} is one token, C its channel count, \alpha the jitter scale (20), added with probability 1.

Which fix matters most? The ablation (Table 5a, unified MVTec AD, image AUROC) answers it. Without any query, the transformer scores 69.5. A query in the first decoder layer only, as in a vanilla transformer, lifts it to 87.6, and a query in every layer to 95.0. The neighbor mask on top of one query alone reaches 96.1, and all three together 96.5. The mask size matters too: masking only the token itself (1 by 1) gives 94.6, because the neighbors still leak the token's content.

Does one model for all really cost accuracy?

UniAD re-ran earlier methods in the unified setting with public code, and set them beside one-model-per-category numbers that it says come from each method's own paper (Table 1, MVTec AD image AUROC). UniAD runs its own model at 224 pixels; it does not state the resolution of the re-runs. ADer, a later benchmark, re-ran methods in the multi-class setting under one protocol (256 by 256 pixels, the final epoch after 100 or 300 epochs, one L40S GPU). The protocols differ, so read each column on its own.

Two cells of the first column need care. PaDiM's 95.5 matches DRAEM's run of PaDiM, class by class, not PaDiM's own paper, which reports 95.3. CutPaste's 96.1 does come from the CutPaste paper, but it is the ensemble of five models; one three-class model scores 95.2.

Three things stand out. Methods that learn from fake defects or density fits lose the most when one model must cover every product; DRAEM even falls to near chance in ADer's runs, far below UniAD's own re-run of it. The two re-runs disagree, and this page does not try to reconcile them. Second, UniAD needs long training: ADer's 100-epoch run is several points below its 300-epoch run, and the original paper trains for 1000 epochs. Third, and most surprising, PatchCore does not collapse at all: one memory bank holding every product's patches is the best row in ADer's MVTec AD table. Its cost is elsewhere. On MVTec AD its test run takes 9h22m in total (UniAD's takes 22s), and on VisA it runs out of memory (OOM). These are totals for the whole test set, not per-image latencies.

Inside UniAD: forward, then backward

Limits and what came next

UniAD needs long training, and the paper reports neither latency nor VisA. Later multi-class designs replaced its transformer: HVQ-Trans (2310.14228) with vector quantization, DiAD (2312.06607) with diffusion, MambaAD (2404.06564) with state-space layers, and Dinomaly with a DINOv2 backbone (chapter 14).
