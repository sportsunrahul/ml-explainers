## 2. Core problem
Unify model-based methods (planning: DP, heuristic search) and model-free methods (MC, TD), and intermix them online.

## 3. What prior methods did and why that hurt
Section 8.2 (p.162) on direct vs indirect RL: "Indirect methods often make fuller use of a limited amount of
experience and thus achieve a better policy with fewer environmental interactions. On the other hand, direct
methods are much simpler and are not affected by biases in the design of the model."

## 4. The one key idea
Planning and learning share one update rule; they differ only in where the experience comes from. "whereas planning
uses simulated experience generated by a model, learning methods use real experience generated by the environment"
(p.161). In Dyna-Q, "the same reinforcement learning method is used both for learning from real experience and for
planning from simulated experience" (p.163).

## 5. Definitions and mechanism

Definitions (Section 8.1-8.2):
- Model (p.159): "By a model of the environment we mean anything that an agent can use to predict how the
  environment will respond to its actions. Given a state and an action, a model produces a prediction of the
  resultant next state and next reward."
- Distribution vs sample models (p.159): distribution models give "all possibilities and their probabilities";
  sample models give "just one of the possibilities, sampled according to the probabilities". DP's p(s', r|s, a)
  is a distribution model (p.160).
- Planning (p.160): "any computational process that takes a model as input and produces or improves a policy for
  interacting with the modeled environment". State-space planning: value functions over states, computed "by
  updates or backup operations applied to simulated experience" (p.160).
- Model-learning vs direct RL (p.162): real experience "can be used to improve the model ... and it can be used to
  directly improve the value function and policy ... The former we call model-learning, and the latter we call
  direct reinforcement learning (direct RL)." Improving values via the model "is sometimes called indirect
  reinforcement learning".
- Search control (p.163): "the process that selects the starting states and actions for the simulated experiences
  generated by the model."
- Dyna architecture (Figure 8.1, p.163): "Real experience, passing back and forth between the environment and the
  policy, affects policy and value functions in much the same way as does simulated experience generated by the
  model of the environment." Dyna-Q's model is a table that "assumes the environment is deterministic": after
  S_t, A_t -> R_{t+1}, S_{t+1} it records that R_{t+1}, S_{t+1} "will deterministically follow" (p.162).

Random-sample one-step tabular Q-planning (box, p.161, PDF 183):
```
Loop forever:
    1. Select a state, S in S, and an action, A in A(S), at random
    2. Send S, A to a sample model, and obtain
       a sample next reward, R, and a sample next state, S'
    3. Apply one-step tabular Q-learning to S, A, R, S':
       Q(S,A) <- Q(S,A) + alpha [R + gamma max_a Q(S',a) - Q(S,A)]
```

Tabular Dyna-Q (box, p.164, PDF 186):
```
Initialize Q(s,a) and Model(s,a) for all s in S and a in A(s)
Loop forever:
    (a) S <- current (nonterminal) state
    (b) A <- epsilon-greedy(S, Q)
    (c) Take action A; observe resultant reward, R, and state, S'
    (d) Q(S,A) <- Q(S,A) + alpha [R + gamma max_a Q(S',a) - Q(S,A)]
    (e) Model(S,A) <- R, S' (assuming deterministic environment)
    (f) Loop repeat n times:
            S <- random previously observed state
            A <- random action previously taken in S
            R, S' <- Model(S,A)
            Q(S,A) <- Q(S,A) + alpha [R + gamma max_a Q(S',a) - Q(S,A)]
```
"Direct reinforcement learning, model-learning, and planning are implemented by steps (d), (e), and (f),
respectively. If (e) and (f) were omitted, the remaining algorithm would be one-step tabular Q-learning" (p.164).
Planning samples "only from state-action pairs that have previously been experienced ... so the model is never
queried with a pair about which it has no information" (p.163).

## 6. Equations
None new. Steps (d) and (f) are the Q-learning update (Eq. 6.8) applied to real and to remembered transitions.
Dyna-Q+ bonus (p.168): planning updates use reward r + kappa sqrt(tau), "for some small kappa", where tau = time
steps since the transition was last tried in real interaction:
```tex
r + \kappa\sqrt{\tau}
```

## 7. Example settings

Example 8.1 Dyna Maze (p.164-165, PDF 186-187; Figure 8.2 p.165):
- "In each of the 47 states there are four actions, up, down, right, and left, which take the agent
  deterministically to the corresponding neighboring states, except when movement is blocked by an obstacle or the
  edge of the maze, in which case the agent remains where it is."
- "Reward is zero on all transitions, except those into the goal state, on which it is +1."
- "After reaching the goal state (G), the agent returns to the start state (S) to begin a new episode."
- "discounted, episodic task with gamma = 0.95."
- "The initial action values were zero, the step-size parameter was alpha = 0.1, and the exploration parameter was
  epsilon = 0.1. When selecting greedily among actions, ties were broken randomly."
- Planning steps per real step n: curves for n = 0 ("direct RL only"), 5, 50 (figure labels; text discusses the
  same three).
- "averaged over 30 repetitions of the experiment. In each repetition, the initial seed for the random number
  generator was held constant across algorithms." So "the first episode was exactly the same (about 1700 steps)
  for all values of n, and its data are not shown in the figure." x-axis: Episodes 2 to 50; y-axis: Steps per
  episode.
- Layout from the inset only (no text gives it; mark uncertain): 6 rows x 9 columns = 54 cells, 7 obstacle cells,
  54 - 7 = 47 states (matches the text). Coordinates (row, col), 1-indexed from the top-left:
  - S = (3, 1): third row from the top, leftmost column.
  - G = (1, 9): top row, rightmost column.
  - Obstacles: column 3, rows 2-4 (three cells); column 6, row 5 (one cell); column 8, rows 1-3 (three cells).
  ```
  . . . . . . . X G
  . . X . . . . X .
  S . X . . . . X .
  . . X . . . . . .
  . . . . . X . . .
  . . . . . . . . .
  ```
  Consistency check (ours): BFS on this layout gives a shortest S-to-G path of 14 steps, which matches the lowest
  y-axis tick "14" printed on Figure 8.2. Figure 8.3 (p.165) shows the same layout.
- Findings (text, p.164): "After the first episode, performance improved for all values of n, but much more
  rapidly for larger values." n = 0 "was by far the slowest agent on this problem, despite the fact that the
  parameter values (alpha and epsilon) were optimized for it. The nonplanning agent took about 25 episodes to reach
  (epsilon-)optimal performance, whereas the n = 5 agent took about five episodes, and the n = 50 agent took only
  three episodes."
- Figure 8.3 (p.165): greedy policies halfway through the second episode for n = 0 and n = 50. Without planning,
  "each episode adds only one additional step to the policy"; with planning, "an extensive policy has been developed
  that by the end of the episode will reach almost back to the start state" ... "By the end of the third episode a
  complete optimal policy will have been found".

Example 8.2 Blocking Maze (p.166, Figure 8.4 p.167), one sentence: a short path right of a barrier is blocked after
1000 time steps and a longer path opens on the left; both Dyna-Q and Dyna-Q+ (cumulative reward over 3000 steps)
go flat, then find the new path.

Example 8.3 Shortcut Maze (p.167, Figure 8.5): after 3000 steps a shorter path opens on the right without
disturbing the old one; "the regular Dyna-Q agent never switched to the shortcut. In fact, it never realized that
it existed. Its model said that there was no shortcut, so the more it planned, the less likely it was to step to
the right and discover it."

Dyna-Q+ (p.168), one sentence: tracks time since each state-action pair was last tried and plans with reward
r + kappa sqrt(tau), which "encourages the agent to keep testing all accessible state transitions". Footnote (p.168):
untried actions may be used in planning step (f), and their initial model is "that they would lead back to the same
state with a reward of zero."

## 8. Results and findings
- Example 8.1 numbers above (about 25 / about five / three episodes for n = 0 / 5 / 50; first episode about 1700
  steps; 30 repetitions).
- Section 8.3 (p.166): "When the model is incorrect, the planning process is likely to compute a suboptimal
  policy." Optimistic model errors tend to get corrected: "The planned policy attempts to exploit these
  opportunities and in doing so discovers that they do not exist." Pessimistic errors may persist: "the modeling
  error may not be detected for a long time, if ever."
- Exploration vs exploitation in planning (p.167): "exploration means trying actions that improve the model,
  whereas exploitation means behaving in the optimal way given the current model."

## 9. Limitations and history (remarks p.192-193, PDF 214-215)
- 8.2: "The Dyna architecture is due to Sutton (1990), and the results in this and the next section are based on
  results reported there." Reference: Sutton (1990), "Integrated architectures for learning, planning, and reacting
  based on approximating dynamic programming", Proceedings of the 7th International Workshop on Machine Learning,
  pp. 216-224 (p.511, PDF 533). Terms direct/indirect come from adaptive control (Goodwin and Sin 1984); model
  learning = "system identification" there.
- 8.11: "The central ideas of MCTS were introduced by Coulom (2006) and by Kocsis and Szepesvari (2006)."
- Stated limits of Dyna-Q as presented: the table model "assumes the environment is deterministic" (p.162);
  Exercise 8.5 asks how to handle stochastic and changing environments.
