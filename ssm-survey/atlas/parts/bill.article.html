The bill attention sends

A cache that grows, against a memory that does not

To write the next word, a Transformer compares it with every word before it. To make that fast it keeps a : a key and a value for every past , in every layer. Each new token adds a column, so the cache (brown) grows for as long as the text does.

A keeps a instead (yellow): a fixed set of numbers that each new token updates. It never gets bigger. It only changes.

The same picture with real sizes. The brown line is the KV cache of Llama 3 8B: 128 KiB for every token, at 16 bits per value. The yellow line is the whole memory of Mamba 2.8B: 11.9 MiB, at any length.

Drag the slider. Near 122,000 tokens the cache of one conversation is as large as the model's weights (the dashed line). The two models differ in size; what matters is that one line rises and the other stays flat.

Step 1 is a toy (twenty tokens, four layers). Step 2 is computed from the published configurations: Llama 3 8B has 32 layers and 8 key-value heads of dimension 128; Mamba 2.8B has 64 layers of width 2560, expanded 2 times, with a state of 16 per channel (the README default) plus the last 3 inputs of a width-4 convolution.
