Continuous time and discretization

One memory, read at any step size

Here the has three numbers, and the yellow curve is how it moves through time. The blue staircase is the input; the green curve is the output. The memory is written as an , a rule for how fast the state changes: a matrix A turns the state and pulls it back to zero, and the input pushes it away. Nothing in that rule has a step size.

A computer sees one token per step, so it needs a recurrence instead. picks a and solves the ODE over one step. Mamba does it with the , and the yellow points are that recurrence. Drag the slider: the curve stays put, only the number of points changes.

Now press Same tokens, new Δ and then Δ = 1/10. The sixteen inputs are now crammed into a tenth of the time. Each token moves the state less, and the state forgets less per token: its memory reaches ten times more tokens back.

A toy, computed exactly: A is chosen by hand (decay rate 0.5 for h1; a pair that turns at 1 radian per time unit and decays at 0.25). The points use the zero-order hold, Abar = exp(ΔA), checked against a fine numerical integration. HiPPO, LSSL and S4 use the bilinear rule instead; S4D found little difference between the two.

The step size Δ is the knob between time and tokens: a smaller step means a longer memory, counted in tokens.
