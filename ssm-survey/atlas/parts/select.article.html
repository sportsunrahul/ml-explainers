Mamba: input-dependent selection

Each token sets its own step size

Important tokens:

In S4 the step size Δ and the matrices B and C are the same for every token, so the model cannot tell a key word from filler. Mamba makes them depend on the token. This is : each token computes its own .

Mark a token important and it gets a large Δ: the yellow state flows toward it, forgets most of what it held, and stores the new value. Filler gets a tiny Δ, and the state barely moves. The green output keeps the last important value across the filler. The dashed path uses one Δ for every token and wanders with each of them.

With one state number this is exactly a : h_t = (1 - g_t) h_(t-1) + g_t x_t, with g_t computed from the token (Mamba's Theorem 1). Press All important: the state copies every token and remembers none. Selection only helps when it is selective.

A toy, computed exactly: one channel, three state numbers, A = diag(-1, -2, -3) (Mamba's default real initialization), Δ = softplus of a linear function of the important flag (2.13 or 0.049), zero-order hold per token. B is selective too; C is fixed. In the paper's ablations at about 350M parameters, a bigger state helps only when B and C are selective: perplexity 9.73 to 8.71 as N goes from 1 to 16, against 9.88 to 9.81 with constant B and C (Table 10).

A large step resets the memory and stores the token; a small step keeps the memory and skips it. Mamba lets each token choose.
