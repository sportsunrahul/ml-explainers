State-space models, intuition first

Attention keeps every token it has seen and reads all of them again for each new one. A state-space model keeps a small memory of fixed size and updates it. This is the story of how that memory was made trainable, fast and selective, and where it still falls short.

Act IThe bill, and the old fix

The bill attention sends

The transformers explainer ended on a cost. To write the next token, attention compares it with every token before it, and the KV cache that makes this fast keeps a key and a value for all of them. Here is that bill in bytes, next to the alternative this survey is about: a model whose memory has a fixed size.

Two things in that chart grow with the context length L. The first is memory: the cache holds two vectors per token per layer, so it grows in a straight line, and every new token must read all of it back from GPU memory before it can be written. The second is work. Reading a prompt of L tokens, attention scores every pair of tokens, which is about L^2/2 pairs per head in every layer. Double the context and the prompt costs four times as much.

A recurrent model makes the opposite trade. It carries a state h of fixed size and folds each new token into it. The cost of the next token does not depend on L at all. The flat yellow line is the whole memory of a 2.8-billion-parameter Mamba model, at any context length: about the size of the Llama 3 8B cache for 95 tokens.

  • Left, attention: the output at step t is a weighted sum over every past value \htmlClass{t-brown}{v_s}, so all past keys and values must be kept. That is the brown line.
  • Right, recurrence: the output depends only on the current state \htmlClass{t-yellow}{h_t}, which is updated from the previous state and the new token \htmlClass{t-blue}{x_t}. That is the yellow line.

Before you drag the slider: at what context length does the Llama 3 8B cache outgrow the model's own weights? The dashed line is the answer. With 16-bit values the weights take about 15 GiB, and the cache passes them near 122,000 tokens, for a single sequence. Serve a batch of such sequences and memory, not arithmetic, sets the limit.

So why not simply use a recurrent network? That was the default for sequence models until 2017. The next chapter shows why it was dropped, and the one change that brings it back.

The catch, stated up front

A fixed-size state is a lossy summary. Anything the model will need later has to survive being folded into those numbers. Mamba reports up to 5x the generation throughput of a Transformer of similar size (each model at the largest batch it fits; the gap is smaller at equal batch sizes), and the hybrids at the end of this page run long contexts on far less memory. But exact recall of something seen thousands of tokens ago is where a pure SSM still loses. The chapter Where SSMs still lose measures how much.

Linear recurrences, and why RNNs were dropped

A recurrent neural network (RNN) is the cheapest memory a sequence model can have: it keeps a state of fixed size and updates it once per token, so every token costs the same. Strip it down to a single cell, \htmlClass{t-yellow}{h_t} = \lambda\, \htmlClass{t-yellow}{h_{t-1}} + b\, \htmlClass{t-blue}{x_t}, and drag the two numbers that define \lambda: its size r and its angle \theta.

Each step multiplies what the cell holds by \lambda. A token that arrived k steps ago has been multiplied k times, so its share of the state is \lambda^k. Below |\lambda| = 1 the token fades geometrically; above it, the token grows without limit. A real \lambda can only fade or flip sign. A complex \lambda = r e^{i\theta} also turns by \theta at each step, so the cell holds a damped oscillation: press Ringing.

The same factor is what made RNNs hard to train. For this linear cell, the gradient that flows from the state at step t back to a token at step k is exactly \lambda^{t-k} b (a one-line derivation of ours; the papers make the point in words). Over hundreds of steps that number vanishes or explodes. This is the vanishing and exploding gradient problem, studied by Hochreiter (1991), Bengio, Simard and Frasconi (1994) and Pascanu, Mikolov and Bengio (2013). LRU's introduction cites all three, and its Section 3.2.1 names the repeated powers of the recurrence matrix as the source.

Real RNNs add a nonlinearity: \htmlClass{t-yellow}{h_t} = \tanh(A\, \htmlClass{t-yellow}{h_{t-1}} + B\, \htmlClass{t-blue}{x_t}). Press Nonlinear tanh RNN. The bars disappear, because no token has a fixed weight any more: its effect on the state depends on every token around it. And step t cannot start until step t-1 is done, so a sequence of length L takes L steps one after another, in training as well as in generation. Now press Exploding. Tanh holds the state near 0.50, so nothing blows up, yet the red gradient line falls below 1% within 17 steps. A bounded state is not a trainable one. Gated RNNs such as the LSTM (1997) and the GRU (2014) were designed to ease the gradient problem, but in LRU's words they remained "slow to optimize due to the inherently sequential nature of their computation".

LRU's introduction also says what Transformers offered instead: attention layers "are easier to scale and parallelize during training, and crucially they do not suffer from the vanishing gradient problem, since the interaction between any two tokens in the sequence is modeled by direct edges in the network." Every position of a training sequence is computed at once, and no gradient has to pass through hundreds of multiplications. The price is the bill of the previous chapter.

Now press Linear again. Without tanh the recurrence unrolls into a plain weighted sum of the inputs, and the bars are its weights. They depend only on how long ago a token arrived, not on what the tokens were, so they are known before any data arrives. All L states can then be computed together, as a convolution (the S4 chapter) or with a parallel scan. Martin and Cundy (ICLR 2018) built such a scan for the GPU: up to 40x faster than a step-by-step loop on long sequences, and slower on short ones (0.06 times the loop's speed at 16 steps). The chapter on the parallel scan takes it apart.

In this page's notation: LRU writes the input as u and the state as x; here they are \htmlClass{t-blue}{x} and \htmlClass{t-yellow}{h}, and \lambda is one diagonal entry of the matrix A (LRU's \Lambda).

  • \lambda: what the cell multiplies itself by at each step. Its size r sets how fast a token fades; its angle \theta sets how fast the cell turns.
  • b\, \htmlClass{t-blue}{x_t}: the new token, scaled by b and added once.
  • \lambda^{t-k}: the weight of token k in today's state, drawn as the bars. It is the impulse response of the chart, read backward. For this linear cell it is also the factor that multiplies the gradient from \htmlClass{t-yellow}{h_t} back to \htmlClass{t-blue}{x_k}.

Press Reset (r = 0.9). Each step keeps 90% of a token. Before you read the marker at k = 50: how much of the token is left 50 steps later? A third? A tenth? The chart says 0.52%. The token fell below 1% at step 44. A cell that keeps 90% per step forgets a paragraph before the paragraph ends. To keep 1% of a token across 16k steps, the length of PathX, LRU's longest task, |\lambda| must be at least 0.9997.

Long memory brings a second problem. Press Long memory: the cell now adds up many recent tokens at nearly full weight. Under random inputs of unit size, its variance settles at 1/(1-|\lambda|^2) times the input's, the red bar: 5.3 at r = 0.9, 50 at r = 0.99, about 500 at r = 0.999, and no limit at all for r \ge 1. Push Exploding in linear mode and the token is 100 times its size by step 49.

The cost against attention fits in one line. Per token, the cell does one multiply and one add for each entry of the state, at any position t, and the state is all it carries: the linear form needs no KV cache, while attention at step t reads all t cached keys and values.

What LRU changed

Deep state-space models such as S4 (the next three chapters) train in parallel and did very well on long-range benchmarks. LRU (Orvieto and colleagues, DeepMind, arXiv 2303.06349v1) asked where that came from. It started from a plain deep RNN and changed one thing at a time, with the rest of the network held fixed:

  1. Linear. Drop the nonlinearity from the recurrence and keep it in the small network that follows each recurrent layer. LRU reports that such linear layers "can be surprisingly expressive when coupled with nonlinear MLP or GLU blocks".
  2. Diagonal and complex. A dense matrix can be written A = P \Lambda P^{-1}, with its eigenvalues on the diagonal of \Lambda; LRU learns \Lambda directly, so each cell updates on its own. A randomly initialized dense matrix has eigenvalues spread over the unit disk of the complex plane (LRU Theorem 3.1), so the cells are complex. A diagonal linear RNN trained about 8 times faster than a dense ReLU RNN on sequential CIFAR (Sec 3.2.2).
  3. A parameterization that cannot explode. Write \lambda through two learned numbers, one for its size and one for its angle, so that |\lambda| < 1 whatever the training does (below).
  4. Start near the circle. Initialize |\lambda| on a ring close to 1, for long memory: from 0.999 to 0.9999 for PathX, whose sequences are 16k long.
  5. Normalize. Scale each cell's input by \gamma, set to cancel the noise gain of the red bar. On PathX alone, LRU also starts the angles small.
\htmlData{step=1, link=magnitude}{\lambda_j = \exp\!\big(-e^{\nu_j^{\log}} + i\,\theta_j\big)} \qquad \htmlData{step=2, link=gain}{\mathbb{E}\,|\htmlClass{t-yellow}{h_t}|^2 \;\to\; \frac{1}{1-|\lambda|^2}} \qquad \htmlData{step=3, link=token}{\htmlClass{t-yellow}{h_t} = \lambda\, \htmlClass{t-yellow}{h_{t-1}} + \gamma\, b\, \htmlClass{t-blue}{x_t}, \;\; \gamma = \sqrt{1-|\lambda|^2}}

Left: the stable exponential parameterization, LRU Sec 3.3 (the final model also writes \theta_j = e^{\theta_j^{\log}}, App A). Middle: LRU Eq. (6), one cell with uncorrelated inputs of unit size. Right: LRU Eq. (7), with \gamma initialized as shown, then trained.

  • \nu_j^{\log}, \theta_j: what training updates for cell j. Because e^{\nu_j^{\log}} is always positive, |\lambda_j| = \exp(-e^{\nu_j^{\log}}) is always below 1, and it nears 1 only as \nu_j^{\log} goes to minus infinity. Size and angle are learned separately.
  • \mathbb{E}\,|\htmlClass{t-yellow}{h_t}|^2: the average squared size of the cell when its inputs are random and uncorrelated. The factor 1/(1-|\lambda|^2) is the noise gain, the red bar.
  • \gamma: a scale on each cell's input. Starting at \sqrt{1-|\lambda|^2}, it cancels the gain, so a cell near the circle starts no larger than its input.

Act IIPrincipled memory

Continuous time and discretization

A linear recurrence multiplies its state by a fixed matrix at every step and adds the new token. The papers in this act take one step back and describe the memory as a system that runs in continuous time, so that a sequence of tokens is that system read at regular steps.

Read the yellow curve as the memory moving through time. The input pushes the state away from zero; the matrix A turns it and pulls it back, so after the input stops the state spirals home and the memory fades. Nothing in that picture has a step size. The points are the recurrence a computer actually runs, one per token, and with the default button they sit exactly on the curve whatever step you choose. Drag the slider: the curve stays the same and only the number of points changes. That is what it means for one model to describe the same signal at any resolution.

The continuous system is the first equation in the Mamba paper, and in LSSL and S4 before it:

\htmlData{step=1, link=state}{\htmlClass{t-yellow}{h'(t)}} = \htmlData{step=2, link=A}{A\,\htmlClass{t-yellow}{h(t)}} \htmlData{step=3, link=input}{{}+ B\,\htmlClass{t-blue}{x(t)}} \qquad \htmlData{step=4, link=output}{\htmlClass{t-green}{y(t)} = C\,\htmlClass{t-yellow}{h(t)}}

Eq. 1 in Mamba. An ordinary differential equation (ODE): it says how fast the state changes, not where it is.

  • \htmlClass{t-yellow}{h(t)} is the state, a vector of N numbers (here N = 3); h'(t) is its rate of change.
  • A is an N \times N matrix. Its eigenvalues have negative real parts, so on its own the state shrinks toward zero; imaginary parts make it turn while it shrinks.
  • B writes the scalar input \htmlClass{t-blue}{x(t)} into the state; C reads the scalar output \htmlClass{t-green}{y(t)} out of it. A real layer runs one such system per channel.

A note on letters: this page writes the input x, the state h and the output y, as Mamba does. HiPPO, the next chapter, writes the input f and the state c; LSSL and S4 write the input u and the state x.

A computer cannot run continuous time. It gets one token per step, so it must turn the ODE into a recurrence. Choose a step size \Delta and assume the input stays constant for the length of each step. Then the ODE can be solved exactly over one step, and the answer is two fixed matrices. This rule is called the zero-order hold (ZOH):

\htmlData{step=1, link=samples}{\overline{A} = \exp(\Delta A)} \qquad \htmlData{step=2, link=input}{\overline{B} = (\Delta A)^{-1}\big(\exp(\Delta A) - I\big)\cdot \Delta B}

Eq. 4 in Mamba (zero-order hold).

  • \exp(\Delta A) is the matrix exponential: what the system does to the state in \Delta time units with no input. Each eigenvalue \lambda of A becomes e^{\Delta \lambda}, a number of size below 1.
  • \overline{B} is what a constant input of size 1 adds to the state over the same \Delta. For small \Delta it is close to \Delta B.

With those two matrices the system becomes the recurrence the figure's points follow, the same shape as the linear recurrence of the last chapter:

\htmlData{step=1, link=samples}{\htmlClass{t-yellow}{h_t} = \overline{A}\,\htmlClass{t-yellow}{h_{t-1}}} \htmlData{step=2, link=input}{{}+ \overline{B}\,\htmlClass{t-blue}{x_t}} \qquad \htmlData{step=3, link=output}{\htmlClass{t-green}{y_t} = C\,\htmlClass{t-yellow}{h_t}}

Eq. 2 in Mamba (the recurrent mode, used for generation one token at a time).

  • One step: multiply the old state by \overline{A}, add \overline{B} times the new token, read the output with C.
  • This is the cost against attention: per token and per channel, one update of an N-number state, the same at token 10 as at token 1,000,000. Attention at token L reads L cached keys and values.

So \Delta is the knob that connects the two pictures. Here is the question to settle with the figure. Press Same tokens, new Δ, which keeps the sixteen input values and gives each one a step of \Delta. Before you press Δ = 1/10: what does a 10 times smaller \Delta do to how long the state remembers?

Counted in time, nothing changes: the slow part of the state still halves every 2.8 time units. Counted in tokens, the memory gets 10 times longer, from 2.8 steps to 28, because each token now covers a tenth of the time. The price is that each token also moves the state about 10 times less, since \overline{B} \approx \Delta B: the whole curve shrinks toward zero. LSSL states the rule in these terms: the length of the dependencies such a layer captures is roughly proportional to 1/\Delta.

Why the points land exactly on the curve

The zero-order hold is exact when the input really is constant between samples, and the figure's input is a staircase for that reason. For a smooth input the ZOH points approach the curve as \Delta shrinks, but they are no longer exactly on it. Not every paper uses this rule. HiPPO, LSSL and S4 discretize with the bilinear method, \overline{A} = (I - \tfrac{\Delta}{2}A)^{-1}(I + \tfrac{\Delta}{2}A) (S4 Eq. 3); Mamba uses ZOH. S4D tried both and found little difference in practice.

The same layer can be read a third way. LSSL (NeurIPS 2021) showed that this one system is at once a continuous model, the recurrence above, and, because \overline{A}, \overline{B} and C are the same at every step, a single long convolution over the whole sequence. That third view is what makes training fast, and it is the subject of chapter 5. First, though, the choice this chapter left open: the toy's A was picked by hand. The next chapter derives an A whose state is the best possible summary of everything it has seen.

HiPPO: memory as compression of the past

The last chapter gave the state a continuous clock but left the matrix A open, and almost any choice of A forgets quickly. HiPPO (Gu, Dao and colleagues, 2020) asked what the state should hold, and answered: the best polynomial fit of everything seen so far.

Here is the idea. At time t the model has seen an input signal on the whole interval [0, t]. Fit it with a polynomial of degree less than N, the closest one in the least-squares sense, and keep only that polynomial's N coefficients. Those numbers are the state. A moment later the history is a little longer, the best fit changes a little, and so do the coefficients. HiPPO calls this online function approximation: compress the past into N numbers, and keep the compression optimal as the past grows.

Written in the right basis, the coefficients move in a simple way. HiPPO expands the fit in Legendre polynomials P_0, P_1, \dots (the standard orthogonal polynomials on an interval), stretched to cover [0, t]. Differentiate the optimal coefficients with respect to t and the result is a linear differential equation, the same shape as the last chapter's. The measure that weighs the past matters: HiPPO-LegS ("scaled Legendre") weighs every past moment equally, however long ago. A word on notation first: HiPPO writes the input as f and the state as c, and it uses x for a moment in the past, not for the input. So in this chapter \htmlClass{t-blue}{f} is our input \htmlClass{t-blue}{x} and \htmlClass{t-yellow}{c} is our state \htmlClass{t-yellow}{h}.

\htmlData{step=1, link=state}{\frac{d}{dt}\,\htmlClass{t-yellow}{c(t)}} = \htmlData{step=2, link=time}{-\frac{1}{t}}\; \htmlData{step=3, link=A}{A\,\htmlClass{t-yellow}{c(t)}} \;+\; \htmlData{step=4, link=B input}{\frac{1}{t}\,B\,\htmlClass{t-blue}{f(t)}}

HiPPO-LegS dynamics: Eq. (3), Theorem 2 in HiPPO v2.

\htmlData{step=1, link=A}{A_{nk} = \begin{cases} \sqrt{2n+1}\,\sqrt{2k+1} & n > k \\ n+1 & n = k \\ 0 & n < k \end{cases}} \qquad \htmlData{step=2, link=B}{B_n = \sqrt{2n+1}}

The LegS matrices, Theorem 2 in HiPPO v2; degrees n, k = 0, \dots, N-1.

  • \htmlClass{t-yellow}{c(t)}: the state, N Legendre coefficients of the best fit to the history. The yellow line across the surface, and the yellow grid of cells.
  • -\frac{1}{t}: the update slows down as the history grows. A new sample is one part in t of everything seen, so it moves the fit by about 1/t.
  • A: how the coefficients pull on each other. It is lower triangular: degree n only listens to degrees 0 to n. Raising N therefore never changes the rows you already had; it adds new ones behind them (watch the surface grow backwards).
  • B\,\htmlClass{t-blue}{f(t)}: the new input, written into every degree with weight \sqrt{2n+1}.

The state is only useful if the past can be read back out of it. The fit itself is the readout: sum the stretched Legendre polynomials, each weighted by its coefficient. That is the yellow line in the lower panel, drawn over the true history in blue.

\htmlData{step=1, link=recon}{f(x) \;\approx\; \sum_{n=0}^{N-1}} \htmlData{step=2, link=state}{\htmlClass{t-yellow}{c_n(t)}}\; \htmlData{step=3, link=time}{\sqrt{2n+1}\; P_n\!\left(\frac{2x}{t} - 1\right)}, \qquad 0 \le x \le t

Reconstruction for LegS, HiPPO v2 Appendix D.3 (general form Eq. (19)). The map x \mapsto 2x/t - 1 stretches the window [0, t] onto [-1, 1]; the factor \sqrt{2n+1} makes each polynomial have unit norm.

Before you move the N slider: the test function has a fast wiggle, about sixteen cycles across the window. How many numbers must the state hold before the yellow line follows it? With N = 4 the fit catches only the slow trend (RMSE 0.750). At N = 16 it follows the two slow waves but flattens the fast one (0.234). At N = 64 it follows everything (0.0133). Now press Play with N = 16. Early on, the same sixteen numbers rebuild the short history almost perfectly (RMSE 0.0118 at t = 20); as the window stretches they must cover more and more of it with the same budget. LegS forgets nothing, so it blurs everything evenly instead.

That is the trade against attention, in its plainest form. After 1,000 samples a KV cache holds all 1,000; the HiPPO state holds N numbers and pays for it with a blurrier past. Thanks to the structure of A, one update costs O(N) operations (Proposition 4); this figure uses a plain triangular solve, which is fast enough for 64 numbers.

Two traps in turning the equation into steps (our reading)

The paper runs LegS with the bilinear rule, which averages the old and new slopes. Its appendix writes the bilinear step for an equation without the minus sign of Theorem 2, so with Theorem 2's positive A the step reads

\htmlClass{t-yellow}{c_{k+1}} = \Big(I + \frac{A}{2(k+1)}\Big)^{-1} \Big[\Big(I - \frac{A}{2k}\Big)\htmlClass{t-yellow}{c_k} + \frac{1}{k} B\, \htmlClass{t-blue}{f_k}\Big]

The paper also divides by k without saying how to start; we start at k = 1 with c_1 = f_0\, e_0, the exact fit of a single constant. With these choices the coefficients at t = 100 stay within 0.0047 of the exact fit computed by numerical integration (N = 64). And the rule matters. Press Forward Euler at N = 64: early steps multiply by I - A/k, whose entries reach 64 when k is small, so a coefficient climbs to about 1.0e44 before the 1/k damping wins. The final RMSE is 0.296, against 0.0133 for the bilinear rule. The paper reports the same ordering (its Fig. 4; Euler is the form of Eq. (4), written "for illustration"). One more note: S4 later folds the minus sign into A itself (S4 Eq. (2)), which is the convention of every other chapter on this page.

Weighing all of history equally has a second payoff. LegS has no window length and no step size to tune: play a signal twice as fast and its coefficients are the same, reached in half the time (Proposition 3). Its gradients also fade slowly. The influence of an old input on the state shrinks like 1/t (Proposition 5), a polynomial decay, not the exponential a^T that sank plain RNNs two chapters ago.

One number needs care. HiPPO's best-known result, 98.3% test accuracy on permuted MNIST (each digit's 784 pixels read one at a time in a fixed shuffled order), is not a linear state-space model. It is a HiPPO-RNN: a gated nonlinear RNN that writes one feature per step into a fixed LegS memory and reads the memory back at the next step. The memory is the new part, and the paper's own ablation shows it carries the result: the same model scores 98.34% validation accuracy with LegS's A and 69.93% with a random one (Table 1). The first numbers for a stack of purely linear state-space layers came a year later from LSSL: 98.76% on the same task, and 98.60% with A frozen at HiPPO's value (LSSL Table 1, where the HiPPO-RNN row reads 98.3).

There is a catch in the equation itself. LegS is time-varying: the 1/t in front of A makes every step different, and there is no step size \Delta anywhere. LSSL and S4 keep LegS's A and B, drop the 1/t, and bring \Delta back, giving h'(t) = A\,h(t) + B\,x(t) with S4's sign (LSSL's appendix prints the positive A without a minus; that system would blow up, so we read it as a typo). The memory is no longer exactly LegS, but it keeps its habit of remembering, and it becomes time-invariant: the same A, B and C at every step. The next chapter shows what that buys.

S4: structure and the convolution view

Drop the 1/t from HiPPO and the memory becomes time-invariant: the same A, B and C at every step. Then one system can be computed in three ways, and one of them trains like a convolutional network, every position at once.

The three views come from LSSL, the paper between HiPPO and S4 (2021). S4 writes the input as u and the state as x; here they stay \htmlClass{t-blue}{x} and \htmlClass{t-yellow}{h}. The continuous view is the differential equation h'(t) = A\,h(t) + B\,x(t) from two chapters ago. The recurrent view samples it every \Delta and steps the state forward one token at a time, like an RNN. The convolutional view unrolls that recurrence. Because A, B and C are the same at every step, the input from j steps ago always reaches the output with the same weight, C\bar A^{\,j}\bar B. Line those weights up and you have one long filter, the kernel \bar K, and the whole output is the input convolved with it.

\htmlData{step=1, link=state}{\htmlClass{t-yellow}{h_k} = \bar A\, \htmlClass{t-yellow}{h_{k-1}}} \htmlData{step=2, link=input}{+ \bar B\, \htmlClass{t-blue}{x_k}}, \qquad \htmlData{step=3, link=output}{\htmlClass{t-green}{y_k} = C\, \htmlClass{t-yellow}{h_k}}, \qquad \htmlData{step=4, link=delta}{\bar A = \big(I - \tfrac{\Delta}{2} A\big)^{-1}\big(I + \tfrac{\Delta}{2} A\big),\;\; \bar B = \big(I - \tfrac{\Delta}{2} A\big)^{-1} \Delta B}

The recurrent view with the bilinear rule: S4 Eq. (3); LSSL Eqs. (4) and (5).

\htmlData{step=1, link=kernel}{\bar K = \big(C\bar B,\; C\bar A\bar B,\; C\bar A^{2}\bar B,\; \dots,\; C\bar A^{L-1}\bar B\big)} \qquad \htmlData{step=2, link=output input}{\htmlClass{t-green}{y} = \bar K \ast \htmlClass{t-blue}{x}}

The convolutional view: S4 Eqs. (4) and (5); LSSL Eqs. (6) and (7), where Eq. (6) drops a C by a typo.

  • \bar A, \bar B: the continuous A, B turned into a per-token step of size \Delta. S4 uses the bilinear rule, as HiPPO did; Mamba will use a different one (zero-order hold).
  • \htmlClass{t-yellow}{h_k}: the state after token k, the four yellow cells that ride along in the recurrent view.
  • \bar K: entry j says how much the input j steps back adds to the output now. It is the yellow row at the bottom: the state's memory, unrolled.
  • \ast: convolution. Output k is the sum of \bar K_j\, x_{k-j} over j: slide the flipped kernel along the input.

The dots and the rings in the figure sit on each other exactly: the recurrent and convolutional views are the same arithmetic in a different order, and they agree to the last digit of a floating-point number. The continuous curve passes through them only up to the error of the bilinear step, 0.0054 at the default \Delta, and the gap shrinks as \Delta does. Each view has a job. The convolution trains: all outputs at once, with no loop over time. The recurrence generates: one constant-cost step per new token. The continuous view sets the clock.

Before you drag the step size: if each token covers less continuous time (a smaller \Delta), does the kernel get longer or shorter? Press Small Δ. It gets longer: at \Delta = 0.03 the kernel stays above 5% of its peak for 42 steps, against 13 at 0.1 and 4 at 0.3. The same continuous memory, read with finer steps, spans more tokens. LSSL puts it this way: the length of dependencies a layer captures is roughly proportional to 1/\Delta, so \Delta sets the width of the convolution.

Against attention, this is the payoff. Training a layer is one fast Fourier transform (FFT) convolution per channel, about L \log L work instead of attention's L^2 scores, and generating is one O(N) step per token (Theorem 2) with no cache. In S4's own benchmark at length 4,096, S4 trained 5.19 times as fast as a Transformer of the same size, in 0.091 of its memory (Table 3); as a generator it was 60x faster (abstract).

The hard part: computing the kernel

The convolution is only cheap if \bar K is. Building it the obvious way, multiplying by \bar A once per lag, costs O(N^2 L) operations and O(NL) memory, and LSSL paid exactly that. The usual fix for powers of a matrix is to diagonalize it, but HiPPO's A cannot be diagonalized safely: its eigenvector matrix has entries as large as 2^{4N/3}, far beyond what floating point survives (S4 Lemma 3.2).

S4's way around it, in plain words. HiPPO's A is normal plus low rank: a well-behaved matrix that a stable change of basis makes diagonal, plus one outer product P Q^{\top} (rank r=1 for LegS, Theorem 1). Next, S4 does not compute the kernel lag by lag. It computes the kernel's Fourier transform at L frequencies, where all the powers of \bar A collapse into a single matrix inverse. The Woodbury identity, a standard formula for inverting "easy matrix plus low rank", splits that inverse into the diagonal part and a small correction. For a diagonal matrix, each frequency is a sum over the N eigenvalues \lambda_j of terms shaped like 1/(\omega - \lambda_j), a Cauchy kernel, a well-studied computation. One inverse FFT turns the L values back into \bar K (Algorithm 1). The theory cost is \tilde O(N + L) operations (Theorem 3, the tilde hiding log factors); the released code runs the simple Cauchy loop instead, O(NL) time and O(N + L) memory (S4 Appendix A). Each channel trains 5N complex numbers for this: the eigenvalues, P, Q, B and C, plus its step \Delta. You do not need to follow each step; the point is that HiPPO's memory became a layer whose kernel costs about as much to build as to apply.

Branch: is the low-rank part needed? (S4D)

S4D drops the low-rank term and keeps only a diagonal A; the kernel becomes "2 lines of code". It works, but only when the diagonal starts from HiPPO. On Path-X, S4D-LegS (HiPPO's diagonal part) reaches 91.95% and S4D-Inv (a closed-form fit to it) 92.80%, while S4D-Lin, a plain Fourier-like spread, fails (S4D Table 5). S4's own ablation says the same of the full model: with A trained, random and HiPPO starts all fit the training set, but validation accuracy differs by over 15% (S4 Sec. 4.4). The structure makes S4 fast; the HiPPO start makes it remember.

Act IIISelection

Why time-invariance is not enough

S4 sends every token through the same kernel, so the weight a past token gets depends only on how many steps ago it arrived, never on what it was. Here is a task where that is exactly the wrong thing to depend on: four letters are scattered among filler, and a memory of four slots must hold them in order. Before you press Reveal, guess which of the two models below reads all four back.

The task is selective copying, one of the two synthetic tests the Mamba paper uses to show what time-invariant models cannot do. Plain copying, with the letters always at the same positions, is easy for them: a kernel with its weight at exactly the right lags reads the letters off. Press Even gaps and the fixed decay gets them all, if blurrily, because its slots were tuned to that spacing. Randomize the gaps and the same kernel reads whatever happens to sit at those lags: a letter twice, or the wrong one.

Two things go wrong, and both come from the kernel being fixed. It cannot skip filler: every filler token still moves the state, so a letter followed by a long run of filler fades, or slides into the wrong slot. And it cannot look anything up: which slot holds what is decided by position, so the model cannot keep "the token that came after X". The gate in the bottom lane fixes the first problem directly. It opens for a letter and stays shut for filler, so the state moves only when there is something to store, and a letter survives any gap untouched.

In symbols, the difference is one subscript. A time-invariant model has one kernel; a selective one computes its parameters from each token.

\begin{aligned} &\htmlData{step=1, link=kernel}{\htmlClass{t-green}{y_t} = \sum_{k \ge 0} \overline{K}_k\, \htmlClass{t-blue}{x_{t-k}}, \qquad \overline{K}_k = C\,\overline{A}^{\,k}\,\overline{B}} \\[4pt] &\htmlData{step=2, link=gate}{\htmlClass{t-yellow}{h_t} = \overline{A}_t\, \htmlClass{t-yellow}{h_{t-1}} + \overline{B}_t\, \htmlClass{t-blue}{x_t}, \qquad \overline{A}_t,\ \overline{B}_t,\ C_t \ \text{computed from}\ \htmlClass{t-blue}{x_t}} \\[4pt] &\htmlData{step=3, link=weight}{\text{weight of}\ \htmlClass{t-blue}{x_s}\ \text{in}\ \htmlClass{t-green}{y_t} = C_t\, \overline{A}_t\, \overline{A}_{t-1} \cdots \overline{A}_{s+1}\, \overline{B}_s} \end{aligned}

Line 1: Eq. 3 in Mamba, the convolution form, valid only when A, B and C are the same at every step. Line 2: Eq. 2 in Mamba with the per-token parameters of its Algorithm 2. Line 3 is our own one-line expansion of line 2.

  • \overline{K}_k is the kernel S4 computes (the S4 chapter): one number per lag k. It is the same for every input, so position alone decides how much a token counts. That is the top lane's yellow curves.
  • In the selective form, \overline{A}_t, \overline{B}_t and C_t are computed from the current token \htmlClass{t-blue}{x_t}. The bottom lane's gate is the simplest such rule. The next chapter shows Mamba's.
  • Multiply the recurrence out and the weight of an old token is the product of every \overline{A} since it arrived. If the tokens in between all say "keep" (\overline{A} near 1, as filler does in the toy), the old token survives untouched, however long the gap.

Mamba: input-dependent selection

The last chapter showed that a system whose \Delta, B and C never change weighs a token by where it sits, not by what it is. Mamba's fix is to let every token compute its own \Delta, B and C, so the token itself decides how far it moves the state.

Mark a token important and its white bar grows: a large \Delta. The state then flows toward that token for a long stretch of continuous time, forgetting most of what it held, and lands on a point that stores the token's value. Filler tokens get a tiny \Delta; the state barely moves and keeps what it has. The green output therefore holds the last important value across the filler that follows. The dashed path is the time-invariant model with one \Delta for everyone: it is pushed by every token alike, so its output wanders. The paper puts it this way: a large \Delta "resets the state h and focuses on the current input", and a small one "persists the state and ignores the current input".

Before you press All important: if every token gets the large step, what will the output remember at the last token? The answer is only the last token. A large \Delta is a reset, so selection is useful only when it is selective. All filler is the opposite failure: nothing gets in at all.

Here is the change, line by line, as Mamba's Algorithm 2 writes it. Shapes are in brackets; the letter \mathtt{B} inside a shape is the batch size, not the matrix B, and \mathtt{D} is the number of channels.

\begin{aligned} &\htmlData{step=1, link=write}{B : (\mathtt{B}, \mathtt{L}, \mathtt{N}) \gets s_B(\htmlClass{t-blue}{x}) = \mathrm{Linear}_N(\htmlClass{t-blue}{x})} \\ &\htmlData{step=2, link=output}{C : (\mathtt{B}, \mathtt{L}, \mathtt{N}) \gets s_C(\htmlClass{t-blue}{x}) = \mathrm{Linear}_N(\htmlClass{t-blue}{x})} \\ &\htmlData{step=3, link=delta}{\Delta : (\mathtt{B}, \mathtt{L}, \mathtt{D}) \gets \mathrm{softplus}\big(\mathrm{Parameter} + \mathrm{Broadcast}_D(\mathrm{Linear}_1(\htmlClass{t-blue}{x}))\big)} \\ &\htmlData{step=4, link=state}{\overline{A}, \overline{B} : (\mathtt{B}, \mathtt{L}, \mathtt{D}, \mathtt{N}) \gets \mathrm{discretize}(\Delta, A, B)} \\ &\htmlData{step=5, link=lti}{\htmlClass{t-green}{y} \gets \mathrm{SSM}(\overline{A}, \overline{B}, C)(\htmlClass{t-blue}{x}) \quad \text{time-varying: recurrence (scan) only}} \end{aligned}

Algorithm 2 in Mamba (the selective SSM, "S6"), lines 2 to 6; selection functions from Sec. 3.2.

  • In S4 (Algorithm 1) the same lines read B : (\mathtt{D}, \mathtt{N}), C : (\mathtt{D}, \mathtt{N}), \Delta : (\mathtt{D}): parameters, one set for the whole sequence. Selection adds the length axis \mathtt{L}: one set per token.
  • B and C have no channel axis: one write vector and one read vector per token, shared by all \mathtt{D} channels. \Delta has one value per channel per token.
  • The softplus, \log(1 + e^z), keeps \Delta positive. The Parameter is a bias per channel. \Delta starts from a single number per token, broadcast to all channels, because "if a given input x_t should be completely ignored ... all D channels should ignore it" (Sec. 3.5). Sec. 3.6 widens that number to a small rank R.
  • A stays a parameter. It acts only through \overline{A} = \exp(\Delta A), so a selective \Delta already makes \overline{A} selective.
  • Discretization is the zero-order hold of chapter 3, now done per token. The price is the last line: with parameters that change at every step, the long convolution of chapter 5 no longer exists, and only the recurrence is left.

Why a softplus, and why call it a gate? Take the smallest case: one state number, A = -1, B = 1, and \Delta = \mathrm{softplus}(z) with z a linear function of the token. The zero-order hold gives \overline{A} = e^{-\Delta} = 1/(1 + e^{z}) = 1 - \sigma(z) and \overline{B} = 1 - \overline{A} = \sigma(z), where \sigma is the logistic sigmoid. The recurrence becomes:

\htmlData{step=1, link=delta}{g_t = \sigma\big(\mathrm{Linear}(\htmlClass{t-blue}{x_t})\big)} \qquad \htmlData{step=2, link=state}{\htmlClass{t-yellow}{h_t} = (1 - g_t)\,\htmlClass{t-yellow}{h_{t-1}} + g_t\,\htmlClass{t-blue}{x_t}}

Theorem 1, Eq. 5 in Mamba (proof in App. C).

  • g_t is a gate between 0 and 1, computed from the token. Near 1 the state is replaced by the token; near 0 the token is ignored.
  • This is the gated recurrent network of chapter 2, with one difference that matters: there is no nonlinearity on the state, so the whole sequence can still be computed with a parallel scan.

So the gates that made LSTMs and GRUs trainable were a discretization all along. LSSL had shown it first, as Lemma 3.1: a gated recurrence is the backward-Euler discretization of the same one-number ODE, with \Delta = e^{z}. Mamba's Theorem 1 is the zero-order-hold version with a softplus step, and HiPPO Sec. 2.5 made the same remark for an input-dependent step. In the figure the slowest state number has exactly A = -1, so its gate per token is 1 - e^{-\Delta}: 0.88 for an important token (\Delta = 2.13) and 0.047 for filler (\Delta = 0.049).

The ablations at about 350M parameters (Table 7) say which selective part matters most. With no selective parameter the model reaches a perplexity of 10.93; with only a selective \Delta, 9.81; with \Delta, B and C all selective, 8.71. Lower is better.

The parallel scan and the hardware-aware kernel

Selection took away S4's shortcut. When \overline{A} and \overline{B} change at every token there is no single kernel to convolve with, so the states must come from the recurrence itself, and a loop over L tokens takes L steps, one after another: exactly what made RNNs slow to train. But each step is still linear in \htmlClass{t-yellow}{h}, and that is enough to compute all L states in about 2 \log_2 L rounds instead.

Step through it with Next level. Write one step of the recurrence, \htmlClass{t-yellow}{h_t} = a_t \htmlClass{t-yellow}{h_{t-1}} + b_t, as the pair (a_t, b_t): keep a_t of the old state, then add b_t. In Mamba, a_t = \overline{A}_t and b_t = \overline{B}_t \htmlClass{t-blue}{x_t}, separately for each state cell. Two steps in a row are again one step of the same form, so two pairs can be merged into one before anyone knows what state they will be applied to. In the up-sweep, neighbours merge in parallel: pairs of tokens, then fours, then eights, until the root holds the effect of the whole sequence. In the down-sweep, each node is handed the state just before its span: a left child copies its parent's, and a right child merges its parent's with its left sibling's pair. One last merge per token turns "the state before me" into "my state".

Martin and Cundy, who parallelized linear RNNs this way in 2018, write a step as an operator (\Lambda, x) \bullet h = \Lambda h + x. The merge rule below is our derivation from it: apply one step, then the next.

\begin{aligned} &\htmlData{step=1, link=pair}{\htmlClass{t-yellow}{h_t} = a_t\, \htmlClass{t-yellow}{h_{t-1}} + b_t \quad\longleftrightarrow\quad (a_t,\ b_t)} \\[4pt] &\htmlData{step=2, link=combine}{(a_1, b_1) \circ (a_2, b_2) = (a_1 a_2,\ \ a_2 b_1 + b_2)} \\[4pt] &\htmlData{step=3, link=assoc}{(p \circ q) \circ r = p \circ (q \circ r)} \\[4pt] &\htmlData{step=4, link=state}{\htmlClass{t-yellow}{h_t} = \text{the } b \text{ of } (a_1, b_1) \circ (a_2, b_2) \circ \cdots \circ (a_t, b_t), \quad \htmlClass{t-yellow}{h_0} = 0} \end{aligned}

Line 1 is Martin and Cundy's operator (Algorithm 1, line 2) in this page's letters. Lines 2 to 4 are our derivation from it. Mamba cites the parallel scan (Blelloch; Martin and Cundy; S5) and calls its own computation "recurrence (scan) only" (Algorithm 2, line 6), without writing the operator.

  • a_t is how much of the old state survives step t (a decay between 0 and 1 in Mamba), and b_t is what step t writes. The pair is the whole effect of one step on any state.
  • \circ means "apply the left pair, then the right one". The result is one pair that does both steps. Order matters: swap the two and you get (a_1 a_2,\ a_1 b_2 + b_1), a different step.
  • Grouping does not matter (associativity, which you can check by expanding both sides). So any tree of merges gives the same answer, and a parallel machine is free to pick the shallowest tree.
  • Starting from \htmlClass{t-yellow}{h_0} = 0, the merged pair for tokens 1 to t maps 0 to its own b, which is therefore \htmlClass{t-yellow}{h_t}.

Before you press All states: will the scan do less arithmetic than the loop, or more? It does more. For 8 tokens the tree needs 22 combines against the loop's 8 steps, about three times the work, but in 7 rounds that each run in parallel. The rounds grow with \log_2 L, so the gap opens quickly: at 2,048 tokens the scan needs 23 rounds instead of 2,048. Martin and Cundy count the same trade for p processors: O(6n(T/p + \lg p)) for the parallel scan against O(2nT) for the serial one, with n features and T steps.

Against attention, the training bill now reads: attention scores about L^2/2 pairs per head per layer, while the scan does about 3L combines per state cell, in about 2\log_2 L rounds.

Where the state lives

The tree fixes the depth. It does not fix the size. Every token's state has D \times N numbers, so the states of a whole batch form a tensor of shape (B, L, D, N), N times larger than the layer's input and output of shape (B, L, D). On a GPU, most operations other than matrix multiplication are limited by how fast data moves to and from memory, not by arithmetic (Mamba, Sec 3.3.2), so writing that tensor out and reading it back would cost more than computing it.

Mamba's kernel answers with three classical techniques, all named in its Sec 3.3.2. Kernel fusion: discretization, the scan and the multiplication by C run inside one GPU kernel, so the (B, L, D, N) values exist only in SRAM, the small fast memory on the chip, and only the inputs and the output cross to HBM, the large slow memory. The parallel scan runs inside that kernel. Recomputation: the states are not saved for the backward pass but recomputed when the inputs are loaded again, which is cheaper than storing them and reading them back. A sequence too long for SRAM is cut into chunks, and the scan carries its state from one chunk to the next (App. D). In the figure the fused kernel moves about 33 times fewer bytes than the standard route; Mamba states the saving as a factor of order N in memory traffic.

When the tree does not pay

The tree buys depth with extra work, so it wins only when there is enough length to spread. Martin and Cundy's parallel kernel runs at 0.06 times the speed of a serial one on 16-step sequences, and 38.5 times faster on 65,536 steps (their Table 1, 4 features). Hardware matters as much. Griffin, trained on TPU-v3, found the associative scan "significantly slower" than a plain sequential scan: its training step was up to 50% slower with it. Its authors wrote a sequential scan kernel that keeps the state in fast on-chip memory, almost 3x faster than the default JAX version, and guess that the tree's scattered memory access suits the TPU poorly. Our reading: the two papers agree on what matters, keeping the state in fast memory and moving as few bytes as possible; they differ on whether the tree is worth its extra work on their hardware.

Mamba-2: linear attention and state-space duality

Attention and Mamba look like opposites: one keeps every token and compares them all, the other folds the past into a small state. Linear attention, built from zero

In 2020, Katharopoulos and colleagues asked what happens if the exponential goes. They replace the similarity \exp(q \cdot k) with a dot product of features, \phi(q) \cdot \phi(k), where \phi is a fixed function applied to each vector (their Eq. 4). They pick \phi(x) = \mathrm{elu}(x) + 1 (Eq. 7): the exponential linear unit is x for positive x and e^x - 1 below zero, so \phi is always positive, like \exp. The paper calls the equivalence state-space duality (SSD): read one way the layer is an SSM, read the other way it is masked attention (Corollary 5.1). The link also runs in reverse. Theorem 5.2 proves that any masked kernel attention that runs as a recurrence with a bounded state must use a semiseparable mask, so every such linear attention is an SSM.

The price is expressiveness. Mamba gives every channel its own decay; Mamba-2 shares one decay per head, which the paper calls "slightly decreasing the expressive power in return for significant training efficiency improvements" (Sec 2.4). And SSD cannot express softmax attention, whose exponential has no finite feature map (Sec 10.3).

One matrix, two algorithms, and the mix

Because M has this structure, there are two ways to apply it. The quadratic way builds M, as attention does, and multiplies: work grows with T^2, but all of it is matrix multiplication, which GPUs run on dedicated matrix-multiply units called tensor cores. The recurrent way carries the state forward: work grows with T, but in T sequential steps of small vector updates that leave the tensor cores idle. That was Mamba's position, a scan that is linear in length but "does not leverage matrix multiplication units" (Sec 2.1).

The SSD algorithm (Sec 6) cuts M into chunks of Q tokens. Each diagonal block is a small attention problem: compute it the quadratic way, all chunks in parallel. Every block below the diagonal has rank at most N, because M is N-semiseparable (Definition 3.1): each such block factors through an N-dimensional bottleneck, and that bottleneck is the state. Those blocks take three batched matrix products: each chunk's final state from its own inputs, a short scan that hands the state from chunk to chunk (T/Q steps instead of T), and each chunk's outputs from the state that entered it.

Before you press Chunks of 1: which entries will still be computed the quadratic way? Only the diagonal. With chunks of one token every other entry goes through the state, so the chunked algorithm with Q = 1 is the recurrence, and with a single chunk of length T it is attention. Q slides between the two. Now pick chunks of 4 or 8 and switch back to softmax attention. The same blocks turn red: their rank equals their size, so no small state can stand in for them. Chunking works for linear attention and SSD because of the low rank, not because of the block shapes.

With N = P = Q every piece is a batch of N \times N matrix multiplications, and the total work is O(TN^2) (Theorem 6.1). At T = 4096 and N = P = Q = 64, our count from the Sec 6.3 cost list gives 2.1 billion multiply-adds per head for the quadratic way, 67 million for the chunked one (99.6% of it in matrix products) and 50 million for the recurrence. Against attention, the paper's Sec 6.3 table puts training work at T^2 N for attention and TN^2 for SSD, the work per generated token at TN against N^2, and the state at T entries against N.

Does the saving show on a GPU? Measured on an A100 80GB PCIe with state size 64, the SSD layer runs 2-8x faster than Mamba's fused scan, and faster than FlashAttention-2 (a fast exact attention kernel) from sequence length 2K on, 6x faster at 16K (Fig 10 and Sec 1). Because the work is in matrix products, the state can also grow: the paper allows states 8x Mamba's size with little slowdown. Mamba-2 uses N "around 64 or 128" (Sec 7.2), where Mamba's experiments used 16; N=256 appears only in the recall test below and in ablations. One caveat from the paper: a whole Mamba-2 model may still train slower than a Transformer at length 2K, because half of a Transformer's layers are MLP (multilayer perceptron) layers, which are pure matrix multiplication (Sec 9.3).

Act IVBeyond text, and honesty

Vision Mamba, VMamba, and a counterpoint

A vision Transformer (ViT) reads an image as a sequence: it cuts the picture into square patches, turns each patch into a token, and lets attention compare every patch with every other. An SSM can read the same sequence, but its scan runs in one direction, and a picture has no natural first patch.

Start with the causal raster scan: patches are read row by row, left to right, the way you read text. The green patch's output can only use patches the scan has already passed, so everything to its right and below is empty. Those patches come later, and they cannot reach it at all.

Even the patches it can see are reached unevenly. The patch to its left is one step back in the sequence. The patch directly above is a whole row back, 14 steps, so with a decay of 0.85 per step it arrives with weight 0.8514 = 0.10. Meanwhile the last patch of the row above, at the far edge of the image, is only seven steps back and counts three times as much. Flattening keeps some neighbours close and pushes others far away.

Vim (Vision Mamba) scans the same row-order sequence twice, once forward and once backward, with separate SSM weights, and adds the two gated outputs. Press Vim: forward + backward: now every patch can reach every other, and the right side lights up. But the patch below is still a row away in either direction, so vertical neighbours stay faint. VMamba (Visual State Space Model) adds two column-order routes, down the columns and back up, each with its own SSM; its authors call this SS2D, a 2D selective scan. In a column route the patch above is one step away. Press VMamba: four routes: the heat becomes a cross, strong along the row and along the column.

How much of this survives in a trained network is an empirical question, and the papers answer it in parts. Vim's ablation is the evidence that the backward scan matters. With the forward scan only, ImageNet top-1 is 73.2 and the ADE20K segmentation score is 32.3 mIoU (mean intersection over union); with a backward SSM and its own convolution, 73.9 and 35.9 (Table 4, no class token). The gain is much larger for segmentation, where every pixel needs context from all sides, than for classification.

Where to put the class token, the extra token whose final output the classifier reads? In a scan, position matters. Vim tried five designs, and the middle won: 76.1 against 75.2 with the token at the head (Table 5). The paper credits the recurrence and the fact that ImageNet objects tend to sit near the centre. Our reading adds the decay: from the middle, every patch is at most about half the sequence away in one of the two scans, while a token at the head is up to 196 steps from the far corner.

The results: Vim-Ti reaches 76.1 top-1 with 7M parameters, against 72.2 for DeiT-Ti, a ViT of the same size. Vim-S reaches 80.3 against 79.8. On square images 1248 pixels wide, 6084 tokens, Vim-Ti runs 2.8x faster than DeiT-Ti and uses 86.8% less GPU memory, measured on the backbone alone. Attention's score matrix grows with the square of those tokens; the scan's state does not grow at all. In the paper's memory chart DeiT-Ti's point at that size is marked OOM, out of memory. VMamba is built differently. It is hierarchical, like a convolutional network: for a 224-pixel input its four stages work on grids of 56, 28, 14, 7 patches per side (3136 tokens in the first stage), with no class token and no position embeddings. The counterpoint: is an image a long sequence?

MambaOut (Yu and Wang, 2024) asks the blunt question: do we need the SSM for vision at all? Its argument starts from cost. An SSM's advantage over attention is that its cost stays linear in the sequence length L, so the question is when attention's quadratic part actually dominates. Count the operations of one Transformer block with an MLP four times as wide as the model:

ImageNet at 224 pixels with 16-pixel patches is 196 tokens, so at ViT-S width the ratio is 0.09: short. The second half of the argument is about direction. An SSM mixes tokens causally, and MambaOut shows that causal mixing hurts image understanding: making ViT-S's attention causal and retraining drops it from 79.8 to 78.9. Two scans soften this, but each branch on its own is still causal.

Claim card: ImageNet classification does not need the SSM, detection and segmentation may (MambaOut)

Claim. An SSM is worth having for long sequences; ImageNet classification is short, so it does not need one, while detection and segmentation are long enough to benefit.

How it was measured. MambaOut stacks Gated CNN blocks: Mamba's block with the SSM removed, so the only token mixer is a 7x7 depthwise conv. What would have falsified it. MambaOut matching VMamba on COCO and ADE20K too, or falling clearly behind on ImageNet. The cleaner test, which the paper does not run, removes the SSM from one visual Mamba at matched compute and recipe; a drop on ImageNet there would refute the first half.

A second paper explains why Mamba does well on images in the first place, using the lens of chapter 9. MLLA (Mamba-Like Linear Attention; the final manuscript renames its model MILA) writes the selective scan beside causal linear attention and lines up the terms: C plays the query, B the key, the input the value, and the state is linear attention's running sum of keys times values. It finds six differences.

Claim card: the forget gate and the block design carry Mamba's gain in vision (MLLA)

Claim. In vision, Mamba behaves like single-head linear attention with an input gate (\Delta), a forget gate (\bar A), a skip connection (D) and no normalization, inside Mamba's block design. Of these, the forget gate and the block design do most of the work.

How it was measured. Start from Swin-T with its softmax attention replaced by linear attention. Add or remove one difference at a time and report ImageNet top-1 and throughput (Table 1). Then remove the forget gate and try position encodings in its place (Table 2).

Result. The baseline scores 77.6 at 1152 images per second. Adding the forget gate gives 78.4, but throughput falls to 743, because the gate turns the computation back into a recurrence. Adopting Mamba's block design gives 80.9. Position encodings can take the forget gate's place at no recurrent cost: 81.6 with LePE, 81.7 with CPE. The paper's reading is that images need local bias and positional information more than a causal decay.

What would have falsified it. The forget gate adding nothing on its own, or position encodings failing to replace it. Both are tested directly, one change at a time, on one architecture.

Put together, the vision papers draw a line through this survey's argument. Where sequences are short and every patch can be seen at once, the scan's direction is a cost and attention or a convolution does as well; where sequences grow to thousands of tokens, the fixed-size state pays for itself. But a fixed state has a price of its own. The next chapter measures what an SSM forgets that attention does not.

Where SSMs still lose

Every model since Mamba keeps its memory at a fixed size, and that is where its speed comes from. The price is just as simple: a fixed state cannot hold more facts than it has room for, while attention's cache keeps every one of them.

The state in the figure is the simplest fixed-size memory there is, the one linear attention builds. Each pair is written as an outer product \htmlClass{t-blue}{v}\,\htmlClass{t-blue}{k}^{\top} and added on top of everything written before. To read, multiply the state by a key. If that key were at right angles to every other stored key, the product would be exactly its own value. An N-dimensional space has room for only N keys at right angles, so from pair N+1 on, every read also picks up a little of every other value. That leak is called crosstalk, and it grows with every pair added. Random keys overlap a little from the start, so they fail earlier.

\htmlData{step=1, link=write}{\htmlClass{t-yellow}{h_t} = \htmlClass{t-yellow}{h_{t-1}} + \htmlClass{t-blue}{v_t}\,\htmlClass{t-blue}{k_t}^{\top}} \qquad \htmlData{step=2, link=read}{\htmlClass{t-green}{y} = \htmlClass{t-yellow}{h}\,\htmlClass{t-blue}{k_j}} \htmlData{step=3, link=signal}{\;=\; \htmlClass{t-blue}{v_j}} \htmlData{step=4, link=crosstalk}{\;+\; \htmlClass{t-red}{\textstyle\sum_{i \ne j} v_i\,(k_i^{\top} k_j)}}

Write rule: Eq. 10 in the linear attention paper, without its feature map; it is also RetNet's recurrence (Zoology App E.2) with the decay set to 1. Read: Eq. 12 there, without the normalizer. The split into signal and crosstalk is ours, for keys of length 1. Linear attention writes the state as keys by values; we write the transpose so it reads like the page's h.

  • \htmlClass{t-yellow}{h_t}: the state, N \times N numbers. Each pair adds one outer product. Nothing is ever removed in this toy; RetNet and Mamba also decay old content, which frees room but forgets.
  • \htmlClass{t-blue}{k_t}, \htmlClass{t-blue}{v_t}: the key and value a token writes. In a real layer they are learned projections of \htmlClass{t-blue}{x_t}, as in attention; here they are random unit vectors.
  • \htmlClass{t-green}{y} = \htmlClass{t-yellow}{h}\,\htmlClass{t-blue}{k_j}: a read with a stored key. Its first part is exactly the wanted value \htmlClass{t-blue}{v_j}.
  • \htmlClass{t-red}{\sum_{i \ne j} v_i (k_i^{\top} k_j)}: every other value, weighted by how much its key overlaps the query. It is zero only when k_j is at right angles to all other keys, which at most N keys can be.

Before you drag K: the 16 x 16 state holds 256 numbers, and one pair is 32 numbers. At how many pairs does it first return a wrong value? With random keys, at 11 pairs; at 16 pairs it still answers 94% of keys, at 32 only 47%, and at 64 it answers 27%. Press "Orthogonal keys": now every answer is right up to 16 pairs, the first wrong one comes at 19, and at 32 pairs the state answers 84%. The cache answers every key at every K. It pays for that with memory: two vectors per pair, so it passes the state's size at K = N/2 and keeps growing. That is chapter 1's trade seen from the other side. One lookup in the cache costs about 2NK multiply-adds and grows with the context; one read of the state costs N x N at any length.

That is the whole argument of this chapter in one picture. A fixed-size state is lossy compression. Exact recall of many key-value pairs, copying a long string token for token, and looking up one line in a long document all need memory that grows with what must be recalled. How much is lost depends on how big the state is next to what must be recalled, so a pure SSM does not always lose; the last box in this chapter shows one that wins.

No paper gives this curve

The toy is our own. No paper in this survey gives a formula for how many pairs a state of size N can hold. The closest statements are bounds. Repeat After Me, Corollary 2.8: a fixed-state model that copies strings of L tokens from an alphabet of D needs about L \log_2 D bits of state; with fewer, it gets more than half of random strings wrong. Based, Theorem 3.1 and Corollary F.13, and Zoology, Corollary H.24 (for RetNet): to solve associative recall, a recurrent model needs a state whose size grows in proportion to the sequence length.

What the papers measured

Four papers test this limit on real models. Each card says what was claimed, how it was measured, what came out, and what result would have proved it wrong. One translation first: Zoology and Based write N for the sequence length, while this page uses N for the state size.

Zoology: recall explains most of the gap

Claim
Most of the quality gap between gated-convolution language models and attention comes from one skill: recalling a token that appeared earlier in the same context.
How measured
17 language models (the appendix counts 14 training runs) trained on the Pile with the same data and recipe, 10B tokens for the smaller ones, changing only the layer that mixes the sequence: attention against the gated convolutions H3, Hyena and RWKV. Test tokens were split into "AR hits", the end of a word pair seen earlier in the context (6.4% of tokens), and the rest. Then a synthetic task, multi-query associative recall (MQAR): many key-value pairs, then many queries, in two-layer models.
Result
The text says the AR hits account for 82% of the average gap. No table shows that average; the mean of the nine cells for H3, Hyena and RWKV in its Table 4 is 81.6% (our arithmetic). Their smallest attention model beats a Hyena model 20 times its size on AR hits (perplexity 2.41 against 3.43). On MQAR, attention solves every sequence length with model width 64, while the gated convolutions stay below 0.9 accuracy unless the width is at least the sequence length. That result is about gated convolutions (H3, Hyena, RWKV, BaseConv). Zoology never trains Mamba. Its result for a fixed state is about RetNet, whose state is an outer-product memory like the toy's: Corollary H.24 proves it needs a state that grows with the sequence, and in its Fig. 6 RetNet needs more width as the pairs grow to 64.
Would have falsified it
AR hits matching attention while the overall gap stayed, which would put the share near zero; or a gated convolution passing 0.9 on MQAR with width below the sequence length at length 512.

Repeat After Me: copying and the phone book

Claim
Transformers copy and retrieve from their context better than models with a fixed state (the paper's class includes S4, Mamba, LSTMs and linear attention), in theory and in practice.
How measured
Theory: the bound above, and a transformer of depth 2 that copies strings exponentially long in its number of heads (Theorem 2.3). Experiments: models of about 160M parameters trained from scratch to copy random strings. Then pretrained Pythia transformers (410M to 2.8B) against Mamba (360M to 2.8B), all trained on the Pile with the same tokenizer, on a phone book: up to 200 lines of names and numbers, 2 worked examples (Sec. 4.3; the Fig. 1 caption says one), then one name to look up.
Result
Transformers needed 100x fewer training examples to learn to copy strings of up to 300 tokens. On the phone book, the smallest Pythia beats the largest Mamba whenever the book has 70 or more entries, the paper's stated condition; its plot shows Pythia ahead from about 40 entries. More state did not simply fix it: in the from-scratch runs, a sweep of Mamba's state size up to 256 found 32 best for copying.
Would have falsified it
A Mamba matching Pythia on phone books of 70 or more entries, or any fixed-state model copying random strings with fewer bits of state than the bound allows.

NVIDIA's 8B study: same data, same recipe

Claim
At equal data and training recipe, 8-billion-parameter pure SSMs match a Transformer on most tasks, but fail at copying from the context and lag on 5-shot MMLU until trained much longer.
How measured
A Transformer, a Mamba and a Mamba-2, each with about 8B parameters, trained on the same 1.1T tokens with the same hyperparameters; the Transformer and Mamba-2 again on 3.5T. Twelve standard tasks, long-context tests, and the phone book, averaged over 20 random phone books per length.
Result
Pure Mamba and Mamba-2 start giving wrong numbers once the phone book is longer than about 500 tokens (1.1T training tokens); Mamba-2 at 3.5T fails beyond about 1000. The Transformer stays near perfect up to its 4096-token context. On 5-shot MMLU at 1.1T, Table 2 gives 46.28 for the Transformer and 29.19 for Mamba-2, a gap of 17.09 points (our arithmetic). The prose states it twice, differently: 17 points in Sec. 3.3.1, "nearly 15 points" in Sec. 1. At 3.5T the gap shrinks to 1.37, and on a fill-in version of MMLU Mamba-2 already matched at 1.1T (37.68 against 37.26): the knowledge was there, the multiple-choice format in context was the problem. On the hardest multi-key needle search, Mamba-2 scores 5.5 to the Transformer's 58.
Would have falsified it
A pure Mamba-2 at 3.5T tokens answering the phone book correctly up to 4096 tokens.

Illusion of State: a different limit

State tracking, following a quantity that changes step by step, is a separate question from recall. Illusion of State proves that log-precision S4 and Mamba, like transformers, fall in the circuit class TC0, so, unless TC0 equals NC1, at a fixed depth neither can track compositions of permutations of five objects (the S5 word problem). In the same experiment, Mamba needs no more layers than the transformer for approximate state tracking.

A big enough state wins

Mamba-2 ran a harder version of MQAR (2 layers, sequences up to 1024 tokens, with T/4 key-value pairs for a sequence of length T). At the smallest model width, 32, Mamba-2 with state size N=256 reached about 0.95 accuracy at length 256, where softmax attention reached about 0.50; at length 1024 it still reached about 0.52, with attention near zero (values read from the plot, Fig. 8). Growing the state from N=16 to N=64 to N=256 helped in most panels (the paper says accuracy improves consistently; one small-width panel at length 256 is an exception in Fig. 8). Based found the same inside every architecture it tested: recall rises with state size. So "SSMs lose at recall" is too strong. What loses is a state that is small next to what must be recalled.

The loss is real but narrow: it shows up when the context holds more exact facts than the state has room for. The next chapter keeps the state and adds back a cache only where those facts are needed.

Hybrids: a little attention goes a long way

The last chapter found the leak: a fixed state cannot hold every exact fact, and a cache can. The fix the large models settled on is to keep the state and add back a cache in just a few layers.

Attention layers and Mamba layers do different jobs, so a model does not need many of the expensive kind. A Mamba layer is cheap and carries a summary of everything so far. An attention layer can look back at any earlier token exactly, which is what the phone book and MQAR test. Each attention layer keeps its own cache, so the cache shrinks in proportion to how many attention layers are removed, while each removed layer is replaced by a fixed-size state.

\htmlData{step=1, link=attn}{\htmlClass{t-brown}{M_{\rm KV}} = 2\, n_{\rm attn}} \htmlData{step=2, link=cache}{\cdot\, d_{\rm kv} \cdot \htmlClass{t-blue}{L} \cdot b} \qquad \htmlData{step=3, link=state}{\htmlClass{t-yellow}{M_{\rm state}} = n_{\rm mamba}\, \htmlClass{t-yellow}{s},\ \text{the same at any } \htmlClass{t-blue}{L}}

Our formula, not numbered in any of the papers; Griffin writes the same cache as 2NTh_k d_{\rm head} (App. F.4).

  • n_{\rm attn}: the number of attention layers; the 2 counts keys and values.
  • d_{\rm kv}: channels per key (key-value heads times head size); \htmlClass{t-blue}{L}: tokens in the context; b: bytes per number, 2 at 16 bits. For Jamba, d_{\rm kv} = 1024 is back-solved (our reading).
  • n_{\rm mamba}\, \htmlClass{t-yellow}{s}: each Mamba layer's state, fixed in size. Jamba does not publish s.

Does recall come back?

The cleanest test is NVIDIA's, because it holds everything else fixed. Its hybrid has the same width, data (3.5T tokens) and recipe as the 8B Transformer and pure Mamba-2 of the last chapter. Of its 56 layers, 24 are Mamba-2 (42.9%), 4 attention (7.1%) and 28 MLP (50%); the abstract rounds these to 43%, 7% and 50%. Counted among sequence mixers only, attention is 4 of 28, or 14.3%. It beats the Transformer on all 12 standard tasks, by 2.65 points on average (55.82 against 53.17; that average counts MMLU twice, at 0 and 5 shots, our reading). On the phone book that pure Mamba-2 failed past about 1000 tokens, the 4K hybrid is perfect up to 5.5K tokens, and the version extended to 128K stays perfect with phone books longer than 150K tokens. Generating with long contexts, the hybrid is "predicted to be up to 8x faster" (8x, at batch size 32): a prediction from a cost model, not a measurement, and not the same claim as the separate 8x speedup of Mamba-2's scan over Mamba's.

The production hybrids disagree on the details

Which Mamba
Jamba-1.5 kept Mamba-1. In its tests at 350M and 1.3B parameters (100B tokens), Mamba-2 beat Mamba-1 on its own, but Mamba-1 with attention beat Mamba-2 with attention. Nemotron-H uses Mamba-2.
How much attention
Nemotron-H says "roughly 8%" attention, but it counts every FFN layer as a layer: 4 of 52 (8B) and 10 of 118 (56B). Among sequence mixers it is 4 of 28 (14.3%) and 10 of 64 (15.6%), a little more than Jamba's 12.5%. The figure's slider uses that denominator.
Scale
Jamba-1.5-Large has 9 blocks of the same 1:7 pattern, width 8192 and 8 key-value heads; that gives 36 KiB per token (our reading), exactly its Table 1 value of 9GB at 256K tokens. Griffin is a different kind of hybrid

Griffin mixes two recurrent layers with one attention layer, but its attention is local: each token sees only the last 1024 tokens. Its cache therefore stops growing at the window, a third shape between the flat state and the growing cache. The price shows on the phone book: Griffin solves it perfectly only up to a context that matches its window of 1024, then degrades. Jamba, Nemotron-H and the NVIDIA hybrid use global attention, which is why they keep recalling far beyond any window.

Where state-space models went

Switch the figure to the domain view and one thing stands out: most of this work is not about language. By title keywords, general vision leads with 469 papers, model architecture and theory follow with 417, and medical imaging has 332, about twice the 158 about language and large language models. The chapter on vision is the caution: on short sequences the state-space part may not be what helps.

The family tree

Three lines run through the tree. The state-space line goes from HiPPO's memory to S4's structure, to the diagonal simplifications (DSS, S4D, S5), to H3's gates, to Mamba's selection and Mamba-2's duality. The linear-attention line starts from the observation that dropping softmax turns attention into a recurrence, and adds gates (RetNet, GLA) and then a smarter write rule (DeltaNet). The linear-RNN line (LRU, Griffin, xLSTM, minGRU) arrives at the same place from the RNN side. Mamba-2 is where the first two meet: chapter 9 showed they compute the same matrix.

What came next

Mamba-3's own introduction names two layers as the ones used in production hybrids: Mamba-2 and Gated DeltaNet. So the latest step is a pair, not a single winner. Gated DeltaNet combines Mamba-2's decay gate, which erases memory quickly, with the delta rule, which overwrites one stored association instead of adding on top of it. Mamba-3 changes the discretization (an exponential-trapezoidal rule instead of zero-order hold), lets the state rotate with complex values, and processes several inputs per state update (MIMO) to use the hardware better. At 1.5 billion parameters its single-input version averages 56.4 on its downstream suite against 55.8 for Gated DeltaNet, and the MIMO version 57.6 (Mamba-3 Table 3).

In deployed models the hybrid won. Nemotron-H reports up to 3x faster inference than Transformers of similar size, and Falcon-H1 claims to match or beat models up to 70B parameters, both with attention layers kept for lookup.

Open questions

  • How much state is enough? Recall improves with state size (chapter 11), and Mamba-3 reaches Mamba-2's quality with a smaller state (chapter 9 and the family tree). Where the curve flattens for real long-context tasks is not settled.
  • How much attention is enough? The studies in chapter 12 land near 7 to 8 percent of all layers, or roughly 12 to 16 percent of the sequence-mixing layers, measured on different models and data. Nobody has a rule.
  • When does vision need a state space? MambaOut's answer is "only for long sequences". Dense prediction, video and 3D medical volumes are where that claim will be tested.
  • Can a recurrence track state exactly? Fixed-depth SSMs and transformers share the same limit on tracking state (the Illusion of State card in chapter 11). Whether input-dependent, complex or non-diagonal transitions escape it in practice is open.

Summary

Attention keeps every token and re-reads all of them, so its cache grows with the context and its prompt cost grows with the square of the length. A state-space model keeps a fixed-size state instead. Making that work took four steps. Drop the nonlinearity inside the recurrence, so the sequence becomes a sum that trains in parallel (LRU). Treat the recurrence as a sampled continuous system and choose its matrix so the state is the best summary of the past (HiPPO). Exploit the fixed matrix to compute the whole layer as one long convolution (S4). Then let the input choose what to keep, which breaks the convolution, and recover the speed with a hardware-aware parallel scan (Mamba). Mamba-2 showed that this selective state space is masked linear attention with a decay: one matrix, computable either way. The same idea spread to images (Vim, VMamba), where scanning order matters and short sequences may not need it (MambaOut). The honest limit is recall: a fixed state cannot keep everything verbatim, and pure SSMs fall behind on copying, phonebook lookup and some in-context tasks unless the state is large compared with what must be remembered. The answer that shipped is the hybrid: mostly state-space layers, with a few attention layers kept for lookup.
