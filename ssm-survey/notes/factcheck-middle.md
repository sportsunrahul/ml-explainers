## 3. Notes (no change to a claim needed)

- N1 (page claim mamba-throughput-5x). The 5x compares peaks at different batch sizes: Mamba-1.4B 1814 tok/s at
  batch 128 vs Transformer-1.3B 364 tok/s at batch 32 (it is OOM at 64 and 128). At equal batch 32 the ratio is
  1445/364 = 3.97x; at batch 1 it is 140/79 = 1.77x. Sec 4.5 body text says 4-5x. Say "up to 5x, each model at
  the largest batch it fits". Evidence: Fig. 8 right bar labels (rendered from src/fig/mamba_inference.pdf); Sec 4.5.
- N2 (cross-paper averages). The Mamba-1 Table 3 averages (mamba-zs-*-avg) use 6 tasks. Mamba-2 Tables 1, 3, 10
  add OpenbookQA (7 tasks), see section 2. Do not put the two sets of averages side by side.
- N3 (mamba-2p8b-* arithmetic, our_reading). Redone, all correct: 64 x 5120 x (16 + 3) = 6,225,920 values;
  x 2 B = 12,451,840 B = 11.875 MiB; x 4 B = 23.75 MiB; SSM only 5,242,880 x 2 B = 10.0 MiB;
  12,451,840 / 131,072 = 95.0 KV tokens; 3 x 2 x 2560^2 x 64 = 2,516,582,400 = 2.52B. Caveats: N = 16 and
  d_conv = 4 come from the README usage-example defaults, not from a stated 2.8B config (the code_only and
  our_reading labels cover this). "3 past inputs" is the minimum conv state; README.md does not say how the
  released code sizes its conv cache, so do not present 11.875 MiB as the exact implementation footprint.
- N4 (Mamba Fig. 8). Every bar label in mamba-tput-* matches the figure. The legend says "Mamba 6.9B"; the word
  "untrained" comes from Sec 4.5 and App. E.5. App. E.5 names the GPU "A100 80GB PCIe"; the figure title says
  "A100 80GB".
- N5 (understanding.md, line 48). "Released sizes 130M-2.8B are README-only" is too strong: the sizes are in
  Mamba Table 3. Only their layer counts and widths are README-only. Suggest: "configs (layers, d_model) of the
  released 130M-2.8B models are README-only".
- N6 (VMamba d_state). Table 12 also has d_state 8 (ssm-ratio 1.5) at 82.69, above the final 82.60, at the
  intermediate [2,2,5,2] config. A page may say the final models use d_state = 1 (correct); it must not say
  d_state = 1 gave the best accuracy. Evidence: vmamba appendix.tex Table 12 (tab:app_dstate).
- N7 (figure labels). Vim Fig. 1(b)/(c), Fig. 3, Fig. 4 and MambaOut Fig. 3(b) print their values on the plot,
  so those claims need no uncertain flag. The four Mamba-2 plot reads (Fig. 8, Fig. 10) carry uncertain and agree
  with the plots on a re-read.
- N8 (dates and venues). All submission dates, version numbers and venues match abs.html (and README.md for
  mambaout-venue, vim-v2-date, vmamba-v3-date).
