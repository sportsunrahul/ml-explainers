Pattern

The stage shows one layer: each row is an output channel, each column an input. Many trained weights are close to zero. sets the smallest ones to exactly zero; the share of zeros is the layer's . Green cells are kept, brown cells are pruned.

Guess before you switch patterns: at the same sparsity, which pattern keeps the most of the weights' total size, and which one does a GPU run faster? Unstructured pruning keeps the most, because it removes exactly the smallest weights. But a dense GPU kernel still multiplies every zero.

The must drop two of every four inputs, so it loses a few large weights. In return, skip half the multiplies. lose the most, but what is left is a smaller dense layer that any kernel runs faster.

The layer is a toy with random weights. The pruning for each pattern and the kept share are computed exactly. The tensor-core facts are from Mishra et al. (NVIDIA): up to 2x math throughput for 2:4, with a 2-bit index per kept weight.

Fewer weights is not the same as less time. Prune in a shape the hardware skips: 2:4 on newer NVIDIA GPUs, or whole channels anywhere.
