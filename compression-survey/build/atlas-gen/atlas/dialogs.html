Arithmetic intensity

The number of arithmetic operations a layer does for each byte it moves to or from GPU memory. A 3x3 convolution on a large feature map reuses each weight at every pixel, so it does hundreds of operations per byte. A layer that touches each weight once, such as a language-model layer processing one token, does about one.

Low intensity means the layer waits on memory; high intensity means it waits on arithmetic.

Tensor cores

Units on NVIDIA GPUs that multiply small matrices in one step. They run FP16 and INT8 (and, on newer GPUs, FP8 and FP4) much faster than ordinary FP32 arithmetic. A layer gets their speed only if it is written as a matrix multiply in a format they support.

FP32, FP16, INT8

FP32 is the 32-bit floating-point format a network is usually trained in. FP16 is a 16-bit float: half the bytes, and fast on tensor cores. INT8 is an 8-bit integer: a quarter of the bytes of FP32, and twice the FP16 tensor-core rate on the toy GPU here. INT8 needs a scale to map real values onto its 256 levels; chapter 3 shows how.

Logits

The raw scores a classifier computes for each class, one number per class, before they are turned into probabilities. They can be any size and sign. A higher logit means the network favors that class more. Only the differences between logits matter for the probabilities.

Softmax

The function that turns logits into probabilities: raise e to the power of each logit, then divide by the sum so the results add up to one. A logit a few units above the rest takes almost all of the probability.

Temperature

A number T that divides every logit before the softmax. T = 1 is the normal softmax. A larger T shrinks the gaps between logits, so the probabilities become more even and the small ones become visible. In distillation the teacher and the student use the same T during training; the finished student runs at T = 1.

KL divergence

The Kullback-Leibler divergence KL(p || q) measures how far a distribution q is from a distribution p. It is zero only when the two are the same. Here p is the teacher's softened output and q the student's. It equals the cross-entropy of q against p minus the entropy of p; the student cannot change the second part, so minimizing either one gives the same gradient.

Scale

The real distance between two neighboring marks of a quantization grid, written S (or Δ, or s). A code q stands for the real value S times (q minus the zero-point). A large scale covers a wide range with coarse marks; a small scale gives fine marks over a narrow range.

Zero-point

The integer code that represents the real value 0.0 exactly, written Z. It lets an unsigned 8-bit grid (codes 0 to 255) cover a range that is not centered on zero. Zero must be exact because padding and ReLU produce many exact zeros. A symmetric grid has Z = 0 and signed codes; GPU toolchains such as TensorRT use that.

Histogram

A bar chart of how many values fall into each small interval of the number line. Calibration records one histogram per activation tensor while a few hundred images pass through the network, then picks the tensor's range from it.

Per-channel quantization

Instead of one scale for a whole weight tensor, each output channel (each filter) gets its own scale fitted to its own range. It costs almost nothing: an output value depends on one filter only, so its scale can be applied after the integer sum. Input channels cannot get their own scales, because those would not factor out of the sum. TensorRT recommends per-channel weights and per-tensor activations for INT8.

Calibration

Choosing the quantization range of each activation tensor from data. A small set of representative images (Wu used 512 training images per detector; Nagel says 500 to 1000 unlabeled images usually suffice) runs through the float network, and a calibrator turns each tensor's histogram into one clip value. Since TensorRT 11 this is done by a tool such as Model Optimizer, which writes the result into the model as quantize nodes.

Percentile

The value below which a given share of the data lies. The 99.99th percentile of the absolute values leaves 1 value in 10,000 above it, so percentile calibration with 99.99 clips exactly that share, whatever the tail looks like.

KL divergence (in calibration)

A measure of how different two probability distributions are: KL(P || Q) is the sum over bins of P log(P / Q). It is zero only when they match. The entropy calibrator compares the activation histogram, with the clipped tail piled into its last bin, against the same histogram as an 8-bit grid can represent it, and picks the clip value where they differ least.

Fake quantization

Rounding a value onto the integer grid and immediately scaling it back to a float: divide by the step size, clip to the grid's range, round to the nearest integer, multiply by the step size again. The result is still a float tensor, but every value sits exactly on a grid level, so the forward pass sees the same numbers the integer model will compute.

Shadow weights

The full-precision (FP32) copy of each weight that the optimizer updates during quantization-aware training. Each forward pass rounds the shadow weights onto the grid and uses only the rounded values. Small updates add up in the shadow weight until it crosses a rounding boundary and the rounded value jumps to the next level. After training, only the rounded integers are kept.

Gradient

For each weight, how much the loss would change if that weight moved a little, and in which direction. Training moves every weight a small step against its gradient. Backpropagation computes the gradient from the loss back to the input by multiplying the slopes of every operation on the way. One flat operation, with slope zero, stops the gradient for everything before it.

Straight-through estimator

A rule for the backward pass through rounding: use slope 1, as if rounding did nothing, instead of its true slope of zero. Bengio, Leonard and Courville named it for binary neurons, crediting a lecture by Hinton. Quantization uses a clipped version: slope 1 inside the grid's range and 0 outside it (Krishnamoorthi; Esser et al.; Wu et al.). The estimate is biased, but in practice it trains.

Sparsity

The share of a layer's weights that are exactly zero. A layer with half its weights at zero is 50% sparse. Zeros can be left out of storage, but whether they save time depends on whether the kernel that runs the layer can skip them.

Magnitude pruning

Set the weights with the smallest absolute values to zero, on the idea that they change the output least. Han et al. set the cut-off as a quality parameter times the standard deviation of the layer's weights. The pruned network is then trained again so the surviving weights make up for the loss, and prune-and-retrain can be repeated.

The 2:4 pattern

In every group of four consecutive weights along the dimension a matrix multiply sums over, at least two are zero, so the layer is exactly half zeros. Pruning keeps the two largest of each group. The kept values are packed together, each with a 2-bit index that says which of the four positions it came from. Mishra et al. train the network dense, prune it to this pattern once, and retrain it with the same schedule and the mask fixed.

Sparse tensor cores

Tensor cores on the A100 and later NVIDIA GPUs that accept a weight matrix in the 2:4 format. The hardware reads the 2-bit indices and picks the matching inputs, so it does half the multiplies. The peak rate doubles; Mishra et al. measured nearly 2x on large INT8 matrix multiplies and timed no whole network, so the gain for a full detector must be timed. TensorRT handles 2:4 weights from version 8.0.

Structured pruning

Removing whole pieces of the computation, such as entire filters or channels, instead of single weights. Li et al. rank filters by the sum of their absolute weights; network slimming ranks channels by their batch-norm scale. What is left is an ordinary, thinner dense network, so every kernel and compiler runs it faster with no special support. Liu et al. found that training the thinner architecture from scratch works as well as keeping the pruned weights.

Large language model (LLM)

A transformer network trained to predict the next word of text, with billions of weights. Most of its time and memory go into large matrix multiplies, so it is where 8-bit and 4-bit methods were pushed hardest.

Its numbers matter here because they behave differently from a convolutional detector's: past a few billion weights, a handful of channels become very large.

Activations

The numbers that flow between layers while the network runs: the input and output of each layer, recomputed for every image or token. Weights are fixed after training; activations change with every input.

To run a layer in INT8, both its weights and its input activations must be put on an integer grid.

Outlier channels

A few channels (feature dimensions) whose values are many times larger than all the others, in nearly every token. Dettmers et al. report up to 20x, and from 6.7B parameters up the outliers sit in every layer; Xiao et al. report about 100x, and their OPT-13B plot shows channels above 70. They matter to the model: setting them to zero badly damages its predictions, so they cannot simply be clipped.

One scale per tensor

The simplest way to quantize: one scale for the whole matrix, set by its largest absolute value, so that value lands on level 127. Every other value is divided by the same scale and rounded.

It is cheap, and it fits a GPU's integer matrix multiply. It fails when a few values are far larger than the rest, because then the steps are too coarse for everything else.

Smoothing (SmoothQuant)

For each input channel j, divide the activations by a number sj and multiply the matching row of weights by the same number. The layer's output is unchanged. The division is folded into the layer before, so it costs nothing at run time.

The scale is sj = max|Xj|alpha / max|Wj|1-alpha. Alpha, the migration strength, says how much of the difficulty moves from activations to weights.

Floating point

A way to write a number as a sign, a power of two and a fraction, like scientific notation in base 2. Because the power of two can change, the same few bits can hold both very small and very large numbers. The price is that the gap between neighbouring values grows with their size.

Exponent

The bits of a float that choose the power of two. Each step of the exponent doubles the value, so it picks a range such as 1 to 2, 2 to 4 or 4 to 8. More exponent bits mean more of these ranges, so a wider span from the smallest to the largest value.

Mantissa

The bits of a float that choose a value inside the range the exponent picked. With 3 mantissa bits there are 8 evenly spaced marks in each range; with 2 bits there are 4. More mantissa bits mean finer steps, so higher precision.

E4M3

The 8-bit float with 1 sign bit, 4 exponent bits and 3 mantissa bits. It gives up infinities and keeps a single NaN pattern, which lets it reach 448. It is meant for weights and activations, where precision matters, and it is the FP8 format TensorRT uses.

E5M2

The 8-bit float with 1 sign bit, 5 exponent bits and 2 mantissa bits. It follows the usual rules of 16-bit floats, with infinities and NaNs, and reaches 57,344. It is meant for gradients during training, where range matters more than precision.

Scaling factor

A number that each tensor is divided by before it is rounded to 8 bits, and multiplied by afterwards. It slides the tensor onto the part of the format where the marks are. Here it is chosen so that the format's largest value meets the tensor's largest value. FP8 needs a scale just as INT8 does.
