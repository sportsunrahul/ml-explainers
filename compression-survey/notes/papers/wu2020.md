- Authors: Hao Wu (first) ... Paulius Micikevicius (last). NVIDIA (Isaev: Georgia Tech intern).

## 2. Core problem
Which integer quantization choices (affine vs scale, granularity, calibrator) keep accuracy while still running on
high-throughput integer math pipelines, measured across many networks and tasks, ending in an int8 workflow that
stays within 1% (relative) of FP32 everywhere.

## 3. What prior practice did and why that hurt (per the paper)
- Krishnamoorthi 2018: even per-channel int8 PTQ leaves MobileNets below baseline; QAT needed (Sec. 2).
- Per-tensor weight quantization loses accuracy for some nets and collapses EfficientNet b0 once BN is folded
  (76.85 -> 12.93, Table 3).
- Max calibration is inconsistent across networks (Inception v4 0.12, EfficientNet b0 22.3; Table 5).
- Affine weight quantization adds a data-dependent term that can erase the integer-math speed advantage (Sec. 3.3).

## 4. The one key idea
For int8 on GPUs: scale (symmetric) quantization everywhere, per-channel max-calibrated weights, per-tensor activations
with a calibrator chosen by trying several; if accuracy is short, skip the few most sensitive layers, then do a short
QAT fine-tune from the best calibration.

## 5. Mechanism, step by step
1. Quantize compute-heavy ops only (conv, linear, matmul, LSTM cells); softmax and BN stay in float; BN is folded
   (App. C). An op is quantized by quantizing its inputs; outputs are not requantized to int8 because the next op
   may need precision (Sec. 4).
2. Weights: per-channel (per-output-channel / per-column), scale quantization, range [-127, 127], max calibration.
3. Activations: per-tensor scale quantization, range chosen on calibration data from the training set (1024 samples
   for ImageNet nets, 512 for detection/segmentation; Table 9).
4. Calibrators (Sec. 3.4, symmetric ranges): Max = maximum absolute value seen; Entropy = minimize KL divergence between
   the original float values and what the quantized format can represent ("the default method used by TensorRT");
   Percentile = range at a percentile of |x| (99% clips the largest 1%). Tested: max, entropy, 99.9, 99.99, 99.999,
   99.9999. There is NO MSE calibrator in this paper and NO equation for the entropy method (it cites the TensorRT GTC
   talk, TrtQuantGtc).
5. Partial quantization (Sec. 5.1): one-at-a-time sensitivity analysis (quantize only one layer, measure accuracy),
   sort layers by sensitivity, leave the most sensitive in float until accuracy is met.
6. QAT (Sec. 5.2): insert fake quantization (Eq. 12) at op inputs; STE (Eq. 13); start from the best calibrated PTQ
   model; ranges fixed during fine-tuning (PACT learned ranges tested separately, Sec. 5.3).

Recommended workflow (Sec. 6, p12), quoted:
"Weights: Use scale quantization with per-column/per-channel granularity; Use a symmetric integer range for
quantization [-127, 127]) and max calibration. Activations: Use scale quantization with with per-tensor granularity."
"PTQ: Quantize all the computationally intensive layers (convolution, linear, matrix multiplication, etc.) and run
activation calibration including max, entropy and 99.99%, 99.999% percentile. If none of the calibrations yield the
desired accuracy continue to partial quantization or QAT.
Partial Quantization: Perform sensitivity analysis to identify the most sensitive layers and leave them in
floating-point. If the impact on computational performance is not acceptable or an acceptable accuracy cannot be
reached, continue to QAT.
QAT: Start from the best calibrated quantized model. Use QAT to fine-tune for around 10% of the original training
schedule with an annealing learning rate schedule starting at 1% of the initial training learning rate."
(Source typos kept: stray ")" and "with with".)
Fig. 5 flow chart (recipe.pdf): Pretrained network -> Unified calibration (max, entropy, 99.99%, "999%" [sic, means
99.999%]) -> Evaluate, pick best calibration -> Accuracy good? Y: Success. N: Build per-layer sensitivity profile ->
Skip most sensitive layers until accuracy target is met -> Performance good? Y: Success; N: loop back -> Fine tune with
quantization, start from best calibration, use STE -> Accuracy good? Y: Success; N: Advanced Topics.

## 6. Equations (TeX verbatim from src/main.tex; PDF number in brackets)
- [1] `s =\frac{2^{b}-1}{\alpha - \beta}` -- affine scale; [beta, alpha] = chosen real range, b = bit-width.
  Note Wu's s multiplies x (s = integer range / real range), the inverse of Nagel's s (step size).
- [2] `z =-\round(\beta \cdot s)-2^{b-1}` -- zero-point; for int8 s = 255/(alpha-beta), z = -round(beta s) - 128.
- [3] clip(x, l, u) = l if x < l, x if l <= x <= u, u if x > u.
- [4] `x_q = \quantize (x, b, s, z)  = \clip(\round(s \cdot x + z), -2^{b-1}, 2^{b-1}-1)` -- signed b-bit output.
- [5] `\hat{x} = \dequantize(x_q, s, z)  = \frac{1}{s}(x_q - z)`
- [6] `s =\frac{2^{b-1}-1}{\alpha}` -- scale (symmetric) quantization for range [-alpha, alpha].
- [7] `x_q = \quantize (x, b, s)  = \clip(\round(s \cdot x ), -2^{b-1}+1, 2^{b-1}-1)` -- int8 uses [-127, 127].
- [8] `\hat{x} = \dequantize(x_q, s) = \frac{1}{s} x_q`
- [9] per-element dot product: `y_{ij} = \sum_{k=1}^{p}{x_{ik} \cdot w_{kj}} \approx \sum_{k=1}^{p}{\dequantize(x_{q,ik}, s_{q, ik}) \cdot \dequantize(w_{q,kj}, s_{w,kj})} = \sum_{k=1}^{p}{\frac{1}{s_{x,ik}}x_{q,ik} \cdot \frac{1}{s_{w,kj}}w_{q,kj} }`
- [10] `\frac{1}{s_{x,i} \cdot s_{w,j}}\sum_{k=1}^{p}{ x_{q,ik} \cdot w_{q,kj}}` -- scales must not depend on k: per-row or
  per-tensor for activations, per-column or per-tensor for weights. Per-row activation scales are impractical (row
  count varies with batch/sequence), so activations are per-tensor; per-column of W in Y = XW = per-output-channel for conv.
- [11] affine weights: `y_{ij} \approx \frac{1}{s_xs_{w,j}} \bigg( \underset{(1)}{\sum_{k=1}^{p}{x_{q,ik} w_{q,kj}}} - \underset{(2)}{\sum_{k=1}^{p}{(w_{q,kj} z_x + z_x z_{w,j})}} - \underset{(3)}{\sum_{k=1}^{p}{x_{q,ik} z_{w,j}}} \bigg)`
  (second line of the split). (1) integer dot product; (2) offline, folds into bias; (3) needs the input X_q at run
  time -- "can introduce considerable overhead, reducing or even eliminating the throughput advantage". Overhead only
  if the WEIGHTS are affine -> recommend scale quantization for weights. Affine activations would be free, but scale was
  sufficient for every network studied.
- [12] `\hat{x} = \dequantize(\quantize(x, b, s), b, s)` -- fake quantization.
- [13] STE: `\frac{d\hat{x}}{dx} = 0, & y < \beta \\ 1, &  \beta \le y \le \alpha \\ 0, & y > \alpha` (cases environment
  body; the source writes y where x is meant). Fig. 4 shows a 3-bit fake quantizer and its STE derivative.
- [14]-[16] BN folding (App. C): c = gamma/sqrt(Var[y]+eps), d = beta - gamma E[y]/sqrt(Var[y]+eps); w'_kj = c_j w_kj,
  b'_j = c_j b_j + d_j.

## 7. Measurement setup (analysis lens)
- Framework: PyTorch with custom quantization ops (simulated). Metric reported as percent; deltas are RELATIVE:
  (acc_int8 - acc_fp32)/acc_fp32 (Sec. 4). Never convert to absolute points.
- Vision models (Table 2 + Table 9): MobileNet v1/v2 (width_mult 1.0), ResNet50 v1.5, ResNet152 v1.5, Inception v3/v4,
  ResNeXt50 32x4d, ResNeXt101 32x8d, EfficientNet b0/b3 on ImageNet 2012 val top-1; inputs 224x224 (Inception 299x299).
  Detection on COCO 2017 val mAP: Faster R-CNN resnet50-fpn and Mask R-CNN resnet50-fpn (torchvision), RetinaNet
  resnext101-32x4d-fpn (mmdetection). Segmentation COCO 2017 val mIoU: FCN resnet101, DeepLabV3 resnet101
  (torchvision). Mask R-CNN mAP type (box or mask) not stated. App. A.1 calls RetinaNet "an additional segmentation
  network" (typo; it is listed under Detection in Table 2).
- Calibration: 1024 samples (classification), 512 (detection and segmentation), from each training set (Table 9).
- QAT schedule (Table 10, App. A.2): classification ImageNet SGD 15 epochs lr 1.0e-3 batch 256; detection COCO 2017
  SGD 3 epochs lr 2.5e-5 batch 16; segmentation COCO 2017 SGD 3 epochs lr 2.5e-5 batch 32. Around 1/10th of original
  steps; LR starts at 1/100th of the original initial LR and decays to 1/100th of that with cosine annealing.
  Detection/segmentation fine-tuned only on COCO.
- Held fixed: weights per-channel max, scale quantization, activations per-tensor.
- No speed/latency measured; Table 1 gives Turing relative throughput only: FP16 8x math / 2x bandwidth, INT8 16x / 4x,
  INT4 32x / 8x, INT1 128x / 32x (vs FP32 1x).

## 9. Limitations stated
- Int8 only; lower bit-widths and methods like ADMM or distillation left to future work (Sec. 7).
- PACT might do better with longer fine-tuning or separate range hyperparameters (Sec. 5.3).
- BERT has no small sensitive layer subset (141 of 244 skipped) -> needs QAT or GELU10 (App. D).
- No timing measurements; speed benefits are only Table 1 throughput ratios for Turing.

## 10. Outline feedback

  to TensorRT. Source viz-calib's KL algorithm from the TensorRT docs or label it "our reading"; source the MSE objective
  from Nagel Eq. 16.
- The detection/segmentation tables are Table 5 (calibrators), Table 7 (PTQ best vs QAT), Table 11 (QAT per
  calibrator); the outline's "Wu Tables 4-7" works only if Table 4 means weights-only.
- Wu's DeepLabV3 and FCN are ResNet-101 models evaluated on COCO 2017 val; RetinaNet is ResNeXt-101-32x4d-FPN from
  mmdetection, not ResNet-50-FPN. The running example and guide rows must carry backbone and dataset.
- All Wu deltas are relative percent. Do not mix them with Nagel/BRECQ absolute point drops in one column.
- Table 6 + Fig. 3 (partial quantization, depthwise layers most sensitive) is the direct source for the guide's
  "per-layer sensitivity, keep sensitive layers in FP16" step. Wu leaves them in floating point, not specifically FP16.
- Calibration set guidance for the guide: Wu used 512 training images for detection/segmentation.
