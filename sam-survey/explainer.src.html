Every model in the SAM line answers the same request. Someone points at an image with a prompt (a click, a box, a word), and the model returns a mask: the set of pixels that belong to the thing. The models before SAM, in chapter 1, take no prompt at all, and SAM 3D, at the end of the line, returns a 3D shape instead of a mask. The papers differ in what counts as a prompt, how many answers come back, and what the model had to see to learn it. One color key holds for the whole page:

Act IBefore SAM

Four ways to draw a mask

A mask is the set of pixels that belong to one thing, drawn as a filled shape on the image. Before 2023, most segmentation models learned to draw masks for a fixed list of classes, from one labelled dataset. Step through four of them on the same desk scene.

FCN (2014) took an image classifier and made every layer a convolution, so one forward pass gives a score for every class at every location. The scores come out on a coarse grid: one cell per 32 pixels. FCN then adds finer scores from earlier layers to sharpen the edges. On a subset of the PASCAL VOC 2011 validation set, the mean overlap (mean IU) went from 59.4 at stride 32 to 62.7 at stride 8. The output has 21 channels: the 20 PASCAL classes plus background.

U-Net (2015) made that idea symmetric. A contracting path shrinks the image and an expanding path grows it back, and skip connections copy detail from each level of the first path to the matching level of the second. It was built for cell images with very few labels: 30 training images for one challenge, and 2 output classes. In our reading, its encoder-decoder shape with skip connections is still the template for many dense-prediction networks.

Mask R-CNN (2017) asked a different question: which pixels belong to this object? It detects each object with a box, cuts the features inside the box, and predicts a small 28x28 mask for it, one per class (80 COCO classes). Two cups become two masks, not one blob. That is instance segmentation; labelling pixels by class alone is semantic segmentation.

MaskFormer (2021) and Mask2Former (2021) dropped both the per-pixel classifier and the boxes. A transformer decoder holds a fixed set of queries, 100 by default, as in DETR's object queries. Each query predicts a class (or "no object") and a mask. The mask comes from a dot product between the query's embedding and the embedding of every pixel:

\htmlData{step=1, link=mask}{\htmlClass{t-green}{m_i[h,w]}} = \mathrm{sigmoid}\big(\htmlData{step=2, link=query}{\htmlClass{t-green}{\mathcal{E}_{\text{mask}}[:,i]}}^{\mathsf T} \cdot \htmlData{step=3, link=pixel}{\htmlClass{t-blue}{\mathcal{E}_{\text{pixel}}[:,h,w]}}\big)

MaskFormer v2, Sec. 3.3 (unnumbered). Mask2Former v3 keeps this mask head.

  • \htmlClass{t-green}{m_i[h,w]}: how strongly pixel (h,w) belongs to mask i, between 0 and 1.
  • \htmlClass{t-green}{\mathcal{E}_{\text{mask}}[:,i]}: the embedding that query i ends with, a vector of 256 numbers.
  • \htmlClass{t-blue}{\mathcal{E}_{\text{pixel}}[:,h,w]}: the embedding of one pixel, the same length, from a pixel decoder that runs at a quarter of the image resolution.

Mask2Former's change is masked attention: each query looks only at the pixels inside the mask it predicted one layer earlier. In an ablation with a ResNet-50 backbone, removing it changes COCO instance AP by -5.9. With it, one architecture matched or beat the specialised models on all three tasks. The best results use a Swin-L backbone (with 200 queries on COCO): 57.8 PQ on COCO panoptic, 50.1 AP on COCO instances and 57.7 mIoU on ADE20K. Panoptic segmentation is the union of the two others: every pixel gets a class, and every countable object also gets its own mask.

A human in the loop

A second line of work never asked a model to know classes. In interactive segmentation, a person clicks on the thing they want, the model draws a mask, and the person clicks again where the mask is wrong.

Run the twelve clicks, then pick another object. Before you do, predict: will the first click or the tenth click change the mask more?

DIOS (Deep Interactive Object Selection, 2016) set the pattern. It turns the clicks into 2 extra image channels, one for positive and one for negative clicks, where each pixel holds its distance to the nearest click (truncated at 255). Stacked with the three colour channels, they go into a fully convolutional network, and the output is the mask. DIOS trained on simulated clicks: random positive clicks inside each object and negative clicks sampled by 3 different rules, in the background around it and on other objects.

RITM (2021) revived and refined two ideas from an earlier method, ITIS (2018), and SAM later reuses both. First, it feeds the previous mask back in as a third input channel, so each click edits the last answer instead of starting again; ITIS had proposed this as an option, and RITM made it work reliably. Second, it trains iteratively: during training it runs the model, finds the error region, places the next click there, and repeats, up to 3 times per example. It clicks inside an eroded error region, 4 times smaller in area, so the model does not overfit to the evaluation's exact rule. Trained on COCO and LVIS (104k images, 1.6M masks), RITM needed 5.34 clicks on average to reach 90% IoU on DAVIS.

SimpleClick (2022) swapped the convolutional backbone for a plain Vision Transformer pretrained with MAE, the same backbone SAM would use. The click maps and the previous mask enter through their own patch embedding. Its ViT-H model trained on COCO and LVIS needs 4.78 clicks on DAVIS. FocalClick (2022) made the loop cheaper by recomputing only the region around each new click.

How the field keeps score

The benchmarks simulate the user. The rule, in RITM's words: "the next click is placed at the center of the region with any type of prediction error (false positive or false negative) with the largest area", where the centre is the point farthest from that region's boundary. The simulated user in the figure follows the same rule. The score is the number of clicks needed to reach a target IoU:

\mathrm{NoC@90} = \min\{\, k : \htmlData{step=1, link=curve}{\htmlClass{t-green}{\mathrm{IoU}_k}} \ge \htmlData{step=2, link=threshold}{\htmlClass{t-yellow}{0.9}} \,\}, \quad \text{capped at } \htmlData{step=3, link=noc}{20}

Our notation for the metric defined in DIOS v1 (Sec. 4.1) and used by RITM and SimpleClick.

  • \htmlClass{t-green}{\mathrm{IoU}_k}: the overlap between the mask after k clicks and the true mask (intersection over union).
  • \htmlClass{t-yellow}{0.9}: the target overlap; NoC@85 uses 0.85.
  • If 90% is never reached, the count is the cap, 20 clicks.

Lower is better. DIOS needed 6.04 clicks on the GrabCut images; RITM, five years later and trained on far more data (COCO and LVIS instead of PASCAL), 1.56.

What was missing

Interactive segmentation had prompts (clicks), feedback (the previous mask) and a training loop that simulates a user. It had no notion of classes, so the window and the pencil are as easy as the mug. But each model was trained on a few datasets, accepted one kind of prompt, and assumed every click had one right answer. The next chapter shows what changes when one click may mean several objects, and when the training set has a billion masks.

Act IISegment Anything (2023)

Any prompt, a valid mask

The Segment Anything Model (SAM) knows no class names. It answers one request: given an image and a prompt that points at something, return a mask for it. Click on the desk scene and see what comes back.

Before you press One output, predict what it will show. A click on the logo of the mug could mean the logo, the mug, or the mug with its saucer. All three are correct answers. A model with one output slot is trained on all three, one example at a time. What single mask makes the smallest total error against three different right answers?

The answer is their average: a soft blob that is darkest on the logo and fades over the saucer. It matches no object. This is why SAM's task asks for a valid mask: "even when a prompt is ambiguous and could refer to multiple objects", the output "should be a reasonable mask for at least one of those objects" (SAM v1, Sec. 2).

The task is both the training signal and the interface

A prompt can be a set of foreground and background clicks, a box, a rough mask, or free text. The same request does two jobs. During training, the model gets a mask and a prompt sampled from it, and must return that mask. After training, other systems talk to SAM through the same request: a detector sends boxes, a person sends clicks, and, in a proof of concept with a modified training procedure, a text model sends words (the released SAM takes no text). SAM's authors call this zero-shot transfer through prompting, the way a language model is steered by its prompt.

Three answers, each with a score

SAM fixes the ambiguity with extra output slots. For a single prompt it predicts 3 masks at once, "since we observe that three layers (whole, part, and subpart) are often enough to describe nested masks". Each slot also gets a predicted score: an estimate of how well its mask overlaps the object it covers, its IoU (intersection over union: shared pixels divided by all pixels in either mask). Applications rank the three masks by this score.

The trick is in the loss. During training, the loss is computed between the true mask and each of the three outputs, but the model "only backpropagate[s] from the lowest loss". Press Train and change which mask the user meant: only the closest output gets a red outline, and only it is pushed toward the target. In our reading, over many ambiguous clicks each slot settles on one level of the nesting; the paper says only that SAM tends to return the subpart, part and whole object.

\htmlClass{t-red}{\mathcal{L}} = \htmlData{step=2, link=min}{\min_{k\in\{1,2,3\}}} \Big[\, \htmlData{step=1, link=masks}{20\,\mathrm{Focal}(\htmlClass{t-green}{M_k}, G) + \mathrm{Dice}(\htmlClass{t-green}{M_k}, G)} \,\Big] + \htmlData{step=3, link=iou}{1.0 \cdot \tfrac{1}{3}\textstyle\sum_{k} \big(\htmlClass{t-green}{\hat s_k} - \mathrm{IoU}(\htmlClass{t-green}{M_k}, G)\big)^2}

Our transcription of SAM v1, App. A ("Losses" and "Making the model ambiguity-aware"). The paper states this loss in words and prints no equation.

  • \htmlClass{t-green}{M_k}: the mask predicted by output slot k; G: the true mask.
  • \mathrm{Focal} and \mathrm{Dice}: two per-pixel mask losses, mixed 20:1. Focal loss is cross-entropy that turns down the weight of easy pixels; dice loss scores the overlap of the two masks as a whole.
  • \min_k: only the slot with the lowest mask loss sends gradient back.
  • \htmlClass{t-green}{\hat s_k}: the predicted score for slot k, trained with a mean-square-error loss against the real IoU, with weight 1.0. Whether this term covers all three slots or only the best one, the paper does not say; we write all three (our reading).

Hover a colored term to light it in the figure. Auxiliary losses after each decoder layer were tried and found unhelpful.

More prompts, less ambiguity

Press Two clicks and place a second click on the saucer. Now the only object that contains both clicks is the mug with its saucer. With several prompts, ambiguity is "much rarer", so SAM does not return three masks. A fourth output token predicts a single mask, which "is never returned for a single prompt and is the only mask returned for multiple prompts". This also keeps the training signal clean: the one unambiguous mask always gets a normal gradient.

All of this has to happen fast enough for a person clicking in a browser. The next chapter shows how the model is split to make that possible.

Heavy once, light many times

A person clicks, looks, and clicks again, so each answer must come back in a moment. SAM gets this by splitting the work: a large network reads the image once, and a small one answers each prompt.

SAM has three parts. The image encoder turns the image into a grid of feature vectors, the image embedding. The prompt encoder turns clicks, boxes and masks into vectors of the same width. The mask decoder mixes the two and draws the masks. Given the image embedding, the mask decoder needs less than 1% of the image encoder's compute (the prompt encoder is smaller still), and the two run in about 50ms in a web browser on a CPU. So the encoder may be as large as quality demands; it runs once per image, not once per prompt.

The image encoder

The encoder is a Vision Transformer (ViT): the image is cut into square patches, each patch becomes a vector, and transformer layers let every patch exchange information with the others. SAM uses the huge size with 16-pixel patches, ViT-H/16, at an input of 1024x1024. That gives a 64x64 grid of patch vectors. At that size, attention between all patch pairs in every layer is expensive, so most layers attend only inside 14x14 windows, and four evenly spaced blocks attend globally, a design taken from ViTDet. Two small convolutions (the neck) then shrink each vector to 256 channels.

The encoder starts from MAE weights. A masked autoencoder (MAE) is trained without labels: it hides most patches of an image and learns to paint them back, which teaches it general visual features (the JEPA explainer compares this with other ways to learn without labels). SAM then trains the whole encoder further on its own task.

The prompt encoder

Every sparse prompt becomes a token of 256 numbers. A click is a positional encoding of its location (a fixed set of sines and cosines at many frequencies, so nearby points get similar codes) plus one of two learned embeddings that say "include" or "exclude". A box is two tokens: one for its top-left corner and one for its bottom-right corner, each with its own learned embedding. In a proof-of-concept variant, text goes through CLIP's text encoder; the released SAM takes no text. A mask prompt is different: it is an image, so small convolutions (with 4 and 16 channels, then 256) shrink it to the 64x64 grid, and it is added to the image embedding pixel by pixel.

The mask decoder

The decoder starts from the prompt tokens plus a few learned output tokens, one per mask slot and one for the scores, like the class token of a ViT. It is a two-way transformer of 2 layers, each in 4 steps: the tokens attend to each other; the tokens attend to the image embedding; an MLP updates each token; and the image embedding attends back to the tokens. The last step is what makes it two-way: the image features also learn about the prompt. All attention layers use 8 heads.

The image embedding is then upsampled 4x with two transposed convolutions, the tokens attend to it once more, and each mask token passes through a 3-layer MLP to become a vector of 32 numbers. Each mask is the dot product of that vector with the upsampled embedding at every location, the same move as MaskFormer's mask head:

\htmlClass{t-green}{M_k}[h,w] = \htmlClass{t-green}{\mathrm{MLP}_k(t_k)}^{\mathsf T}\, \htmlClass{t-blue}{U[:,h,w]}

Our notation for SAM v1, App. A ("Lightweight mask decoder"): t_k is mask token k after the decoder, U the upsampled image embedding (32 channels at a quarter of the input resolution).

The score head reads the extra output token and predicts one IoU per mask. That gives the three ranked masks of the last chapter.

Inside SAM: forward, then backward

Step through one forward pass with the shapes computed from the paper's configuration. Before you open the backward stages, guess: which boxes will the gradient reach, and is anything frozen?

Every box is trainable, and the cost of that is in the encoder. The next question is where the training masks came from.

One training step: eleven rounds

Not narrated. SAM is not trained on single prompts. For every mask it plays a short game of interactive segmentation against itself, and the loss is counted in every round. Step through one game.

  1. The first prompt. For each target mask, SAM picks a foreground point or a box with equal probability. Points are sampled uniformly from the ground truth mask. A box is the mask's bounding box with noise on each corner: a standard deviation of 10% of the side, up to 20 pixels.
  2. Round 1 returns three masks. One prompt may be ambiguous, so the decoder gives three. The mask loss is computed for each, and only the lowest-loss mask sends a gradient back (the loss is in chapter 3). The IoU head learns to predict mask quality; whether its loss covers all three masks, SAM's paper does not say.
  3. The next point comes from the mistakes. Each later point is selected uniformly from the error region between the last prediction and the ground truth. A point where the mask is missing becomes an include point; a point where it spills over becomes an exclude point.
  4. The last answer is fed back. The previous prediction enters as a mask prompt, as unthresholded mask logits rather than a yes/no mask, so the model sees how sure it was. When round 1 gave three masks, the one passed on is the one with the highest predicted IoU. With more than one prompt, the decoder returns a single mask from its fourth output token (our reading: from round 2 on).
  5. Two rounds without a new point. After 8 sampled points the gains fade (the authors tested up to 16). Two more rounds give no new point, so the model learns to clean up its own mask: one is placed at random among the sampled points and one is always at the end. That makes 11 rounds.
  6. Why eleven rounds are cheap. The image encoder runs once per image. The decoder that runs eleven times needs less than 1% of the encoder's compute. Earlier interactive methods ran only one or a few rounds per optimizer step.
  7. The optimizer step. AdamW, a learning rate of 8e-4 after a linear warmup of 250 iterations, divided by 10 at 60k and at 86666 iterations, for 90k iterations: about 2 passes over SA-1B. A batch holds 256 images, with at most 64 masks sampled per GPU. The ViT-H model trained on 256 A100 GPUs for 68 hours.

What SAM 2 changes in this game (App. D.2.1): 7 correction clicks instead of 8; for the two rounds without a new point, "we do not add such iterations"; and an l1 loss on the IoU predictions of all three masks on the first click (in the SA-1B pre-training stage), while the mask loss still goes only to the lowest-loss mask.

The data engine and SA-1B

A promptable model for "anything" needs masks of almost everything, and no such dataset existed. The SAM team built one with the model itself in the loop, until the model could label images on its own. Here is the last, fully automatic step on the desk scene.

Before you step through, guess: of all the candidate masks on the grid, what share survives? Most candidates are duplicates. Neighbouring points on the same mug return the same mug, so in this toy, box non-maximum suppression (NMS) removes far more than any quality filter.

Three stages, one model getting better

Assisted-manual. Professional annotators clicked include and exclude points in a browser tool, and SAM drew the mask in real time. They labelled anything they could name or describe, and moved on when a mask took more than 30 seconds. The model was retrained 6 times on the new masks, and its image encoder grew from ViT-B to ViT-H. Time per mask fell from 34 to 14 seconds, and masks per image rose from 20 to 44. This stage gave 4.3M masks on 120k images.

Semi-automatic. To add the less obvious objects, a box detector trained on the stage-1 masks (one generic "object" class) pre-filled the confident objects, and annotators labelled what was left. This gave 5.9M more masks on 180k images, with 5 more retrains. The remaining objects were harder: time per mask went back to 34 seconds. Masks per image reached 72.

Fully automatic. Now SAM labelled alone. It prompted each image with a 32x32 grid of points plus 20 zoomed-in crops for small objects, kept a mask only if its predicted IoU was at least 88.0 and it was stable, removed masks covering 95% or more of the image, and removed duplicates with box NMS at 0.7. A mask is stable when thresholding its logits at -1 and at +1 gives nearly the same mask: their IoU must be at least 95.0. A last clean-up removed stray parts and filled holes under 100 pixels. This ran on 11M images and produced 1.1B masks.

One detail is easy to miss: the masks of SA-1B were not made by the SAM you can download. They came from a special version trained only on the stage 1 and 2 masks, with 3 decoder layers instead of 2 and 4 sampled points per mask instead of 9. The released SAM was then trained on SA-1B alone.

Claim card: are automatic masks good enough to train on?

Claim
The fully automatic masks are close to what professional annotators would draw.
How measured
The authors sampled 500 images (about 50k masks) and asked annotators to correct each automatic mask with the brush tool. They then compared each mask with its corrected version by IoU.
Result
94% of pairs had an IoU above 90%, and 97% above 75%. Earlier work found that two annotators agree at 85-91% IoU.
What would falsify it
Corrections that change many masks a lot, or a model trained on the automatic masks doing clearly worse than one trained on the manual ones. In the ablation of Sec. 7.6, training on the automatic masks alone scored only 0.5 mIoU below training on all the data.

The data engine made about 1.1B masks, 99.1% of them automatically, and SA-1B releases only the automatic ones: 11M licensed images, about 100 per image. That is 400x more masks than Open Images, the largest dataset before it. The masks carry no class names. SA-1B teaches where things are, not what they are called.

What prompting buys

SAM was never trained on the datasets in this chapter. The authors gave it one click per object on datasets it had not seen and compared it with RITM, the strongest interactive model at one click.

Before you press Best of three masks, guess: on the datasets where SAM loses, is the right answer missing, or is SAM picking the wrong one of its three answers? The rings answer it. On every dataset, one of the three masks beats RITM. So most of SAM's losses are ranking errors on ambiguous clicks, not missing answers. For example (our reading, not the paper's), a click on a hand in an egocentric video (GTEA) could mean the hand, the arm, or the person.

Composing SAM with other parts

A promptable model is a part, not a finished system. The authors wired SAM into four other tasks with no further training, by choosing the prompts:

  • Edges. Prompt a 16x16 grid of points, take the boundaries of all masks, and thin them. On BSDS500, SAM reaches ODS .768. That beats the classic zero-shot method Canny (.600) and comes close to HED (.788), which was trained on BSDS500. It is below the newest trained model, EDETR (.840).
  • Object proposals. Prompt a 64x64 grid and keep up to 1000 masks. On LVIS v1, mask recall AR@1000 is 59.3 against 63.0 for ViTDet-H, a detector trained on LVIS. SAM is ahead on rare categories (65.8 vs 58.3).
  • Instance segmentation. Prompt SAM with ViTDet-H's boxes. Mask AP is lower than ViTDet-H's own masks: 46.5 vs 51.0 on COCO, 44.7 vs 46.6 on LVIS v1. Yet when both models were given ground-truth LVIS boxes, people rated SAM's masks higher (8.1 vs 7.9). The authors' reading: ViTDet learned the drawing habits of COCO's annotators, and AP rewards that.
  • Text to mask. Train SAM to take a CLIP image embedding of the masked object as its prompt; at test time, give it the CLIP text embedding instead, because CLIP puts both in one space. The paper calls this "exploratory and not entirely robust". SAM 3 makes text a first-class prompt (chapter 9).

Two LVIS versions appear in this chapter. The 23-dataset suite uses LVIS v0.5; proposals and instance segmentation use LVIS v1. Their numbers are not comparable.

What the authors say it cannot do

The limitations section (SAM v1, Sec. 8) is short and specific. SAM can "miss fine structures", it "hallucinates small disconnected components" at times, and it "does not produce boundaries as crisply" as slower methods that zoom in. Prompts run in real time, but the whole model is "not real-time when using a heavy image encoder". And it is "unclear how to design simple prompts that implement semantic and panoptic segmentation": SAM finds things, but it does not name them. Each of these became a later paper: HQ-SAM for boundaries, the efficient encoders for speed (chapter 11), SAM 3 for names (chapter 9). The next gap the authors left was time.

Act IIITime, concepts, depth

SAM 2: video is images with memory

SAM 2 treats an image as a video with one frame. It reads a video frame by frame, and before it draws a mask on a frame it looks back at what it remembers about the object.

Press Play and stop on a frame where the mug is completely behind the box. Guess first: what should a segmentation model draw? A model that must always output a mask would draw something wrong. SAM 2 has an extra output, the occlusion head, that predicts whether the object is visible on this frame at all. When it says no, the frame gets no mask, and the model keeps tracking from memory.

Memory for video segmentation is older than SAM 2. STM (2019) treated past frames and their masks as an external memory: every pixel of the new frame attends to every pixel of every stored frame, and it stored a new memory frame every 5 frames. The memory grows with the video, so such models struggle on long clips. XMem (2022) split memory into 3 stores, after a model of human memory: a sensory memory updated every frame, a high-resolution working memory of recent frames, and a compact long-term memory of prototypes. With a 6 GB memory budget it could process up to 34,000 frames. Cutie (2023) added object-level memory on top. All three start from a full mask on the first frame. SAM 2's change is to make the memory promptable: any click on any frame becomes a memory.

The task is called promptable visual segmentation. You may click, draw a box or give a mask on any frame. The model answers at once on that frame, then spreads the answer over the whole video as a masklet, one mask per frame. A later click on any frame refines the masklet. Image segmentation is the special case of a video with one frame.

Four parts make this work:

  • A streaming image encoder. A Hiera encoder (a hierarchical vision transformer pretrained with MAE) runs once per frame, as the frames arrive. Its stride-16 and stride-32 features are fused into a 256x64x64 frame embedding.
  • Memory attention. L = 4 transformer blocks condition the frame embedding on the memory bank: self-attention over the frame, cross-attention to the memories, then an MLP.
  • A memory bank. It holds up to 6 memories of recent frames, each tagged with how many frames ago it was made, and the memories of frames you prompted, which carry no such tag. A memory is the predicted mask, downsampled and added to that frame's embedding, compressed to 64 channels.
  • Object pointers. The decoder's mask token for the chosen mask is a 256-number summary of the object. It is split into 4 tokens of 64 numbers and stored next to the spatial memories.

The read itself is ordinary cross-attention. The paper prints no equation for it; in standard notation (our transcription):

\htmlData{step=1, link=frame}{\htmlClass{t-blue}{X'}} = \mathrm{softmax}\!\Big(\frac{\htmlData{step=2, link=frame}{\htmlClass{t-blue}{Q_{\text{frame}}}}\,\htmlData{step=3, link=memory}{\htmlClass{t-blue}{K_{\text{mem}}}}^{\mathsf T}}{\sqrt{d}}\Big)\,\htmlData{step=4, link=memory}{\htmlClass{t-blue}{V_{\text{mem}}}}

Standard scaled dot-product cross-attention (our notation). SAM 2 v2, Sec. 4 describes it in words: self-attention, then cross-attention to the memories and object pointers, then an MLP, repeated in each of the 4 blocks.

  • \htmlClass{t-blue}{Q_{\text{frame}}}: one query per position of the current frame's 64x64 feature map.
  • \htmlClass{t-blue}{K_{\text{mem}}, V_{\text{mem}}}: keys and values from every position of every stored memory, plus the object pointer tokens.
  • \htmlClass{t-blue}{X'}: the frame's features, now "knowing" where the object was. The SAM decoder then turns them into a mask exactly as in chapter 4.

Two details carry a lot. First, a frame's memory is made after its mask is drawn, so mistakes can enter the bank; that is why a correction click is stored as a memory in a separate queue of prompted frames, apart from the 6 recent ones, so it is not pushed out as the video moves on (the queue size is not stated). Second, the decoder still produces several masks for an ambiguous click, but in a video only the one with the highest predicted IoU is carried forward unless a later prompt settles it.

An image is a video with an empty memory

With nothing in the bank, memory attention has nothing to read, and SAM 2 is a SAM. Trained only on SA-1B, the Hiera-B+ model scores 58.9 mIoU at one click on the 23-dataset suite of chapter 7, against 58.1 for SAM's ViT-H. It runs at 130.1 frames per second against 21.7, about 6x faster. That speed-up is for images. On video, with memory, the paper reports 43.8 frames per second for Hiera-B+ and 30.2 for Hiera-L on one A100.

  • Fewer clicks. Started with one click on the first frame and evaluated on 17 video datasets, SAM 2 reaches an average accuracy of 64.7 against 56.7 for SAM followed by the Cutie tracker. The model "may fail to segment objects across shot changes and can lose track of or confuse objects in crowded scenes, after long occlusions or in extended videos". It "struggles with accurately tracking objects with very thin or fine details especially when they are fast-moving", and it confuses "nearby objects with similar appearance". Each object is tracked separately, "without inter-object communication". Chapter 12 shows the follow-ups that attack long videos and look-alikes.

SAM 3: every object of this kind

SAM and SAM 2 answer "which pixels belong to this object?" for one prompt at a time. SAM 3 (first posted 2025-11-20) answers "where is every object of this kind?" from a short phrase such as "leaf", from example boxes, or from both, and returns a mask for each instance.

Before you press "yellow mug", guess. The mug in the scene is grey. A detector that judges each region on its own sees something that looks very much like a mug. What stops it from answering "here is your yellow mug"?

The paper calls the task promptable concept segmentation (PCS). A concept is a short noun phrase, a set of exemplar boxes (each marked positive or negative), or both. The output is every matching instance, and in a video each instance keeps one identity across frames for clips of up to 30 secs.

A detector with a presence token

The detector is built like DETR. A fixed set of learned queries passes through a transformer decoder; each query ends as one proposed object with a box, a mask and a score. SAM 3 adds one more token to the decoder, the presence token. It does not look for any instance. It answers one question for the whole image: is this phrase here at all? The authors split the decision in two because "is it here" needs the whole image, while "is this region an instance" is local, and asking each query to do both "can conflict with the localization objectives that are by nature very local" (App. C.2).

\htmlData{step=1, link=total}{\htmlClass{t-green}{p(\text{query}_i \text{ matches NP})}} = \htmlData{step=2, link=query}{p(\text{query}_i \text{ matches NP}\mid \text{NP appears in image})} \cdot \htmlData{step=3, link=presence}{\htmlClass{t-blue}{p(\text{NP appears in image})}}

SAM 3 v2, App. C.2, "Presence Head" (unnumbered display).

  • \htmlClass{t-green}{p(\text{query}_i \text{ matches NP})}: the total score of query i. A mask is kept when it is above 0.5.
  • The first factor is the query's own score: how well its region matches the noun phrase (NP), if the phrase is in the image. It only has to localise.
  • \htmlClass{t-blue}{p(\text{NP appears in image})}: the presence score, one number from the presence token, shared by every query.

The training rule follows from the split. The presence head is trained with a binary cross-entropy loss on every image (weight 20). The query scores are trained only when the phrase is present. When it is absent, no query score gets a gradient, so only the presence head learns what absence looks like. Supervising the query scores only when the phrase is present gave 54.0 on the paper's main benchmark (cgF1, defined below), against 52.2 for the usual DETR rule of supervising them always. These are ablation runs (a smaller, shorter-trained model on an internal version of the benchmark); the best row, 54.9, also supervises the total score (Table 10).

What the presence token and hard negatives buy, honestly

A hard negative is a phrase that is not in the image but names something that looks similar: "yellow mug" for a grey mug. The data engine adds them on purpose. Set the figure to "yellow mug" and switch hard negatives off and on. In the toy, only the presence score moves; the query for the mug still looks like a mug either way (our reading of the mechanism). The paper's ablation measures whole models, not the presence score alone, but its numbers fit that picture. As hard negatives go from none to 30 per image, image-level accuracy (IL_MCC, defined below) rises from 0.44 to 0.68, while mask quality (pmF1) stays flat at 62.4 and 62.8 (Table 9b).

The presence head is not free. Adding it raised IL_MCC from 0.77 to 0.82, but lowered pmF1 from 65.4 to 63.4. The combined score still rose by +1.5 (Table 9a, shorter training runs). SAM 3 also does not beat SAM 2 on everything. On the interactive point benchmark (SA-37) with one click it scores 66.1 mIoU against 66.4 for SAM 2.1 L, and it runs at 43.5 frames per second against 93.0 (Table 7).

Exemplars, and ambiguity again

Words are not always enough. An exemplar is a box drawn on one instance, marked positive ("more like this") or negative ("not this"). Each exemplar becomes a prompt token from its position, its label and the image features inside the box. In the figure, one positive box on a small leaf brings in the two sideways leaves that the word alone missed, and one negative box removes the window frame from "window pane". With one exemplar and no text, SAM 3 beat the earlier exemplar model T-Rex2 by +18.3 AP+ on COCO, a metric scored on positive examples only: 76.8 against 58.5 (Table 3).

SAM 1 met ambiguity with three masks per click (chapter 3). SAM 3 meets it at the level of concepts. "Window" may mean the whole window or each pane. An ambiguity head holds 2 experts trained winner-takes-all, the same rule as SAM's three masks: only the expert with the lowest loss gets a gradient, so each learns one reading. It is trained on top of a frozen SAM 3 and cut overlapping instances by 15% (App. C.2).

Inside SAM 3: forward, then backward

SAM 3 has about 850M parameters (the README says 848M). Most of them sit in one backbone, the Perception Encoder (PE), whose image and text encoders were first trained together contrastively on 5.4 billion image-text pairs (stage 1). The detector and the video tracker share that backbone. Step through the detector's training stages 2 and 3; stage 4, the tracker, is the second figure.

Detect, then match, in video

In a video, SAM 3 runs the detector on every frame and the tracker on every known object, then reconciles the two:

\hat{\mathcal{M}}_{t} = \mathrm{propagate}(\mathcal{M}_{t-1}), \quad \mathcal{O}_{t} = \mathrm{detect}(I_{t}, P), \quad \mathcal{M}_{t} = \mathrm{match\_and\_update}(\hat{\mathcal{M}}_{t}, \mathcal{O}_{t})

SAM 3 v2, Sec. 3 (unnumbered). \mathcal{M}: the tracked objects ("masklets"); \mathcal{O}_t: the detections on frame t; P: the prompt.

A detection that overlaps no tracked object starts a new one. A few simple rules keep the identities clean (App. C.3):

  1. Wait before you trust. A new object is confirmed only after 15 more frames. If it matched detections in fewer frames than it missed them, it is removed.
  2. Remove duplicates. Two tracks that both overlap the same detection (IoU above 0.1) for half of that window are one object; the younger track goes.
  3. Re-anchor on good detections. Every 16 frames, if a detection matches a track with IoU and both scores at least 0.8, the track restarts from the detection's mask.

Claim card: the SA-Co data engine and the cgF1 metric

Claim
Language models used as "AI verifiers", plus adversarial hard negatives, let a data engine label concepts exhaustively at a scale people alone could not reach.
How
Four phases. Phase 1: a captioner and a parser propose phrases, SAM 2 prompted by an open-vocabulary detector proposes masks, and people verify them (4.3M image-phrase pairs). Phase 2: Llama models fine-tuned on those decisions take over two checks, "is this mask right?" and "are all instances found?"; SAM 3 is retrained 6 times (122.2M pairs). Phase 3: more domains (the high-quality set spans 15) and long-tail phrases mined from a Wikidata-based ontology of 22.4M nodes (17 top-level categories, 72 sub-categories). Phase 4: video.
Result
The AI verifiers match people: 77.7 against 75 on mask checks and 81.1 against 81.8 on exhaustivity (Table 23). A negative phrase took 71 seconds for a person and 6 with the full engine. The high-quality set, verified by people and AI verifiers, has 4M unique phrases on 5.2M images with 52M masks; 88.5% of its image-phrase pairs are negatives. The synthetic set adds 1.4B masks with no people involved.
Falsified if
Models trained on verifier-labelled data scored no better than on human-only data, or the verifiers disagreed with people far more than people disagree with each other.

A benchmark with 207K unique phrases (the README says 270K), most of them on images where the phrase is absent, breaks the usual detection metric, average precision. Its average over tens of thousands of rare classes is mostly noise, and it ignores whether the scores are calibrated. The paper's metric multiplies two parts:

\mathrm{cgF}_1 = 100 \cdot \mathrm{pmF}_1 \cdot \mathrm{IL\_MCC}

SAM 3 v2, App. E.3, Eq. 3.

  • \mathrm{pmF}_1: mask quality on images where the phrase is present: F1 over matched instances, averaged over IoU thresholds from 0.5 to 0.95 (Eq. 1).
  • \mathrm{IL\_MCC}: image-level correctness, a Matthews correlation between "the phrase is here" and "the model predicted something" (Eq. 2). It ignores mask quality.

On the benchmark's Gold split, SAM 3 scores 54.1 cgF1, more than double the strongest baseline (OWLv2* at 24.6), and 74% of the human score of 72.8 (Table 1). The paper gives four human numbers for this split: 72.8 in Table 1, 76.2 for the oracle protocol on a three-reviewer subset (Table 29; SAM 3's Gold score also uses the oracle protocol, so this is the like-for-like number), 55.5 on the same subset when one reviewer is scored against one other at random, and 70.8 on the internal version used for ablations. On LVIS, a standard benchmark with a long tail of rare classes, SAM 3 reaches 48.5 zero-shot mask AP in Table 1, against 38.5 for the best earlier zero-shot model (DINO-X, as reported in its own paper; models trained on LVIS score higher); the introduction states 48.8, and the paper does not explain the difference.

Object Multiplex (version 2 appendix)

The paper's video pipeline processes each object separately, so video cost grows with the number of objects. The version 2 appendix (we read only version 2; the README dates the SAM 3.1 Object Multiplex release 2026-03-27) packs objects into buckets of 16 slots that share one memory, with a per-object embedding to keep identities apart. At 128 objects it is 5.2x faster on one H100; with a single object it costs about 7% more time. Both figures use the authors' optimised internal implementation (App. H).

The limits matter for inspection. The paper says SAM 3 "struggles to generalize to fine-grained out-of-domain concepts (e.g., aircraft types, medical terms) in a zero-shot manner, especially in niche visual domains (e.g., thermal imagery)", and that it accepts only simple noun phrases (App. B). Its remedy is a few labelled examples. On RF-100VL, a benchmark of 100 datasets from varied real-world domains, zero-shot SAM 3 scores 15.2 box AP, slightly below Grounding DINO-T at 15.7. Fine-tuned on the official 10-shot splits (ten labelled examples per class, per dataset), it reaches 36.5 (Table 2). Chapter 14 returns to this.

SAM 3D: from a mask to an object

A mask tells you which pixels belong to an object. SAM 3D (submitted 2025-11-20, revised 2026-06-02) takes one image and one such mask and generates the whole object in 3D: its shape, including the hidden back, its texture, and where it sits in the scene.

SAM 3D is not part of SAM. It does not make masks; it assumes one, and its authors point to the SAM series as a fast way to get it. It belongs on this page for a different reason: it copies SAM's recipe for a field that had no data.

The model. A DINOv2 encoder turns the object crop, its mask, the full image and the full mask into 4 sets of conditioning tokens. A 1.2B-parameter geometry model, a flow-matching transformer, generates the coarse shape as 4096 latent tokens (a 64^3 voxel grid) and the layout as 1 more token: a rotation in 6D form, a translation and a scale per axis. A 600M-parameter model then refines the shape and adds texture, and decoders output a mesh or Gaussian splats. Predict before you switch tabs: which of the three outputs (shape, rotation, placement) is hardest to learn from one photo?

The geometry model learns all its outputs with one flow-matching loss: start from noise, and learn the velocity that moves it in a straight line to the true shape and layout.

\mathcal{L}_{\text{CFM}} = \htmlData{step=1, link=shape}{\sum_{m \in \mathcal{M}} \lambda_m} \, \mathbb{E}_{\tau, \mathbf{x}_0^m}\Big[ \big\| \htmlData{step=2, link=layout}{\mathbf{v}^m} - \htmlData{step=3, link=mask}{\mathbf{v}_\theta^m(\mathbf{x}_\tau^m, \htmlClass{t-green}{c}, \tau)} \big\|^2 \Big]

SAM 3D v2, Eq. 1 (App. C.2), with \mathbf{x}_\tau^m = \tau\mathbf{x}_1^m + (1-\tau)\mathbf{x}_0^m and \mathbf{v}^m = \mathbf{x}_1^m - \mathbf{x}_0^m.

  • m \in \mathcal{M}: the outputs, shape, rotation, translation and scale, each with a weight \lambda_m (rotation and scale get 0.1).
  • \mathbf{x}_0^m: noise; \mathbf{x}_1^m: the true value; \mathbf{x}_\tau^m: a point on the straight line between them at time \tau.
  • \mathbf{v}^m: the velocity along that line, the target; \mathbf{v}_\theta^m: the network's guess, conditioned on \htmlClass{t-green}{c}, the image and the mask.

If flow matching is new to you, the diffusion explainer's rectified-flow chapter builds it from scratch.

The data engine, again

Nobody has millions of photos paired with true 3D models, and most people cannot build a 3D mesh. They can, however, pick the best of several candidates. SAM 3D's engine asks for exactly that. Annotators choose target objects (10 seconds per object, with SAM helping to segment), pick the best of several candidate shapes (N=8 in the method section, 6 to 10 in the annotation statistics; 80 seconds), and align the winner to a point cloud of the scene (150 seconds). Professional artists model the hardest failures. The losing candidates become negative examples for preference training.

As in SAM's engine, the model takes over the work: the best SAM 3D model eventually produced about 80% of the annotated data. The engine annotated almost 1 million images with 3.14 million untextured meshes and collected 7 million pairwise preferences.

The training follows a language-model recipe: pretraining on 2.7 million rendered synthetic meshes, mid-training on 61 million semi-synthetic samples (rendered objects pasted or swapped into real images, plus synthetic indoor scenes), then supervised fine-tuning and preference optimisation (DPO) on the engine's real data. Each step helps, measured as shape F1 on the new SA-3DAO benchmark of 1,000 artist-made meshes paired with natural images:

Limits (App. F): the 64^3 grid distorts thin structures; objects are predicted one at a time, with no reasoning about contact or stability; and texture is predicted without knowing the pose, so symmetric objects can get a rotated texture. Mask errors from the segmenter carry through, though the paper reports fair robustness to over- and under-segmentation.

Act IVThe family

SAM on a budget

SAM's split into a heavy encoder and a light decoder has a direct consequence: to make SAM fast, you only have to replace the encoder. Guess first: how much of the time per image is the encoder?

MobileSAM (June 2023) measured SAM's ViT-H encoder at ~452ms per image on one GPU, against 4ms for the mask decoder. Its fix is decoupled distillation: train a small encoder, TinyViT with 5.78M parameters against ViT-H's 632M (as MobileSAM counts the encoder; SAM's own Fig. 13 gives 636M for its ViT-H model), to reproduce ViT-H's image embedding with a plain MSE loss. No prompts and no masks are needed for this step, so it ran on a single GPU in less than one day, on 1% of SA-1B. SAM's own decoder then works with the new encoder unchanged. The new encoder takes ~8ms. One caution: MobileSAM scores itself by agreement with SAM's masks (mIoU 0.7447), not against human labels.

EfficientSAM (December 2023) pretrains the small encoder first: it hides 75% of the image patches and learns to reconstruct SAM's features for them (SAMI, a masked-image pretraining as in MAE), then fine-tunes on SA-1B. On COCO, with boxes from a ViTDet detector as prompts, EfficientSAM-S reaches 44.4 AP against SAM's 46.5 and MobileSAM's 38.7, in EfficientSAM's own measurement.

EfficientViT-SAM (February 2024) redesigns the encoder and measures everything on one setup: single NVIDIA A100 GPU with TensorRT, fp16. SAM-ViT-H runs 11 images per second; EfficientViT-SAM-L2 runs 538 at a COCO mAP of 46.6 against SAM's 46.5. The paper calls this a 48.9x speedup without accuracy loss. That holds on COCO; on LVIS, L2 scores 42.7 against SAM's 44.2.

For video the move is not enough. EdgeTAM (January 2025) found that a small image encoder alone does not make SAM 2 fast, because memory attention dominates the time, so it shrinks memory attention for phones: 15.7 frames per second on an iPhone 15 Pro Max against 0.7 for SAM 2-B+ and SAM 2.1-B+, at a cost in accuracy (SA-V val J&F 72.3 against 73.6 for SAM 2-B+ and 76.8 for SAM 2.1-B+). EfficientSAM3 (November 2025) proposes to distil SAM 3 into nine small students, in stages that train on SA-1B, SA-V and SAM 3's data, but its first version has no results yet. MobileSAMv2 speeds up a different part: SAM's automatic "segment everything" mode, where most time goes to decoding a grid of points. A small detector proposes boxes instead, which cuts prompt sampling plus decoding from 6464ms to 97ms; decoding alone goes from 6400ms to 50ms.

Going the other way: HQ-SAM

SAM's masks miss thin structures and fine boundaries; its own paper says so. HQ-SAM (June 2023) keeps SAM frozen and adds a single learned output token plus a fusion of early and late encoder features, about 5.1M trainable parameters on top of SAM's ViT-L model, trained in 4 hours on 8 RTX 3090 on 44K fine-grained masks. On the DIS benchmark of detailed objects, the boundary metric mBIoU goes from 52.8 to 70.4, at 4.8 against 5.0 frames per second (ViT-L). For inspection, where defects are often thin, this is the variant to know (our reading).

Compose, adapt, track

SAM answers one narrow question, "which pixels go with this prompt?", and that makes it easy to plug into other systems. Most of its descendants either feed it better prompts, teach it a new domain, or carry its masks through time.

Look at the green line first: SAM, SAM 2 and SAM 3, each built on its predecessor, and SAM 3D, which takes a mask from any SAM model as its input (it appeared the same day as SAM 3 and builds on a separate 3D generator). Then switch to "After SAM" and predict which lane fills fastest.

Compose: give SAM a better prompt

SAM knows no words. Grounded SAM adds them by chaining two models: Grounding DINO, an open-vocabulary detector, turns a text phrase into boxes (its large Swin-L model reaches 52.5 AP on COCO without COCO training; the chain below uses the base model), and SAM turns each box into a mask. On the 25 datasets of the Segmentation in the Wild benchmark, the chain scores 48.7 mean AP zero-shot, and 49.6 with HQ-SAM. The paper is dated 2024-01-25, but its code came out in 2023: MobileSAM already cites it by July 2023. SEEM (April 2023) went the other way: one model trained on far less data, 0.12M images against SAM's 11M, that accepts clicks, boxes, scribbles, text and reference images. SAM 3 later absorbed the text half of this idea into one model.

Adapt: teach SAM a new domain

SAM's training images are mostly photographs, so it is weakest where pictures look different. MedSAM fine-tuned SAM on 1,570,263 medical image-mask pairs from 10 imaging modalities, with box prompts; on an external nasopharynx-cancer task its median Dice score is 87.8%. SAM-Adapter keeps SAM's image encoder frozen, inserts small trainable adapters into it, and fine-tunes the mask decoder; on camouflaged objects (COD10K) the structure score S-alpha rises from 0.783 to 0.883. The paper does not say how its SAM baseline was prompted; SAM-Adapter itself uses no prompts. The map chapter shows how much of the field this is: medical imaging alone is the largest named topic.

Track: carry masks through time

Before SAM 2, Track Anything (April 2023) joined SAM to XMem: SAM makes the first mask from a click, XMem propagates it, and SAM refines it when the track drifts. It reached 73.1 J&F on DAVIS-2017 test-dev from clicks alone. SAM 2 made this one model. Its descendants then patch its weak spots: SAM2Long keeps several memory pathways and picks the best, adding up to 5.3 J&F on SA-V test without retraining (on SAM 2-L; 1.6 on SAM 2.1-L), and SAMURAI adds a motion model for visual tracking, raising LaSOT AUC from 68.54 to 74.23.

The explosion

SAM was released with its weights and its dataset, and other researchers built on it at once. A dated search of arXiv shows how fast, and in which directions.

Before you look at the curve, guess: did the field peak in the year SAM appeared, or later? The two queries return 1,447 unique papers. 4 of them have a first version older than SAM: three are earlier papers whose later revisions mention SAM, and one matches only because arXiv search treats "segmenting anything" as the same phrase. We drop them, so the chart starts in April 2023 with 1,443 papers. In SAM's own month there were already 41.

The count did not peak in 2023. The year totals are 302 for April to December 2023, 490 for 2024, 426 for 2025, and 225 for 2026 up to the query date. By topic, the largest identifiable group is medical imaging, with 387 titles: organs, tumours, polyps, cells. Act VInspection

Where SAM helps inspection, and where it fails

A defect is often not an object. A scratch has no closed outline, and a stain has almost no edge, while SAM was trained on a billion masks of things. Step through three ways to use it on a toy machined part.

Before you click the second tab, guess: will a box around the scratch fix it? The papers that tested SAM on defects agree on a pattern, and the toy follows it.

Where it fails

Claim
Zero-shot SAM is weakest on concealed, low-contrast and thin targets, and industrial defects are the hardest case.
How measured
"Segment Anything Is Not Always Perfect" ran SAM on CDS2K, an industrial defect set of 2,492 images, and kept SAM's best mask by comparing each candidate with the ground truth: an upper bound on SAM. Metric: mean absolute error (MAE), lower is better.
Result
MAE 0.265 for SAM ViT-H against 0.089 for the best dedicated model (DGNet). Larger encoders help less and less: ViT-B 0.372, ViT-L 0.281.
Would falsify it
SAM matching the dedicated model on CDS2K even with oracle mask selection.

Finding a defect and outlining it are different. On infrared thermography of carbon-fibre parts, zero-shot SAM found the defects on flat parts (a recall-weighted F-score of 98.24) but its masks overlapped the true extent poorly: IoU 49.32. Fine-tuned on the task (DefectSAM), IoU rose to 78.58. On irregular parts zero-shot SAM also missed defects (F-score 68.02).

Zero-shot anomaly segmentation without any training images is possible but weak. Segment Any Anomaly chains Grounding DINO boxes from text such as "scratch" with SAM masks, then filters them with hand-written rules about location and size. Its best version scores a pixel max-F1 of 34.85 overall and 28.82 on objects. Much of the gain comes from the rule filters: without the property prompts, texture categories drop from 53.79 to 21.83.

Where it helps

How measured
Boxes2Pixels turns detection boxes into SAM masks, trains a small student on them with a separate defect-vs-background head and a one-sided self-correction step, and tests on a manually masked set. Baselines train on the same SAM masks.
Result
Defect mIoU 0.6523 against 0.5881 for SegFormer-B2. Self-correction raises binary recall from 0.6195 to 0.8051. The student has 5.6M trainable parameters and runs in 6.20 ms on an H100; SAM is not needed at run time.
Would falsify it
The baselines matching the student when trained on the same pseudo-masks, or the gain vanishing on the manual test set.

As a labelling tool, SAM saves clicks. In a case study on aircraft borescope images, the example image for each of five defect classes needed 1-3 clicks for a pixel-accurate mask. That paper says SAM drastically reduces labelling time but does not measure it, and no paper here does, so treat speed-up claims with care. On edge hardware, a distilled SAM encoder can carry an OK/NG classifier: KairosAD, built on MobileSAM's encoder, reaches an image AUROC of 99.10 on MVTec AD at 211 ms per image on a Jetson NX, but only 92.3 on VisA, and it needs labelled defect images and gives no masks.

A recipe for an inspection platform (our reading)

  • Label with it, do not detect with it. Use SAM, or HQ-SAM for thin defects, inside the labelling tool with positive and negative clicks. Check diffuse defects such as dirt and stains by eye.
  • Prompt with boxes. If a detector or past labels already give boxes, prompt SAM with them; a box removes most of the "which object" ambiguity.
  • Distil for production. Train a small segmenter on SAM's masks with a noise-tolerant loss, keep a small hand-masked test set, and deploy the student, not SAM.
  • Fine-tune when you have labels. For a new imaging modality, fine-tune the decoder or add adapters; zero-shot SAM's extents are not ground truth.
  • Use SAM 3 for "every scratch". Concept prompts with exemplar boxes ask for all instances of a defect type; the chapter on SAM 3 shows how its presence score decides whether the concept is there at all.

Summary

Segmentation models used to learn a fixed list of classes from one labelled dataset. Interactive segmentation showed another way: let a person point, feed the last mask back, and train on simulated clicks. SAM made that the whole task, "a valid mask for any prompt", returned three masks for an ambiguous click, split the cost into a heavy encoder that runs once and a light decoder that runs per click, and grew its own training set with a data engine that ended fully automatic. SAM 2 added a memory so one click follows an object through a video. SAM 3 changed the prompt from "this object" to "this kind of object" and separated "is it here?" from "where is each one?". SAM 3D turned a mask into a 3D object with the same data-engine recipe. Around this line grew faster encoders, sharper masks, domain adaptations and pipelines. For inspection, our reading of the papers is that SAM is a useful labelling tool and a source of pseudo-labels, and a weak zero-shot defect detector.
