SAM 2: video is images with memory

SAM 2 treats an image as a video with one frame. It reads a video frame by frame, and before it draws a mask on a frame it looks back at what it remembers about the object.

Press Play and stop on a frame where the mug is completely behind the box. Guess first: what should a segmentation model draw? A model that must always output a mask would draw something wrong. SAM 2 has an extra output, the occlusion head, that predicts whether the object is visible on this frame at all. When it says no, the frame gets no mask, and the model keeps tracking from memory.

Memory for video segmentation is older than SAM 2. STM (2019) treated past frames and their masks as an external memory: every pixel of the new frame attends to every pixel of every stored frame, and it stored a new memory frame every 5 frames. The memory grows with the video, so such models struggle on long clips. XMem (2022) split memory into 3 stores, after a model of human memory: a sensory memory updated every frame, a high-resolution working memory of recent frames, and a compact long-term memory of prototypes. With a 6 GB memory budget it could process up to 34,000 frames. Cutie (2023) added object-level memory on top. All three start from a full mask on the first frame. SAM 2's change is to make the memory promptable: any click on any frame becomes a memory.

The task is called promptable visual segmentation. You may click, draw a box or give a mask on any frame. The model answers at once on that frame, then spreads the answer over the whole video as a masklet, one mask per frame. A later click on any frame refines the masklet. Image segmentation is the special case of a video with one frame.

Four parts make this work:

  • A streaming image encoder. A Hiera encoder (a hierarchical vision transformer pretrained with MAE) runs once per frame, as the frames arrive. Its stride-16 and stride-32 features are fused into a 256x64x64 frame embedding.
  • Memory attention. L = 4 transformer blocks condition the frame embedding on the memory bank: self-attention over the frame, cross-attention to the memories, then an MLP.
  • A memory bank. It holds up to 6 memories of recent frames, each tagged with how many frames ago it was made, and the memories of frames you prompted, which carry no such tag. A memory is the predicted mask, downsampled and added to that frame's embedding, compressed to 64 channels.
  • Object pointers. The decoder's mask token for the chosen mask is a 256-number summary of the object. It is split into 4 tokens of 64 numbers and stored next to the spatial memories.

The read itself is ordinary cross-attention. The paper prints no equation for it; in standard notation (our transcription):

\htmlData{step=1, link=frame}{\htmlClass{t-blue}{X'}} = \mathrm{softmax}\!\Big(\frac{\htmlData{step=2, link=frame}{\htmlClass{t-blue}{Q_{\text{frame}}}}\,\htmlData{step=3, link=memory}{\htmlClass{t-blue}{K_{\text{mem}}}}^{\mathsf T}}{\sqrt{d}}\Big)\,\htmlData{step=4, link=memory}{\htmlClass{t-blue}{V_{\text{mem}}}}

Standard scaled dot-product cross-attention (our notation). SAM 2 v2, Sec. 4 describes it in words: self-attention, then cross-attention to the memories and object pointers, then an MLP, repeated in each of the 4 blocks.

  • \htmlClass{t-blue}{Q_{\text{frame}}}: one query per position of the current frame's 64x64 feature map.
  • \htmlClass{t-blue}{K_{\text{mem}}, V_{\text{mem}}}: keys and values from every position of every stored memory, plus the object pointer tokens.
  • \htmlClass{t-blue}{X'}: the frame's features, now "knowing" where the object was. The SAM decoder then turns them into a mask exactly as in chapter 4.

Two details carry a lot. First, a frame's memory is made after its mask is drawn, so mistakes can enter the bank; that is why a correction click is stored as a memory in a separate queue of prompted frames, apart from the 6 recent ones, so it is not pushed out as the video moves on (the queue size is not stated). Second, the decoder still produces several masks for an ambiguous click, but in a video only the one with the highest predicted IoU is carried forward unless a later prompt settles it.

An image is a video with an empty memory

With nothing in the bank, memory attention has nothing to read, and SAM 2 is a SAM. Trained only on SA-1B, the Hiera-B+ model scores 58.9 mIoU at one click on the 23-dataset suite of chapter 7, against 58.1 for SAM's ViT-H. It runs at 130.1 frames per second against 21.7, about 6x faster. That speed-up is for images. On video, with memory, the paper reports 43.8 frames per second for Hiera-B+ and 30.2 for Hiera-L on one A100.

Claim card: the SA-V data engine

Claim
Putting SAM 2 in the annotation loop makes video masks much cheaper at comparable quality.
How measured
A controlled run of the three annotation setups on the same 169 videos and 452 masklets: phase 1 used SAM on every frame, phase 2 added a mask-only SAM 2 to propagate, phase 3 used the full SAM 2 with clicks. Quality is the share of masks that agree with phase 1's at IoU above 0.75.
Result
See the table. Time per frame fell from 37.8 to 4.5 seconds, about 8.4x faster, while 89.1% of phase 3 masks still agreed with phase 1.
What would falsify it
Low agreement with phase 1, which would mean the speed came from sloppier masks.

The result is SA-V: 50.9K videos and 642.6K masklets, of which 190.9K were drawn by people and 451.7K were generated automatically and checked. Counting the automatic masklets, that is 53x more masks than any earlier video object segmentation dataset; the manual masklets alone are 15x more. The paper gives the average video length as 14 seconds in the main text and 13.8 seconds in the appendix. Objects disappear and come back often: 42.5% of the manual masklets disappear at some point, which is exactly what the occlusion head is for.

What memory buys

  • Fewer clicks. Started with one click on the first frame and evaluated on 17 video datasets, SAM 2 reaches an average accuracy of 64.7 against 56.7 for SAM followed by the Cutie tracker. The accuracy is J&F, which averages region overlap and boundary accuracy, on every dataset but VOST, where the table reports region overlap J.
  • Better tracks. Given a full mask on frame 1, the standard video-segmentation setting, Hiera-B+ scores 77.0 on the SA-V test set against 62.8 for Cutie-base+, and 90.2 on DAVIS 2017.
  • Pointers help on long, hard videos; a recurrent memory does not add much. In the paper's ablation setup (a smaller model at 512 px input), without object pointers SA-V val drops from 68.3 to 64.5. Feeding memories through a GRU instead gives 65.3. Pointers help on SA-V val and LVOSv2, but not on the average over the nine zero-shot datasets. Six recent memories is a speed choice: eight scored 69.0 but ran at 0.93 of the speed.

The authors list what still breaks (SAM 2 v2, App. C). The model "may fail to segment objects across shot changes and can lose track of or confuse objects in crowded scenes, after long occlusions or in extended videos". It "struggles with accurately tracking objects with very thin or fine details especially when they are fast-moving", and it confuses "nearby objects with similar appearance". Each object is tracked separately, "without inter-object communication". Chapter 12 shows the follow-ups that attack long videos and look-alikes.
