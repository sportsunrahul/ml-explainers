Act I: DETR

Detection is a set problem

Ask a person what is in a photo and you get a short list: two people, one dog, a car. No order, no duplicates. That list is a set of (class, box) pairs, and it is exactly what an object detector is supposed to produce.

Classic detectors never produce that set directly. They lay down thousands of candidate boxes (anchors, proposals, or a grid of centers), score every one, and end up with a cloud of overlapping guesses around each object. A cleanup step called non-maximum suppression (NMS) then keeps the highest-scoring box and deletes any other box that overlaps it by more than a threshold.

That threshold is a hand-set guess about what "duplicate" means. Push two people close together and see what it does.

With the people apart, any threshold up to about 0.5 works. Overlapping, a threshold of 0.3 deletes the second person entirely, because their best box overlaps the first person's best box, and NMS cannot tell "another person" from "the same person again". Raise it to 0.8 and a pile of duplicates survives. A middle value happens to work for this toy image, but the right setting depends on how crowded the scene is, and it is chosen by hand. The detector itself never learned to avoid duplicates; a heuristic cleans up after it.

DETR's question is simple: can the network output the final set directly, with no duplicates and no cleanup step?

One prediction per object: Hungarian matching

DETR predicts a fixed number of slots, N = 100, all at once. Each slot outputs a class (including a special "no object" class) and a box. A typical COCO image has far fewer objects than that, so most slots should say "no object".

Training needs to know which slot is responsible for which object. DETR pads the ground-truth list with "no object" up to N entries and finds the one-to-one assignment between slots and entries that costs the least. Here is the trick: because each object can be claimed by exactly one slot, a second slot sitting on the same object gets assigned "no object", and the loss then trains it to say so. Duplicates become expensive during training, so no NMS is needed afterwards.

Try it. Each row is a predicted slot, each column a ground-truth object (or a "no object" pad). Click one cell per row to build an assignment and compare your total with the optimum.

Now the math, which says exactly what you just did. First, choose the cheapest one-to-one assignment \hat\sigma of the N padded ground-truth entries to the N slots (DETR Eq. 1):

\hat{\sigma} = \arg\min_{\sigma\in\mathfrak{S}_N} \sum_{i}^{N} \htmlClass{t-red}{\mathcal{L}_{\rm match}}\big(\htmlClass{t-yellow}{y_i}, \htmlClass{t-blue}{\hat{y}_{\sigma(i)}}\big)
  • \mathfrak{S}_N: every possible way to pair the N entries with the N slots.
  • \htmlClass{t-yellow}{y_i}: ground-truth entry i, a real object or a "no object" pad.
  • \htmlClass{t-blue}{\hat{y}_{\sigma(i)}}: the prediction in the slot that assignment \sigma gives to entry i.

The cost of one pairing is what the matrix cells show:

\htmlClass{t-red}{\mathcal{L}_{\rm match}} = -\mathbb{1}_{\{c_i\neq\varnothing\}}\,\htmlClass{t-blue}{\hat{p}_{\sigma(i)}(c_i)} + \mathbb{1}_{\{c_i\neq\varnothing\}}\,\mathcal{L}_{\rm box}\big(\htmlClass{t-yellow}{b_i}, \htmlClass{t-blue}{\hat{b}_{\sigma(i)}}\big)
  • For a real object: minus how much probability the slot puts on the right class, plus how far its box is from the true box.
  • For a "no object" entry the indicator is 0, so the cost is zero whatever the slot predicts.

With the assignment fixed, the training loss (the paper's "Hungarian loss", Eq. 2) trains every slot's class, real or "no object", with cross-entropy, and trains the box only for slots matched to real objects:

\mathcal{L}_{\rm Hungarian} = \sum_{i=1}^{N}\Big[-\log \htmlClass{t-blue}{\hat{p}_{\hat\sigma(i)}(c_i)} + \mathbb{1}_{\{c_i\neq\varnothing\}}\,\mathcal{L}_{\rm box}\big(\htmlClass{t-yellow}{b_i}, \htmlClass{t-blue}{\hat{b}_{\hat\sigma(i)}}\big)\Big]

The box loss mixes two distances: \mathcal{L}_{\rm box} = \lambda_{\rm iou}\,\mathcal{L}_{\rm GIoU} + \lambda_{\rm L1}\,\lVert b - \hat b\rVert_1, with lambda_L1 = 5 and lambda_iou = 2. L1 alone would treat a 10-pixel error the same on a tiny box and a huge one; the GIoU (generalized intersection over union) term is scale-invariant and still gives a signal when two boxes do not overlap at all. Because most slots are "no object", their class term is down-weighted by a factor 10.

Object queries and a decoder that talks to itself

Where do the 100 slots come from? The architecture is almost boring, which is the point. A ResNet turns the image into a coarse grid of features, a transformer encoder lets every grid cell attend to every other, and a transformer decoder reads that grid through 100 learned input vectors called object queries. Each query becomes one slot's (class, box).

The decoder has two kinds of attention. Cross-attention lets each query read the image. Self-attention lets the queries read each other, and that is how they coordinate: if two queries are drifting toward the same car, self-attention gives them a way to notice, and the matching loss gives one of them a reason to back off.

The paper tests this directly. It attaches the prediction heads after every decoder layer and runs classic NMS on each layer's output. NMS helps the first layer, which still produces duplicates, but the benefit fades with depth and slightly hurts at the last layers. From the first decoder layer to the last, AP rises by +8.2 AP.

Two details matter for what comes next. First, the object queries are just learned vectors; they do not depend on the image, and nothing in them says "I am a box at this position". Second, because attention is blind to order, DETR adds its positional information at every attention layer, not only once at the input: sine encodings of pixel position on the image side, and the learned object queries on the decoder side. Keep both in mind: the follow-up papers are largely about what an object query should really be.
