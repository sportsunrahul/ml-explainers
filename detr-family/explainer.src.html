Act IDETR

Detection is a set problem

Ask a person what is in a photo and you get a short list: two people, one dog, a car. No order, no duplicates. That list is a set of (class, box) pairs, and it is exactly what an object detector is supposed to produce.

Classic detectors never produce that set directly. They lay down thousands of candidate boxes (anchors, proposals, or a grid of centers), score every one, and end up with a cloud of overlapping guesses around each object. A cleanup step called non-maximum suppression (NMS) then keeps the highest-scoring box and deletes any other box that overlaps it by more than a threshold.

That threshold is a hand-set guess about what "duplicate" means. Push two people close together and see what it does.

With the people apart, any threshold up to about 0.5 works. Overlapping, a threshold of 0.3 deletes the second person entirely, because their best box overlaps the first person's best box, and NMS cannot tell "another person" from "the same person again". Raise it to 0.8 and a pile of duplicates survives. A middle value happens to work for this toy image, but the right setting depends on how crowded the scene is, and it is chosen by hand. The detector itself never learned to avoid duplicates; a heuristic cleans up after it.

DETR's question is simple: can the network output the final set directly, with no duplicates and no cleanup step?

One prediction per object: Hungarian matching

DETR predicts a fixed number of slots, N = 100, all at once. Each slot outputs a class (including a special "no object" class) and a box. A typical COCO image has far fewer objects than that, so most slots should say "no object".

Training needs to know which slot is responsible for which object. DETR pads the ground-truth list with "no object" up to N entries and finds the one-to-one assignment between slots and entries that costs the least. Here is the trick: because each object can be claimed by exactly one slot, a second slot sitting on the same object gets assigned "no object", and the loss then trains it to say so. Duplicates become expensive during training, so no NMS is needed afterwards.

Try it. Each row is a predicted slot, each column a ground-truth object (or a "no object" pad). Click one cell per row to build an assignment and compare your total with the optimum.

Now the math, which says exactly what you just did. First, choose the cheapest one-to-one assignment \hat\sigma of the N padded ground-truth entries to the N slots (DETR Eq. 1):

\htmlData{step=1, link=assign}{\hat{\sigma} = \arg\min_{\sigma\in\mathfrak{S}_N}} \htmlData{step=2, link=cost}{\sum_{i}^{N} \htmlClass{t-red}{\mathcal{L}_{\rm match}}}\htmlData{step=3, link=gt pred}{\big(\htmlClass{t-yellow}{y_i}, \htmlClass{t-blue}{\hat{y}_{\sigma(i)}}\big)}
  • \mathfrak{S}_N: every possible way to pair the N entries with the N slots.
  • \htmlClass{t-yellow}{y_i}: ground-truth entry i, a real object or a "no object" pad.
  • \htmlClass{t-blue}{\hat{y}_{\sigma(i)}}: the prediction in the slot that assignment \sigma gives to entry i.

The cost of one pairing is what the matrix cells show:

\htmlClass{t-red}{\mathcal{L}_{\rm match}} = \htmlData{step=1, link=class pred}{-\mathbb{1}_{\{c_i\neq\varnothing\}}\,\htmlClass{t-blue}{\hat{p}_{\sigma(i)}(c_i)}} \htmlData{step=2, link=box gt}{+ \mathbb{1}_{\{c_i\neq\varnothing\}}\,\mathcal{L}_{\rm box}\big(\htmlClass{t-yellow}{b_i}, \htmlClass{t-blue}{\hat{b}_{\sigma(i)}}\big)}
  • For a real object: minus how much probability the slot puts on the right class, plus how far its box is from the true box.
  • For a "no object" entry the indicator is 0, so the cost is zero whatever the slot predicts.

With the assignment fixed, the training loss (the paper's "Hungarian loss", Eq. 2) trains every slot's class, real or "no object", with cross-entropy, and trains the box only for slots matched to real objects:

\mathcal{L}_{\rm Hungarian} = \sum_{i=1}^{N}\Big[\htmlData{step=1, link=pred}{-\log \htmlClass{t-blue}{\hat{p}_{\hat\sigma(i)}(c_i)}} \htmlData{step=2, link=gt pred}{+ \mathbb{1}_{\{c_i\neq\varnothing\}}\,\mathcal{L}_{\rm box}\big(\htmlClass{t-yellow}{b_i}, \htmlClass{t-blue}{\hat{b}_{\hat\sigma(i)}}\big)}\Big]

The box loss mixes two distances: \mathcal{L}_{\rm box} = \lambda_{\rm iou}\,\mathcal{L}_{\rm GIoU} + \lambda_{\rm L1}\,\lVert b - \hat b\rVert_1, with \lambda_{\rm L1} = 5 and \lambda_{\rm iou} = 2. L1 alone would treat a 10-pixel error the same on a tiny box and a huge one; the GIoU (generalized intersection over union) term is scale-invariant and still gives a signal when two boxes do not overlap at all. Because most slots are "no object", their class term is down-weighted by a factor 10.

Object queries and a decoder that talks to itself

Where do the 100 slots come from? The architecture is almost boring, which is the point. A ResNet turns the image into a coarse grid of features, a transformer encoder lets every grid cell attend to every other, and a transformer decoder reads that grid through 100 learned input vectors called object queries. Each query becomes one slot's (class, box).

The decoder has two kinds of attention. Cross-attention lets each query read the image. Self-attention lets the queries read each other, and that is how they coordinate: if two queries are drifting toward the same car, self-attention gives them a way to notice, and the matching loss gives one of them a reason to back off.

The paper tests this directly. It attaches the prediction heads after every decoder layer and runs classic NMS on each layer's output. NMS helps the first layer, which still produces duplicates, but the benefit fades with depth and slightly hurts at the last layers. From the first decoder layer to the last, AP rises by +8.2 AP.

Two details matter for what comes next. First, the object queries are just learned vectors; they do not depend on the image, and nothing in them says "I am a box at this position". Second, because attention is blind to order, DETR adds its positional information at every attention layer, not only once at the input: sine encodings of pixel position on the image side, and the learned object queries on the decoder side. Keep both in mind: the follow-up papers are largely about what an object query should really be.

One training step, end to end

This chapter has no narration: step through it at your own pace.

You have now seen every part of DETR. Here they are running together in one training step: a batch leaves the data loader, flows through the network, gets matched to its ground truth, and becomes one loss and one weight update. Click a stage or press Next to walk through it, or Run a step to watch the whole pass. New batch draws fresh augmented image sizes, and every tensor shape below updates with them.

At inference there is no matching and no loss: take the last decoder layer's 100 slots and give each one its most likely real class (ignoring "no object") and its box. For its COCO AP numbers the paper keeps all of them this way, even slots whose top class is "no object", and reports that this scores 2 AP higher than filtering those slots out. To draw a clean picture you would instead keep only the slots whose score clears a threshold. No NMS either way.

Training repeats this step for every batch: 300 epochs with the learning rate cut tenfold after 200 for the paper's ablations, or 500 epochs with the drop after 400 for the headline model. The paper reports 3 days on 16 V100 GPUs for the shorter schedule. Why it needs so many epochs is where the next chapter starts.

What it cost: long training and small objects

The headline result was a clean tie. DETR with a ResNet-50 reached 42.0 AP on COCO, the same as a carefully tuned Faster R-CNN with FPN (42.0 AP), with no anchors and no NMS. But the tie hides two very different profiles.

On large objects DETR was much better: 61.1 versus 53.4 APL. On small objects it was much worse: 20.5 versus 26.6 APS. And it needed 500 epochs of training for the headline number, against 109 epochs for the baseline.

The small-object problem traces back to the encoder. Every one of the HW feature-map cells attends to every other, so the cost grows with the square of the number of cells. DETR can only afford the coarse stride-32 map, where a small object may cover a single cell. The long training has more than one suspect, and the next chapters meet them: attention over image features that starts out nearly uniform over thousands of pixels (Deformable DETR's diagnosis), and object queries that carry no clear notion of position (DAB-DETR's). Doubling the resolution (the paper's DC5 variant) multiplies encoder self-attention cost by 16x and drops speed from 28 to 12 FPS. Slide the stride to feel the square.

In the paper's own accounting (Appendix A.3), one encoder self-attention layer costs

\mathcal{O}\big(d^2\,\htmlClass{t-blue}{HW} + d\,(\htmlClass{t-red}{HW})^2\big)
  • d: the feature width (d = 256). The first term is the linear projections, one per cell.
  • The second term is every cell comparing itself with every other cell. Once HW is in the thousands it dominates, and it is the one that explodes when you ask for finer features.

The paper names the long schedule and small objects as the "new challenges" of its design. Everything in Act II is an answer to them.

Act IIMaking DETR train fast

Deformable DETR: look at a few points, not every pixel

Here is the idea that fixed attention over image features, in the encoder and in the decoder's cross-attention alike. A query does not need to compare itself against every pixel. Give it a reference point, and let it predict a handful of sampling points near it: where to look, and how much to trust each look. No query-key dot products at all; the offsets and the weights both come from the query through one linear layer.

Deformable DETR uses M = 8, K = 4: eight heads, each sampling four points, on each of L = 4 feature levels. That is 128 per query sampled points, no matter how large the feature maps are. Drag the reference point around.

Written out, deformable attention for one query (Deformable DETR Eq. 2) is

\mathrm{DeformAttn}(\mathbf{z}_q, \mathbf{p}_q, \mathbf{x}) = \sum_{m=1}^{M} \mathbf{W}_m \Big[\sum_{k=1}^{K} \htmlClass{t-green}{A_{mqk}} \cdot \mathbf{W}'_m\, \mathbf{x}\big(\mathbf{p}_q + \htmlClass{t-blue}{\Delta\mathbf{p}_{mqk}}\big)\Big]
  • \mathbf{z}_q: the query's feature; \mathbf{p}_q: its reference point.
  • \htmlClass{t-blue}{\Delta\mathbf{p}_{mqk}}: where head m's k-th point looks, relative to the reference point, predicted from \mathbf{z}_q. Fractional, so the feature is read by bilinear interpolation.
  • \htmlClass{t-green}{A_{mqk}}: how much that look counts; the K weights of a head sum to 1. Also predicted from \mathbf{z}_q, not from comparing with keys.
  • \mathbf{W}'_m, \mathbf{W}_m: the usual value and output projections.

The multi-scale version (Eq. 3) is the same sum with an extra loop over the L levels, and one softmax across all L x K points of a head, so a head can weigh fine and coarse evidence against each other. That is FPN-style fusion done by attention itself; adding an actual FPN on top gave no gain in the paper's ablation.

The effect on training was dramatic. Deformable DETR reached 43.8 AP in 50 epochs, against DETR's 42.0 AP in 500 epochs, and small-object AP rose to 26.4 APS. Sparse attention also starts out focused, instead of spread uniformly over thousands of pixels, which the paper gives as a reason for the faster convergence. Two variants mattered for the future: iterative box refinement, where each decoder layer corrects the previous layer's box (45.4 AP), and a two-stage version whose queries start from the encoder's best proposals (46.2 AP). The cost: it runs 25% slower than Faster R-CNN at similar FLOPs, because scattered sampling is unfriendly to memory.

DAB-DETR: a query is a box

Back to that loose end: what is an object query? DAB-DETR's answer starts by splitting it in two. A decoder query has a content part (what it has seen so far) and a positional part (where it is looking). In DETR the positional part is an opaque learned vector, and the paper's visualizations show it spreads attention over several unrelated regions at once, which it conjectures is a root cause of the slow training.

So make the positional part literally a box. Each of the 300 queries owns an anchor (\htmlClass{t-blue}{x}, \htmlClass{t-blue}{y}, \htmlClass{t-blue}{w}, \htmlClass{t-blue}{h}). Its center steers where attention looks, its width and height stretch attention into an oval of the right size, and after every decoder layer the box is nudged toward the object. Drag the box, change its size, and watch the positional attention follow.

The anchor becomes the positional query in two steps (DAB-DETR Eq. 1-2): encode each of the four numbers with sines and cosines, then map the concatenation through a small MLP shared by all layers.

P_q = \mathrm{MLP}\big(\mathrm{PE}(\htmlClass{t-blue}{A_q})\big),\qquad \mathrm{PE}(\htmlClass{t-blue}{A_q}) = \mathrm{Cat}\big(\mathrm{PE}(\htmlClass{t-blue}{x_q}), \mathrm{PE}(\htmlClass{t-blue}{y_q}), \mathrm{PE}(\htmlClass{t-blue}{w_q}), \mathrm{PE}(\htmlClass{t-blue}{h_q})\big)

The oval comes from Eq. 6: the similarity between an image position (x, y) and the anchor center is computed separately along x and along y, and each part is divided by the anchor's size relative to a reference size.

\mathrm{ModulateAttn} = \Big(\mathrm{PE}(x)\cdot \mathrm{PE}(\htmlClass{t-blue}{x_{\rm ref}})\,\frac{w_{q,\rm ref}}{\htmlClass{t-blue}{w_q}} + \mathrm{PE}(y)\cdot \mathrm{PE}(\htmlClass{t-blue}{y_{\rm ref}})\,\frac{h_{q,\rm ref}}{\htmlClass{t-blue}{h_q}}\Big) \big/ \sqrt{D}
  • A wide anchor (large \htmlClass{t-blue}{w_q}) shrinks the x term, so attention flattens and spreads horizontally. A narrow one sharpens it.
  • This happens before the softmax, so it reshapes where the query looks, not what it does with what it finds.

DAB-DETR also found that the standard temperature T = 10000 in the sine encoding, designed for integer word positions, is a poor fit for box coordinates between 0 and 1; it uses T=20. Flip between the two temperatures above to see why: at 10000 the attention is nearly flat.

After each of the six decoder layers a shared head predicts a correction, and the anchor is updated in logit space, \sigma(\sigma^{-1}(\text{old}) + \Delta): the rule Deformable DETR prints in its Appendix A.4, which DAB-DETR says it follows. In the paper's ablation, removing this layer-by-layer update costs 1.7 AP. The full model reaches 45.7 AP in 50 epochs (ResNet-50 with dilated last stage and 3 pattern embeddings).

DN-DETR and DINO: teach with noisy answers

Even with better queries, DETR-style training has a quieter problem. Early on, the Hungarian matching is unstable: for the same image, a slot matched to the dog this epoch may be matched to the car the next. Its training target keeps flipping, so it keeps unlearning. DN-DETR measures this directly, counting how many slots change their assigned object between consecutive epochs.

The fix is a piece of teaching folklore: give the student problems whose answer is known. Alongside the normal queries, DN-DETR feeds the decoder noised copies of the ground-truth boxes, shifted and rescaled a little, sometimes with a wrong label, and trains them to recover the original. These queries skip matching entirely; their target is fixed by construction. The model learns to refine a nearby box, a skill the matching queries then share, and the whole denoising part is dropped at test time, so inference costs nothing extra.

In DN-DETR's words, a box is shifted so its center moves by |\Delta x| < \lambda_1 w/2 and |\Delta y| < \lambda_1 h/2, and rescaled so its width lies in [(1-\lambda_2)w, (1+\lambda_2)w] (height likewise), with 0.4 for both scales. Labels are flipped to a random class at rate 0.2, which forces the model to use the box to recover the class. There are 5 noised groups by default.

One detail is load-bearing: an attention mask. The matching queries must not see the denoising queries (they would just copy near-perfect boxes), and one noised group must not see another (another noisy copy of the same object leaks the answer). Denoising without the mask does not just fail to help; it collapses to 24.0 AP against 43.4 with it.

DINO then stacks the best ideas so far, DAB-style box queries, DN-style denoising and Deformable attention, and adds three of its own:

  • Contrastive denoising. Plain denoising only teaches "fix a nearby box". DINO adds hard negatives: noised boxes a bit further out that must be answered with "no object". That teaches the model to reject a near-miss, which cuts duplicates. Toggle DINO's noise above to see the two shells.
  • Mixed query selection. The decoder's anchor boxes start from the encoder's top-scoring locations for this image, while the content part of each query stays a learned vector. The encoder's rough features are good at where, not yet at what.
  • Look forward twice. In box refinement, layer i's correction is normally trained only by layer i's loss. DINO lets the refined box of the next layer also send gradient back, so a layer is judged partly by how much it helps its successor.

In DINO's ablation (ResNet-50), engineering improvements and query selection borrowed from Deformable DETR first lift DN-DETR from 43.4 to a strong baseline of 46.5 AP; DINO's own three additions then take it to 47.9. DINO-4scale reaches 49.0 AP in only 12 epochs (4 feature scales, no extra data). The famous 63.3 AP on COCO test-dev needs a Swin-L backbone, pre-training on Objects365 and test-time augmentation, so it is a different kind of number.

Act IIIMaking DETR run fast

RT-DETR: DETRs beat YOLOs once you count NMS

By 2023 DETRs trained fast enough, but they were still too slow at inference for real-time use, where YOLO dominated. RT-DETR starts by pointing out something odd about the comparison: YOLO speed numbers usually leave out NMS. And NMS time is not a constant. It depends on how many boxes survive the confidence threshold, and on the IoU threshold. Step through the thresholds the paper measured.

Lower thresholds keep more boxes and slightly more AP, and they cost more NMS time: at the paper's best-accuracy setting YOLOv8's NMS kernel alone takes 2.36 ms. A set predictor has no such knob to trade.

RT-DETR's own changes attack the remaining cost, the encoder. It runs self-attention only on the coarsest feature map, where each cell already stands for a whole object part (the paper calls this AIFI), and fuses the finer scales with a cheap convolutional path (CCFF). Its queries are chosen from the encoder's best features, with a training loss that makes a high class score also mean a well-placed box; in the ablation that is worth 48.7 versus 47.9 AP. And because every decoder layer is supervised, you can drop layers at inference to trade accuracy for speed without retraining: stopping one layer early costs 0.1 AP and saves half a millisecond.

The result, measured end to end with NMS included for the YOLOs, on a T4 GPU with TensorRT FP16 at 640 x 640: RT-DETR-R50 reaches 53.1 AP at 108 FPS, against YOLOv8-L at 52.9 AP and 71 FPS. Barely more accurate, about half again as fast.

RF-DETR: train once, pick your latency

Real-time detectors usually come as a hand-designed ladder of sizes, N, S, M, L, X, each trained separately and tuned on COCO. RF-DETR asks why. It takes a DETR with a pretrained DINOv2 vision-transformer backbone and trains one weight-sharing network per backbone size: at every training step it samples a random patch size, input resolution and number of attention windows, so the same weights learn to work under all of them. The number of decoder layers and queries is cut only at inference.

After training, a grid search over thousands of configurations measures accuracy and latency for each, and keeps the best trade-offs. Picking a model is then picking a latency budget. Slide the budget.

Two numbers stand out. The nano model reaches 48.0 AP at 2.3 ms, 5.3 AP above D-FINE's nano at a similar latency. And the 2XL model is the first real-time detector above 60: 60.1 AP at 17.2 ms. It does not win everywhere; turn on the baselines and you can see D-FINE ahead at the M, L and XL sizes on COCO.

There are really two base networks here, one on a small DINOv2 backbone (N to L) and one on a larger one (XL to Max), each trained once. Watch the readout as you raise the budget: on the small backbone the patch size stays at 16 while resolution and decoder depth grow; the large backbone switches to patch 20, and Max changes again to patch 12. The paper notes that accuracy tracks the number of spatial locations, resolution divided by patch size, more closely than either alone. The search itself is paid for once: about 10,000 GPU hours on T4s to evaluate the configurations. On the 100-dataset RF100-VL benchmark, the paper finds that COCO-tuned architectures already transfer remarkably well, and a per-dataset search adds a further 0.1 to 0.7 AP at most sizes.

Notice what never changed from 2020 to here: a fixed set of queries, one-to-one matching, and no NMS. Everything else, the attention, the queries, the training signal, the backbone and the search, was rebuilt around that idea.

Summary

DETR reframed detection as predicting a set: a fixed number of query slots, trained with a one-to-one Hungarian matching so that duplicates are punished by the loss itself, which removes anchors and NMS. The price was dense attention over every pixel, which made training long and small objects hard. Deformable DETR made attention sparse and multi-scale; DAB-DETR made each query an explicit box refined layer by layer; DN-DETR and DINO stabilized training with denoising queries and hard negatives, reaching strong accuracy in a dozen epochs. RT-DETR then showed that, once NMS is counted, a DETR can beat YOLO at real-time speed, and RF-DETR trained a single weight-sharing network from which a whole family of speed-accuracy trade-offs can be chosen after training.
