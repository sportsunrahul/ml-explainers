Learning to see with no labels

An illustrated guide to Meta AI's DINO family: how a network can teach itself what images mean by comparing different views of the same picture, and how three papers turned that trick into the strongest general-purpose vision backbones available.

The shared idea

All three papers answer one question: how do you learn good visual features from images alone, with no captions and no class labels? Their answer is self-distillation. Two copies of the same network look at different random views of one image. One copy, the teacher, produces a target. The other, the student, is trained to match it. The teacher is never trained directly; it is a slowly moving average of the student's past weights, so it behaves like a steadier, slightly wiser version of the student.

To match the teacher from a tiny crop of a bird's wing, the student has to understand that the wing belongs to a bird. That pressure to agree across views is what forces semantic understanding. The name comes from the method: DIstillation with NO labels.

What changes across generations is everything around that core: the amount and quality of data, the model size, extra loss terms that make patch-level features good, and in DINOv3 a new regulariser that stops those patch features from decaying during very long training.

DINO

2021Caron et al., “Emerging Properties in Self-Supervised Vision Transformers”

Main idea

DINO showed that a Vision Transformer (ViT) trained by self-distillation learns features that are excellent for nearest-neighbour retrieval and, remarkably, that its attention maps segment objects on their own. Supervised ViTs do not show this. The method is also simpler than most of its predecessors: no negative pairs (unlike contrastive learning such as SimCLR or MoCo), no memory bank, no predictor network (unlike BYOL), and no batch normalisation in the head.

The training loop

Each image is augmented into several crops. Two global crops (224 px, covering a large part of the image) and several local crops (96 px, covering small parts). The teacher only sees the global crops. The student sees everything. The student must predict, from each view, the teacher's output for the other views. Matching a tiny local crop to a global view teaches “local-to-global” correspondence: the part implies the whole.

The loss

Both networks output K logits (K = 65,536 in the paper), turned into probabilities with a softmax at temperature τ. The student learns by minimising cross-entropy against the teacher's distribution, summed over all pairs of different views:

\begin{aligned} &\htmlClass{t-teacher}{P_t}(x) = \mathrm{softmax}\!\left(\frac{g_{\theta_t}(x) - c}{\tau_t}\right) \qquad \htmlClass{t-student}{P_s}(x') = \mathrm{softmax}\!\left(\frac{g_{\theta_s}(x')}{\tau_s}\right) \\ &\htmlClass{t-plum}{L} = \sum_{x \in \{\text{global}\}} \; \sum_{x' \neq x} -\,\htmlClass{t-teacher}{P_t}(x) \cdot \log \htmlClass{t-student}{P_s}(x') \end{aligned}
τt ≈ 0.04 to 0.07 (sharp), τs = 0.1, c is the running centre of teacher outputs.

The teacher is a moving average

\htmlClass{t-teacher}{\theta_t} \leftarrow \lambda\,\htmlClass{t-teacher}{\theta_t} + (1 - \lambda)\,\htmlClass{t-student}{\theta_s} \qquad \lambda \text{ goes from } 0.996 \text{ to } 1 \text{ on a cosine schedule}
No gradient ever flows into the teacher (a “stop-gradient”). It behaves like a model ensemble over training time, which is why it gives better targets than the student itself.

Why it doesn't collapse

Self-distillation has an obvious cheat. If both networks output the same thing for every image, the loss is perfect and nothing is learned. DINO blocks this with two opposing forces applied to the teacher's output:

Centering subtracts a running mean c of teacher logits (updated with momentum 0.9). This stops any single dimension from dominating for every image, but on its own it pushes outputs toward a flat, uniform distribution. Sharpening uses a low teacher temperature, which makes outputs confident, but on its own lets one dimension win everywhere. Together they balance: each image gets a confident answer, and different images get different answers. Try it below. Architecture

The backbone is a standard ViT. The image is cut into 16×16 or 8×8 pixel patches, each patch becomes a token, a learnable [CLS] token is prepended, and a stack of transformer blocks mixes them. The [CLS] output is the image's feature. On top sits a projection head used only during training: a 3-layer MLP (hidden size 2048), an ℓ2-normalised 256-d bottleneck, and a weight-normalised linear layer to K = 65,536 outputs. After training the head is thrown away. Models released: ViT-S/16, ViT-S/8, ViT-B/16, ViT-B/8 (about 21M and 85M parameters), plus a ResNet-50 for comparison.

The student and teacher have the same architecture. That is one of the things that makes DINO elegant: there is no separate target network design, only an averaged copy.

The emergent surprise: attention that segments

Look at where the [CLS] token attends in the last layer. In a DINO-trained ViT, different heads lock onto the object, its parts, or the background, producing clean masks without any segmentation labels. A supervised ViT trained on ImageNet classes attends in a noisier, scattered way, because it only needs enough evidence to name the class.

Results in brief

With a frozen backbone and a simple linear classifier, ViT-B/8 reached 80.1% top-1 on ImageNet, and a plain k-nearest-neighbour classifier reached 77.4%, which showed the feature space itself was semantically organised. It also did well on image retrieval, copy detection and video object segmentation, all without fine-tuning. Everything was trained on ImageNet-1k images only, with labels ignored.

Strengths

  • Simple: no negatives, no memory bank, no predictor, identical student and teacher.
  • Strong k-NN performance, so features are useful as-is for retrieval and search.
  • Attention maps give object segmentation for free, a genuinely new finding.
  • Works with both ViTs and ConvNets.

Weaknesses

  • Collapse control depends on carefully tuned temperatures, momentum and centering; small changes can destabilise training.
  • Multi-crop is compute-heavy, and small patches (ViT-B/8) are very expensive.
  • Trained only on ImageNet-1k, so features are biased toward object-centric photos and don't transfer as broadly as later versions.
  • The loss acts on the [CLS] token only, so individual patch features are not directly trained and dense tasks lag behind.

DINOv2

2023Oquab et al., “DINOv2: Learning Robust Visual Features without Supervision”

Main idea

DINOv2 asked whether self-supervised learning could produce all-purpose frozen features, the way large language models give text features that work for many tasks. The recipe was not a new principle but a careful scale-up: a much larger curated dataset, a billion-parameter ViT, a combined image-level and patch-level objective, and a lot of engineering so it trains stably and efficiently. The result was the first self-supervised backbone that matched or beat weakly supervised text-image models such as OpenCLIP on most vision benchmarks, including dense ones like depth and segmentation.

Data curation: quality over raw size

Simply training on raw web images makes features worse, because the web is dominated by a few kinds of content and many near-duplicates. DINOv2 built LVD-142M: starting from about 1.2 billion uncurated images, it removed near-duplicates with a copy-detection model, embedded everything with a self-supervised ViT, and then used a set of curated seed datasets (ImageNet-22k, ImageNet-1k, Google Landmarks and several fine-grained sets) to retrieve web images similar to them. Only images close to something in the seed collection were kept.

The training objective

DINOv2 combines three losses, borrowing from DINO, iBOT and a nearest-neighbour regulariser.

1. DINO loss on the image

Exactly as before: student [CLS] output matches teacher [CLS] output across crops.

2. iBOT loss on the patches

Random patches in the student's input are replaced with a learnable mask token. The teacher sees the full image. For each masked position, the student must predict the teacher's output for that exact patch. This is masked image modelling in feature space rather than pixel space, and it is what makes DINOv2's patch features good for dense tasks. DINOv2 uses separate (“untied”) projection heads for the image-level and patch-level losses, which worked better at scale.

3. KoLeo regulariser

The Kozachenko–Leonenko entropy estimator encourages features within a batch to spread out evenly. For each feature, it looks at the distance di to its nearest neighbour and penalises small distances:

\htmlData{link=koleo, label=the KoLeo loss}{L_{\text{KoLeo}}} = -\frac{1}{n}\sum_{i} \log \htmlData{link=nn, label=the nearest-neighbour distances}{d_i}, \qquad d_i = \min_{j \neq i} \lVert \htmlData{link=pts, label=the features}{x_i} - x_j \rVert
Applied to ℓ2-normalised [CLS] features with a small weight (0.1). Evenly spread features make nearest-neighbour retrieval much better.Hover or tap a term to see it in the figure below.

Centering, upgraded

DINO's running-mean centering is replaced by Sinkhorn–Knopp normalisation (from SwAV). It rescales the teacher's batch of outputs so that every prototype is used equally across the batch, a stricter and more stable way to prevent collapse at large scale.

Architecture and engineering

The largest model is ViT-g/14: about 1.1 billion parameters, 40 blocks, width 1536, patch size 14 and SwiGLU feed-forward layers. Training used FlashAttention, sequence packing of global and local crops, efficient stochastic depth that skips dropped blocks entirely, and fully sharded data parallelism. At the end of pretraining, the model is trained briefly at 518 px so it handles higher resolutions, a cheap way to get sharper dense features.

Smaller models (ViT-S/14, B/14, L/14) are not trained from scratch. They are distilled from the frozen ViT-g using the same self-supervised losses, which gives them better features than training them directly.

A follow-up fix: registers

Shortly after release, a companion paper (“Vision Transformers Need Registers”) found that large ViTs, DINOv2 included, repurpose some low-information background patches as scratch space for global computation. Those tokens get abnormally high norms and create artifacts in attention and feature maps. Adding a few extra learnable register tokens, which are discarded at output, gives the model dedicated scratch space and removes the artifacts. DINOv2 checkpoints “with registers” were released, and DINOv3 builds registers in from the start.

What improved over DINO: 142M curated images instead of 1.3M, a 1.1B model instead of 85M, patch-level supervision through iBOT, KoLeo for spread, Sinkhorn–Knopp for stability, high-resolution adaptation, and a distilled family of models. Frozen linear ImageNet accuracy rose to 86.5% (ViT-g/14), and frozen features became strong for depth estimation and segmentation too.

Strengths

  • Truly general frozen features: one backbone serves classification, retrieval, depth, segmentation and more with only a linear head.
  • Patch features are useful on their own, thanks to the iBOT objective.
  • Distilled small models are practical for real applications.
  • Open code and weights under Apache 2.0, which drove wide adoption.

Weaknesses

  • High-norm artifact tokens in feature maps (fixed later with registers).
  • Retrieval-based curation can only find content similar to its seed datasets, so it inherits their biases and misses unusual domains.
  • Patch size 14 gives coarse feature maps; fine detail still requires high-resolution inputs.
  • No link to language, so zero-shot text queries need an extra alignment step.
  • Training the ViT-g teacher is expensive and hard to reproduce.

DINOv3

2025Siméoni et al., “DINOv3”

Main idea

DINOv3 scaled again, to a 7-billion-parameter ViT trained on about 1.7 billion images, and in doing so hit a wall: when you train a large model for a long time, global features keep improving but dense patch features get worse. Patch similarity maps become noisy and lose their locality after roughly the first couple of hundred thousand iterations. The paper's central contribution is Gram anchoring, a regulariser that fixes this, letting the model keep its excellent patch features while training long enough to get the best global ones.

The problem, and Gram anchoring

Stack the ℓ2-normalised patch features of an image into a matrix X (one row per patch). Its Gram matrix X Xᵀ holds the cosine similarity between every pair of patches. That matrix is the dense structure: which patches belong together. DINOv3 keeps an earlier checkpoint of the teacher whose patch features were still clean, called the Gram teacher, and adds a loss that makes the student's Gram matrix match it:

\htmlData{link=gram, label=the Gram anchoring loss}{L_{\text{Gram}}} = \left\lVert \htmlData{link=gs, label=the student patch similarities}{\htmlClass{t-student}{X_S X_S^{\top}}} - \htmlClass{t-teacher}{X_G X_G^{\top}} \right\rVert_F^{2}
XS: student patch features. XG: Gram teacher patch features. Only relative similarities are constrained, so the features themselves are still free to move and improve.

This is the clever part. It does not freeze the features to old values, only the pattern of similarities between patches. Gram anchoring is switched on in a refinement phase after about one million iterations, and dense performance recovers quickly. A refinement called high-resolution Gram feeds the Gram teacher images at twice the resolution and downsamples its features, which gives even cleaner, more detailed targets.

Training recipe

Data: LVD-1689M, curated from roughly 17 billion public Instagram images. It mixes three pools: images selected by balanced sampling across hierarchical k-means clusters (so rare concepts are not drowned out), a retrieval-based pool similar to DINOv2's, and raw ImageNet-1k. A separate model is trained on about 493 million satellite images.

Objective: DINO loss plus iBOT loss plus KoLeo, as in DINOv2, then Gram anchoring added during refinement. All hyperparameters (learning rate, weight decay, teacher momentum) are held constant after warm-up instead of following cosine schedules. That means you don't have to decide the training length in advance and can simply keep training and pick checkpoints.

High-resolution adaptation: a final stage trains on mixed crop sizes, including large global crops, with Gram anchoring still active, so the features stay stable and sharp at high input resolutions.

Distillation: the 7B model is distilled into a family: ViT-S, S+, B, L, H+ (about 840M) and ConvNeXt Tiny to Large for efficient deployment. A multi-student setup shares one teacher's forward pass across several students to save compute.

Architecture

The teacher is a custom ViT-7B/16: about 6.7B parameters, 40 blocks, width 4096, 32 heads, patch size 16 and 4 register tokens. Instead of learned absolute position embeddings, it uses rotary position embeddings (RoPE) applied along both image axes, with random jittering of the coordinate box during training. That makes the model robust to changes in resolution and aspect ratio, which is what allows dense features to stay useful at large input sizes. The patch size moved from 14 back to 16, trading a little resolution per pixel for fewer tokens and better efficiency at scale.

Extras

dino.txt aligns a text encoder to the frozen DINOv3 features, so the vision backbone can do zero-shot classification and open-vocabulary segmentation without being retrained with text. The satellite variant brings the same recipe to remote sensing, for tasks such as canopy height estimation.

What improved over DINOv2: about 6 times more parameters and 12 times more curated images, balanced cluster-based curation, Gram anchoring to keep dense features clean through long training, RoPE for resolution robustness, registers built in, constant schedules, and a broader distilled family including ConvNeXt. The 7B model reaches about 88.4% frozen linear accuracy on ImageNet, and its largest gains are on dense tasks: segmentation, depth, 3D correspondence, tracking and detection with a frozen backbone.

Strengths

  • State-of-the-art dense features from a single frozen backbone; often competitive with specialised, fine-tuned systems.
  • Stable at high resolutions thanks to RoPE and the high-resolution stage.
  • Wide model family, from small ViTs and ConvNeXts to 7B, plus satellite and text-aligned variants.
  • Gram anchoring is a general idea: any self-supervised method that loses dense quality with long training could use it.

Weaknesses

  • Enormous compute to train the 7B teacher, far beyond most labs.
  • A multi-stage pipeline (pretrain, Gram refinement, high-res, distil) with more hyperparameters to get right, including which checkpoint to use as the Gram teacher.
  • Released under a custom DINOv3 licence rather than Apache 2.0, and weights require accepting its terms.
  • On tasks that need language knowledge, such as reading text in images, text-supervised models can still do better.
  • The 7B model is heavy to run; most users will rely on the distilled versions.

The thread that connects them

Each paper fixed the most visible weakness of the one before. DINO proved the principle but learned only from the [CLS] token on a small dataset. DINOv2 added patch-level learning and scaled data and model, which exposed that curation mattered more than size and that big ViTs grow artifact tokens. DINOv3 scaled further, found that long training quietly erodes dense features, and introduced a loss that protects the similarity structure between patches.

Which one should you use?

For a new project needing dense features (segmentation, depth, correspondence, tracking, robotics), start with a distilled DINOv3 ViT-B or ViT-L, provided its licence works for you. For a permissive licence or a very large existing ecosystem, DINOv2 with registers remains an excellent, battle-tested choice. For learning the method, read and run the original DINO: it is small enough to train yourself and the core loop fits on a page.

A typical workflow is to keep the backbone frozen, extract [CLS] and patch features, and train only a light head. For example, loading DINOv2 in PyTorch:

import torch
model = torch.hub.load("facebookresearch/dinov2", "dinov2_vitb14_reg")
model.eval()
feats = model.forward_features(images)       # images: (B, 3, H, W), H and W multiples of 14
cls   = feats["x_norm_clstoken"]             # (B, 768)  global feature
patch = feats["x_norm_patchtokens"]          # (B, N, 768)  dense features

DINOv3 weights are distributed through the official repository and Hugging Face after accepting the licence; check its README for the current loading code.
