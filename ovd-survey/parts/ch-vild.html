ViLD: teach the region head to see like CLIP

Where text enters ViLD: only at the classifier. CLIP's text encoder embeds the class names once, before training, and the detector compares each region embedding with those stored vectors.

Chapter 3 ended with a detector that boxes a forklift and then calls it background. CLIP can name that crop. ViLD (Gu et al., 2021) trains the detector's region embeddings to land where CLIP would put them, so the detector can name every proposal in one pass.

Guess first. The forklift regions have no label in the training data. Before you press Text loss only, decide where that loss will send them. Then press Image loss only and compare.

With the text loss alone, the forklift regions drift toward the learned background vector: a proposal that matches no labelled box is, by definition, background. The image loss uses no labels at all. It asks each region to copy CLIP's view of its crop, and CLIP's view of a forklift crop sits near the word "forklift". That is how ViLD reaches classes that no box label ever touches.

The slow way: ask CLIP about every box

The direct approach needs no new training. Take the class-agnostic proposals of chapter 3, crop each one out of the image, and give the crop to CLIP's image encoder (CLIP is recapped in chapter 1). Compare the result with the text vector of every class name, and the best match names the box. ViLD tries this first, with one refinement: it embeds each box twice, once tight and once enlarged 1.5x for context, and adds the two:

\htmlData{step=1, link=image}{\htmlClass{t-blue}{\mathcal{V}(\text{crop}(I, \tilde{r}_{\{1\times, 1.5\times\}}))}} = \htmlData{step=3, link=sphere}{\frac{\mathbf{v}}{\|\mathbf{v}\|}}, ~\text{where}~ \htmlData{step=2, link=image}{\mathbf{v} = \mathcal{V}(\text{crop}(I, \tilde{r}_{1\times})) + \mathcal{V}(\text{crop}(I, \tilde{r}_{1.5\times}))}

Eq. 1 in ViLD (2104.13921v3).

  • I: the image; \tilde{r}: one proposal box, computed offline.
  • \text{crop}(I, \tilde{r}_{1\times}): the box itself; \tilde{r}_{1.5\times}: the same box enlarged for context. Each crop is resized to 224x224.
  • \mathcal{V}: CLIP's frozen image encoder (ViT-B/32). The two embeddings are summed into \mathbf{v}.
  • \mathbf{v}/\|\mathbf{v}\|: the sum rescaled to unit length, a point on the sphere in the figure (the small faded blue points).

It works. On LVIS, CLIP on cropped proposals, combined with the RPN objectness score, reaches 18.9 APr (mask AP, ViLD Table 3), with no rare-class label at all; CLIP alone scores 13.0 (ViLD Table 2). But every proposal is a separate CLIP forward pass, and the paper reports the runtime of this R-CNN-style method as 630x that of a Mask R-CNN-style detector. CLIP's scores also ignore box quality: it often gives its highest score to a box that covers only part of an object (ViLD App. B), so the paper combines them with the RPN's objectness. ViLD's aim is to keep CLIP's knowledge and drop the per-box cost.

ViLD-text: the class rows become CLIP text vectors

First, replace the classifier. ViLD-text drops the learned matrix W and uses CLIP text embeddings of the 866 base class names as the class rows. Each name fills 63 prompt templates, such as a photo of {category} in the scene, and the template embeddings are averaged. A projection layer resizes the region embedding to the text width. One row stays learned: background. The word "background" does not describe the clutter in unmatched proposals, so ViLD gives background its own trainable vector \mathbf{e}_{bg}:

\begin{aligned} &\htmlData{step=1, link=regions}{\htmlClass{t-blue}{\mathbf{e}_r} = \mathcal{R}(\phi(I), r)} \\ &\htmlData{step=2, link=background text}{\mathbf{z}(r) = \begin{bmatrix} \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-brown}{\mathbf{e}_{bg}}), & \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-yellow}{\mathbf{t}_1}), & \cdots, & \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-yellow}{\mathbf{t}_{|C_B|}}) \end{bmatrix}} \\ &\htmlData{step=3, link=text}{\htmlClass{t-red}{\mathcal{L}_{\text{ViLD-text}}} = \frac{1}{N}\sum_{r \in P}\mathcal{L}_\text{CE}\Big(\operatorname{softmax}\big(\mathbf{z}(r) / \tau \big), y_r \Big)} \end{aligned}

Eq. 2 in ViLD (2104.13921v3). The first two lines are definitions; the number belongs to the loss.

  • \phi(I): the backbone features; r: one proposal from the online RPN, out of the set P, with N = |P| per image (the paper does not give N).
  • \mathcal{R}: the region head with its projection layer; \htmlClass{t-blue}{\mathbf{e}_r}: the region embedding, a blue point in the figure.
  • \mathrm{sim}(\mathbf{a}, \mathbf{b}) = \mathbf{a}^\top \mathbf{b} / (\|\mathbf{a}\|\|\mathbf{b}\|): cosine similarity.
  • \htmlClass{t-yellow}{\mathbf{t}_i}: the stored CLIP text embedding of base class i, one of |C_B| = 866. \htmlClass{t-brown}{\mathbf{e}_{bg}}: the learned background row.
  • \tau = 0.01: the temperature. Cosines lie between -1 and 1; dividing by it stretches the logits enough for a confident softmax.
  • y_r: the base class of the labelled box that r matches, or background if it matches none. \mathcal{L}_\text{CE}: cross-entropy.

This is chapter 1's idea applied to a two-stage detector, and it already transfers: 10.1 APr. But the loss only ever sees base classes. Look at y_r: a proposal on an unlabelled forklift gets the label background, and the loss pushes it toward \mathbf{e}_{bg}, as the figure shows.

ViLD-image: copy CLIP's view of each proposal

The second loss needs no labels. Before training, ViLD stores the CLIP embeddings (Eq. 1) of M proposals per training image. During training, the detector's region embedding for each of those boxes must match the stored vector:

\htmlData{step=3, link=regions}{\htmlClass{t-red}{\mathcal{L}_{\text{ViLD-image}}} = \frac{1}{M} \sum_{\tilde{r} \in \widetilde{P}} \|} \htmlData{step=1, link=image}{\htmlClass{t-blue}{\mathcal{V}(\text{crop}(I, \tilde{r}_{\{1\times, 1.5\times\}}))}} - \htmlData{step=2, link=regions}{\htmlClass{t-blue}{\mathcal{R}(\phi(I), \tilde{r})}} \htmlData{step=3, link=regions}{\|_1}

Eq. 3 in ViLD (2104.13921v3).

  • \widetilde{P}: the M offline boxes of this image, from a first-stage RPN trained on base classes (the paper does not give M).
  • The first term is the stored teacher vector from Eq. 1 (small faded blue point); the second is the student's region embedding for the same box (blue point).
  • \|\cdot\|_1: the sum of absolute differences, averaged over the M boxes. The paper's sweep found L1 better than L2 for rare classes (16.3 vs 13.7 APr at the same weight, Table 7).

Those boxes come from an RPN, and chapter 3 showed that an RPN boxes novel objects too. So the image loss reaches forklifts, which no label does. ViLD-image alone reaches 11.2 APr. Its weakness is the frequent classes, where it drops to 11.1 APf, because copying CLIP ignores the base labels.

Both losses, and an ensemble

The full loss adds the two:

\htmlClass{t-red}{\mathcal{L}_{\text{ViLD}}} = \htmlData{step=1, link=text}{\mathcal{L}_{\text{ViLD-text}}} + \htmlData{step=2, link=image}{w \cdot \mathcal{L}_{\text{ViLD-image}}}

Eq. 4 in ViLD (2104.13921v3).

  • w: the weight of distillation, 0.5 for the ResNet-50 model.

The two terms pull the same region embedding in two directions, as Both losses shows: toward its class name and toward CLIP's view of its crop. The paper's sweep (Table 7, a shorter schedule of 84,375 iterations) shows the trade. Raising w from 0.05 to 1.0 lifts APr from 12.9 to 17.3 and drops APf from 31.7 to 25.1.

ViLD-ensemble removes the tug of war. It trains two heads of the same shape, one per loss, and mixes their class scores with a weighted geometric mean:

p_{i, \text{ensemble}} = \begin{cases} \htmlData{step=1, link=text}{p_{i, \text{ViLD-text}}^\lambda \cdot p_{i, \text{cls}}^{(1-\lambda)} \quad \text{if } i \in C_B} \\ \htmlData{step=2, link=novel}{p_{i, \text{ViLD-text}}^{(1-\lambda)} \cdot p_{i, \text{cls}}^\lambda \quad \text{if } i \in C_N} \end{cases}

Eq. 5 in ViLD (2104.13921v3).

  • p_{i, \text{ViLD-text}}: the score for class i from the head trained with Eq. 2.
  • p_{i, \text{cls}}: in ViLD-ensemble, the score from the head trained with Eq. 3. (The paper first defines it as CLIP's own score on the crop, which brings back the slow per-box pass.)
  • \lambda = 2/3: base classes C_B trust the text-trained head more, novel classes C_N trust the distilled head more.

Read the table in three steps. The text rows matter: CLIP text gives 10.1 APr where GloVe word vectors, learned from text alone, give 3.0. Distillation is what reaches the rare classes: ViLD is 6.0 APr above ViLD-text and 3.8 above a supervised model that saw the rare labels and oversampled their images (repeat factor sampling, RFS). And distillation costs the frequent classes: APf falls from 32.5 to 28.3.

CLIP on crops stays best on rare classes, at its 630x runtime. A stronger teacher closes that gap: with ALIGN as the teacher and an EfficientNet-b7 backbone, ViLD-ensemble reaches 26.3 APr (same table, mask AP).

Three branches

OVR-CNN (Zareian et al., first posted 2020-11-20) came before CLIP and set up the task. It pretrains a ResNet and a vision-to-language projection on image captions, grounding caption words to image regions, with frozen BERT word embeddings. The detector then uses that projection and the word embeddings as a fixed classifier, with a fixed all-zero background vector where ViLD learns \mathbf{e}_{bg}. On COCO's 48 base and 17 novel classes it reaches 22.8 box AP50 on the novel classes in the generalized setting (base and novel classes scored together), the number that ViLD's Table 4 compares against.

RegionCLIP (Zhong et al., 2021-12-16) pretrains on region-text pairs instead of distilling into a detector. It parses 6,790 concepts from CC3M captions, proposes regions with an RPN, lets CLIP pick the best concept for each region as a pseudo-label, and trains a region-level image encoder, initialized from CLIP, on those pairs. That encoder becomes the detector's backbone, again with an all-zero background. Its LVIS APr is 17.1 with ResNet-50 and 22.0 with ResNet-50x4. These are box AP (our reading: the ViLD rows in its table equal ViLD's box AP), so the fair ViLD number is 16.3 box APr (ViLD Table 8), not the mask 16.1; the detectors and schedules also differ.

Detic (Zhou et al., 2022-01-07) keeps the ViLD-text classifier and adds image-level labels. For an ImageNet image labelled "x", it applies the label to the largest proposal and trains only the classifier on it. No prediction decides which box gets the label: the largest proposal covers the target object in 92.8% of an annotated sample, against 69.0% for a prediction-based choice. In ViLD's own setting (Mask R-CNN ResNet-50, trained from scratch on LVIS base classes) and with IN-L, the 997 ImageNet-21K classes that overlap LVIS, Detic reaches 17.8 mask APr against ViLD's 16.1, a like-for-like comparison (Detic Table 2).
