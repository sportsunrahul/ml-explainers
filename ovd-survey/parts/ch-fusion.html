Deep fusion: words change what the image encoder sees

Where text enters here: the cross-attention inside each DyHead module, before the score.

In late fusion, the image encoder never sees the prompt. The box features are the same whatever you ask, and text meets image only in the final dot product. GLIP adds cross-attention between the image and text features in the last encoder layers, so the image features become a function of the prompt.

Guess first. In late fusion, part of the "stingray" score leaks onto the fish, because the word alone does not say what a stingray looks like. Can a better dot product at the very end remove the leak, or must the image features themselves change? Decide, then press Deep fusion.

The features must change. In deep mode, each region takes in the words that it matches best, and each word takes in the regions that match it. After a few layers, the stingray regions look more like "stingray" and the fish look more like "fish", and the leak shrinks layer by layer. In late mode nothing moves, because the image side never reads the prompt. The text side changes too: watch the five bars of the token vector in deep mode.

The fusion equations, term by term

GLIP's image encoder ends in L DyHead modules, and its text encoder BERT gets newly added layers on top, one per fusion step in Eq. 6, so L of them (our reading; the paper and config never state the count). Before each pair of modules, a cross-modal attention block (X-MHA) computes a context vector for each side from the other side. Each side adds its context and runs its own module (Sec. 3.2):

\begin{aligned} &\htmlData{step=1, link=xmha}{\htmlClass{t-yellow}{O^i_{\rm t2i}},\ \htmlClass{t-blue}{P^i_{\rm i2t}} = \text{X-MHA}(\htmlClass{t-blue}{O^i}, \htmlClass{t-yellow}{P^i}), \quad i \in \{0, 1, \dots, L-1\}} \\ &\htmlData{step=2, link=image t2i}{\htmlClass{t-blue}{O^{i+1}} = \text{DyHeadModule}(\htmlClass{t-blue}{O^i} + \htmlClass{t-yellow}{O^i_{\rm t2i}}), \quad \htmlClass{t-blue}{O} = \htmlClass{t-blue}{O^{L}}} \\ &\htmlData{step=3, link=text i2t}{\htmlClass{t-yellow}{P^{i+1}} = \text{BERTLayer}(\htmlClass{t-yellow}{P^i} + \htmlClass{t-blue}{P^i_{\rm i2t}}), \quad \htmlClass{t-yellow}{P} = \htmlClass{t-yellow}{P^{L}}} \end{aligned}

Eq. 4 to 6 in GLIP (2112.03857v2). The paper prints the two context terms in red; here each takes the color of the side it carries information from, because red means loss on this page.

  • \htmlClass{t-blue}{O^i}: the image features entering module i; \htmlClass{t-blue}{O^0} comes from the vision backbone. \htmlClass{t-yellow}{P^i}: the token features; \htmlClass{t-yellow}{P^0} comes from BERT.
  • \htmlClass{t-yellow}{O^i_{\rm t2i}}: text-to-image context, what each region reads from the tokens. \htmlClass{t-blue}{P^i_{\rm i2t}}: image-to-text context, what each token reads from the regions.
  • L: the number of DyHead modules. \text{BERTLayer}: the newly added BERT layers on top of the pre-trained BERT.
  • Delete the two context terms and the model is late fusion (the paper's words): the same encoders, scored only by O P^{\top} at the end. That is GLIP-T (A) in the table of chapter 7.

Inside X-MHA, one score matrix serves both directions. Each head projects the image and text features, takes their scaled dot products, and normalizes them one way for the image side and the other way for the text side:

\begin{aligned} &\htmlData{step=1, link=attn}{O^{(q)} = O W^{(q,I)},\ \ P^{(q)} = P W^{(q,L)},\ \ Attn = O^{(q)} (P^{(q)})^{\top} / \sqrt{d}} \\ &\htmlData{step=2, link=t2i}{P^{(v)} = P W^{(v,L)},\ \ \htmlClass{t-yellow}{O_{\rm t2i}} = \mathrm{SoftMax}(Attn)\, P^{(v)} W^{(out,I)}} \\ &\htmlData{step=3, link=i2t}{O^{(v)} = O W^{(v,I)},\ \ \htmlClass{t-blue}{P_{\rm i2t}} = \mathrm{SoftMax}(Attn^{\top})\, O^{(v)} W^{(out,L)}} \end{aligned}

The X-MHA block of GLIP Sec. 3.2 (unnumbered in the paper).

  • W^{(q,\cdot)}, W^{(v,\cdot)}, W^{(out,\cdot)}: learned query, value and output projections, one set per side (I image, L language). There is no separate key projection.
  • Attn: one region-by-token matrix. \mathrm{SoftMax}(Attn) normalizes over the tokens for each region, and \mathrm{SoftMax}(Attn^{\top}) over the regions for each token (our reading: the paper does not state the axis). The yellow dots that light up in the figure are the first one for the chosen word.
  • d: the feature width of the attention.

GLIP Table 8. COCO: box AP on 2017val (domain transfer, see chapter 7). ODinW-13: GLIP's average AP over its 13 ODinW datasets, zero-shot or after full-model tuning on all the training data. Chapter 12 uses a larger ODinW average from other papers; the two are not comparable.

With grounding data, deep fusion lifts zero-shot ODinW-13 from 35.5 to 44.4. The gain is a zero-shot gain. With all the downstream training data, the order flips a little: full tuning scores slightly higher without fusion in both pairs. On LVIS the effect is mixed (App. D.2).

The price is speed. GLIP-T runs at 4.84 frames per second without fusion and 2.52 with it, and inference memory grows from 1.0 to 2.4 GB (Table 7: one P100 GPU, batch 1, one prompt per image). Without fusion, the text embeddings of a prompt can be cached, so the model costs the same as a plain DyHead (App. D.1). With fusion, the fusion layers must run again for every new pair of image and prompt; the backbone and BERT still run once each (our reading: neither depends on the other side before fusion). This is the argument OWL-ViT makes against fusion in chapter 5: a late-fusion model can score thousands of text queries against one image almost for free.

Prompt tuning works only with deep fusion

Claim
Training only the prompt embedding P^0 adapts a deep-fusion model almost as well as full training, but not a late-fusion model.
Measured
ODinW-13 average AP with all the training data. Prompt tuning computes P^0 once with BERT, discards BERT, and trains only P^0; linear probing trains the box head and a projection; full tuning trains everything (GLIP Sec. 5.2, Tables 11 to 13).
Result
GLIP-T (A), late fusion: prompt tuning 43.3, linear probing 44.1, full tuning 63.6. GLIP-T, deep fusion: prompt tuning 62.4, full tuning 64.9.
Would falsify
A late-fusion model whose prompt tuning came close to full tuning, or a deep-fusion model where it did not.

Why the difference? In late fusion, P^0 only sets the classifier rows, so tuning it is about as strong as retraining a linear classifier, and that is what the numbers show. In deep fusion, P^0 flows through every X-MHA into the image features, so tuning the prompt also changes what the image side computes (our reading; GLIPv2 says the same of its own prompt tuning).

Words matter: hand-written prompts

A model that reads the prompt this closely should respond to better wording. Two lessons. First, describing the look can matter more than any change to the model: Mushrooms goes from 13.6 to 73.8 when the variety names become plain descriptions. Second, it is not reliable: the Pothole sentence changed nothing. Chapter 13 returns to this: on rare industrial parts, the name is often where the detector fails.
