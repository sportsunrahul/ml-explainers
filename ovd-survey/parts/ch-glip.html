Act IVDetection as grounding (2021-2023)

GLIP: a detector is a grounding model

Where text enters GLIP: at the score, where every box meets every token of the prompt, and in the last encoder layers (chapter 8).

Chapter 1 replaced the class rows with text vectors, one vector per class name. GLIP (Li et al., CVPR 2022) writes all the class names into one sentence, person. bicycle. car., and scores every box against every token of that sentence. Detection then becomes phrase grounding: find the box that each phrase of a caption refers to.

Guess first. toothbrush is in the prompt, but no box shows one. Which cells in its two columns become positive targets? Decide, then press Target: toothbrush.

None of them. Both subword tokens are negative targets for every box. This detail makes a prompt work as a classifier: a class name with no object in the image teaches the model to say no. The forklift row is the mirror case. The box is there, but no phrase names it, so for this prompt it is background.

From phrases to tokens

A classifier has one column per class. A text encoder does not see classes; it sees tokens, and a prompt has more tokens than phrases. GLIP gives four reasons (Sec. 3.1):

  • a phrase can have several words, such as "traffic light" (the toy uses "traffic cone");
  • the tokenizer splits some words into subwords: "toothbrush" becomes "tooth#" and "#brush";
  • the language model adds tokens of its own, such as separators and special tokens;
  • GLIP appends one [NoObj] token at the end of the sequence.

So the score matrix has M token columns, with M larger than the number of classes c, but the detection labels give a target with c columns. GLIP widens the target to the token level:

\begin{gathered} \htmlData{step=1, link=scores}{\htmlClass{t-green}{S_{\rm ground}} = \htmlClass{t-blue}{O}\,\htmlClass{t-yellow}{P}^{\top} \in \mathbb{R}^{N\times M}} \\[4pt] \htmlData{step=2, link=targets}{T \in \{0,1\}^{N\times c} \;\longrightarrow\; \htmlClass{t-green}{T'} \in \{0,1\}^{N\times M}, \qquad \htmlClass{t-green}{T'_{ij}} = \begin{cases} T_{ik} & \text{token } j \text{ belongs to phrase } k \\ 0 & \text{token } j \text{ is an added token} \end{cases}} \\[4pt] \htmlData{step=3, link=loss}{\htmlClass{t-red}{\mathcal{L}_{\rm cls}} = \mathrm{loss}(\htmlClass{t-green}{S_{\rm ground}};\, \htmlClass{t-green}{T'})} \end{gathered}

Eq. 3 in GLIP (2112.03857v2), then the target expansion of Sec. 3.1, which the paper states in words; the case notation is ours.

  • \htmlClass{t-blue}{O}: one feature row per N boxes (regions). \htmlClass{t-yellow}{P}: one feature row per token of the prompt, M rows.
  • \htmlClass{t-green}{S_{\rm ground}}: every box against every token, the matrix in the figure.
  • T: the detection label, which class each box is. \htmlClass{t-green}{T'}: the same label copied to every token of that class's phrase; added tokens are 0 for every box.
  • \htmlClass{t-red}{\mathcal{L}_{\rm cls}}: a focal sigmoid loss over every cell, the loss of a one-stage detector. Only the target got wider.

At test time, each phrase needs one score. GLIP averages the token probabilities of the phrase (Sec. 3.1):

\htmlData{step=1, link=phrase}{p(\text{box } i,\ \text{phrase } k) = \frac{1}{|k|}\sum_{j \in k} \sigma\!\left(\htmlClass{t-green}{S_{{\rm ground},\,ij}}\right)}

The inference rule of GLIP Sec. 3.1, written as a formula (our notation).

  • |k|: the number of tokens in phrase k; \sigma: the sigmoid. The cone box in the figure shows the arithmetic.

Does the rewrite cost accuracy? GLIP tested it on COCO with all 80 class names in one prompt. The same DyHead detector with a Swin-T backbone scores 49.4 AP on COCO val2017 both as a detector and as a grounding model (App. B).

The prompt has a budget. BERT can read 512 tokens, and GLIP limits the prompt to 256. Objects365 has 365 classes, too many for one prompt, so in pre-training each prompt holds at most 85 category names: every class present in the image, plus random absent classes as negatives (App. C.1). On LVIS, GLIP splits the 1,203 categories into prompts of 40 and runs the model once per prompt (App. C.2). The format matters too: with BERT as the text encoder, person. bicycle. car. works better than the friendlier Detect: person, bicycle, car. The paper gives no number for this.

Any captioned box is now training data

Once detection is grounding, three kinds of data train one model with one loss. Detection labels become prompts of class names. Human grounding data gives a caption with a box for each phrase. Web image-caption pairs get boxes from a teacher model. The vocabulary grows by orders of magnitude. The largest detection datasets have no more than 2,000 categories. The gold grounding data has 44,518 unique phrases in Flickr30K and 110,689 in VG Caption (Sec. 3.3).

The web data comes from self-training. A GLIP trained on gold data is the teacher. A language parser finds the noun phrases in each caption, and the teacher boxes them. The student trains on the gold data plus these pseudo labels. On the 24M web pairs of GLIP-L, the teacher kept 78.1M phrase-box pairs with confidence above 0.5, which cover 58.4M unique noun phrases (Sec. 1).

What the zero-shot numbers mean

Two of GLIP's headline tests are not open-vocabulary in ViLD's sense, so read them with care.

COCO is domain transfer. GLIP-L reaches 49.8 AP on COCO 2017val without COCO training (Table 2). But Objects365 contains all 80 COCO classes (Sec. 4.1), so the test changes the images, not the classes; the paper calls it zero-shot domain transfer. A plain DyHead-T trained on Objects365, with its outputs restricted to COCO's classes, already scores 43.6.

LVIS holds nothing out. GLIP-L scores 28.2 APr and 37.3 AP on LVIS minival, and 17.1 APr and 26.9 AP on LVIS val v1.0 (Table 3, box AP, our reading). our reading: no LVIS category was removed from pre-training (the paper describes no filtering), and the checkpoint was chosen by its minival score (App. C.2). ViLD's numbers in chapter 4 are mask AP with the rare classes held out. Do not set the two side by side as equals.

Branches

MDETR: the grounding ancestor

MDETR (Kamath et al., 2104.12763v2) came first. It is DETR whose encoder reads the image features and the RoBERTa token features as one joined sequence. Each matched query predicts which tokens its box refers to, and a contrastive loss pulls query and token embeddings together. GLIP says its token-level target follows MDETR (Sec. 3.1). MDETR trained on 1.3M aligned image-text pairs. It cannot be tested zero-shot: every training text has a box, which biases the model "to always predict boxes for a given text" (Sec. 3.2.1). On LVIS it asks for one class name per forward pass, about 10s per image on a GPU. GLIP's detection prompts list absent classes, so its model learns to answer "no box" (our reading).

GLIPv2: more negatives, same tap

GLIPv2 (2206.05836v2) keeps GLIP's architecture, so text still enters at the fusion layers. It changes the loss: it adds negatives from the other images in the batch, scored on the features before fusion, and a masked-language loss on the text. At the Tiny size, zero-shot ODinW-13 (the average AP over GLIP's 13 ODinW datasets) goes from 46.5 to 48.5, and LVIS minival AP from 26.0 to 29.0 (GLIPv2 Table 2).
