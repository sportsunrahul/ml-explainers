Act VIWhen words run out

Show, do not tell: visual prompts

Every detector so far needs a name. Some factory parts have no name that a web-trained text encoder knows, so this chapter draws a box around one example and uses the box as the prompt.

Where the prompt enters: T-Rex2, the main model of this chapter, is a late-fusion model. A name or a box picks the decoder's starting queries and becomes a classifier row; the image encoder never sees the prompt (T-Rex2 Sec. 3.4).

Guess first. The name bracket finds the angle bracket, which is what the word means on the web, and misses the odd parts. Before you press Box prompt, look at odd part 3: it is dark and turned on its side. Will one box on odd part 1 find it?

It does not. The box finds odd part 2, which looks like the example, and odd part 3 stays below the line. One example shows one look. Press Both, averaged: the name adds what all brackets share, odd part 3 crosses the line, and the angle bracket rises a little. Now click washer 1 and try the three modes again. For a part with a good name, the name alone is best, and the box only narrows it.

The first box prompt: an image as the query

Chapter 5 met this idea already. OWL-ViT scores every image token against a query embedding, and the query does not have to come from text. Give it a reference image with a box, and it runs its image tower on that image. Among the predicted boxes that overlap the query box with an IoU above 0.65, it keeps the embedding that is most unlike the others, because one foreground embedding stands out from many similar background ones. In about 10% of cases no predicted box overlaps enough, and it falls back to a generic text query (App. A1.7).

On COCO classes held out from training, this one-shot query reached 41.8 AP50, against 24.3 for AIT, the best earlier one-shot detector (Table 2: means over four class splits, each split averaged over three runs). That model is a hybrid of ResNet-50 and ViT-H/32 at 960 pixels, not the CLIP L/14 model of chapter 5. With ten example images averaged per class, it reached 46.8. The paper's Fig. 2 shows why this matters: the text query "luna moth" finds nothing, and an image of the moth as the query finds it.

T-Rex2: names and boxes in one space

T-Rex2 (2024) builds both kinds of prompt into one detector. Its body is DINO, a DETR-style detector with deformable attention and denoising queries (recap in the DETR family explainer), plus the language-guided query selection of Grounding DINO from chapter 9. A Swin backbone and 6 encoder layers make multi-scale image features. Two prompt encoders feed one classifier.

The text side is simple. A CLIP-B text encoder turns each category name or short phrase into one vector \htmlClass{t-yellow}{T}. T-Rex2 fine-tunes this encoder, at the learning rate of the backbone, 1e-5.

The box side needs more work, because a box is four numbers, not a picture. T-Rex2 turns each of the K boxes (or points) into a fixed sine-cosine position code, and a linear layer maps the code to the model width D (Eq. 1 and 2). Each box also gets a learned content vector, and one extra global query stands for the whole class (Eq. 3). Then each query looks at the image around its own box:

\htmlData{step=1, link=exemplar}{Q'_j = \operatorname{MSDeformAttn}(Q_j,\ \htmlClass{t-yellow}{b_j},} \htmlData{step=2, link=features}{\{\htmlClass{t-blue}{\boldsymbol{f}_i}\}_{i=1}^L)}, \qquad \htmlData{step=3, link=visual}{\htmlClass{t-blue}{V}=\operatorname{FFN}(\operatorname{SelfAttn}(Q'))[-1]}

Box case of Eq. 4, and Eq. 5, in T-Rex2 (2403.14610v1). The point case puts the point p_j in place of b_j.

  • Q_j: the query of the j-th box, its position code joined with the learned content vector.
  • \htmlClass{t-yellow}{b_j}: the user's box, (x, y, w, h) normalized. It is the reference location, so the query reads features near it.
  • \htmlClass{t-blue}{\boldsymbol{f}_i}: the encoder's feature map at scale i, for L scales.
  • \operatorname{MSDeformAttn}: multi-scale deformable attention. Each query reads a few learned sampling points near its box instead of the whole image. The encoder stacks 3 such layers.
  • \htmlClass{t-blue}{V}: after self-attention among the K+1 queries and a feed-forward layer (hidden width 1024), the output of the global query (index -1, the last one) is the visual prompt embedding: one vector per class per image.

From here on, a box prompt and a name are the same kind of object. Both become a row of the classifier, which is the swap this page started with in chapter 1:

\htmlData{step=1, link=scores}{\htmlClass{t-green}{\operatorname{Label}}} = \htmlData{step=2, link=visual}{\htmlClass{t-blue}{V}} \cdot \htmlData{step=3, link=regions}{Q_{dec}^T} : \mathbb{R}^{C \times D} \times \mathbb{R}^{D \times N} \rightarrow \mathbb{R}^{C \times N}

Eq. 8 in T-Rex2 (2403.14610v1). A text prompt uses \htmlClass{t-yellow}{T} in place of \htmlClass{t-blue}{V}.

  • \htmlClass{t-blue}{V}: the prompt embeddings, one row per class, C \times D. The paper does not state D.
  • Q_{dec}: the features of the decoder's N queries, one per candidate box. The top 900 encoder tokens by similarity to the prompts set their starting boxes.
  • \htmlClass{t-green}{\operatorname{Label}}: every candidate box scored against every prompt, C \times N. In the toy, these are the score bars.

Training alternates between the two prompt types: one iteration uses names, the next uses boxes. In a box iteration the prompts come from the training image itself. For each category, the model takes one to all of its ground-truth boxes, and with a 50% chance it turns them into center points (Sec. 3.3). A contrastive loss ties the two prompt types together. For the K prompted regions of an image, it pulls each region's visual embedding toward the text embedding of its class and away from the other classes' text:

\htmlData{step=1, link=align}{\htmlClass{t-red}{\mathcal{L}_{align}} = -\frac{1}{K} \sum_{i=1}^K \log} \frac{\exp(\htmlData{step=2, link=visual}{\htmlClass{t-blue}{v_i}} \cdot \htmlData{step=3, link=text}{\htmlClass{t-yellow}{t_i}})}{\sum_{j=1}^K \exp(\htmlClass{t-blue}{v_i} \cdot \htmlClass{t-yellow}{t_j})}

Eq. 9 in T-Rex2 (2403.14610v1).

  • \htmlClass{t-blue}{v_i}: the visual prompt embedding of region i.
  • \htmlClass{t-yellow}{t_i}: the text embedding of the class name of region i; the \htmlClass{t-yellow}{t_j} are the class names of the other regions in the same image.
  • \htmlClass{t-red}{\mathcal{L}_{align}}: a softmax over the K text embeddings, in one direction (visual to text), with no temperature written. The paper calls it a mutual distillation (Sec. 3.2). Without it, the two embeddings of one class sit apart, and the name prompts score lower (Table 4).

Once trained, a class can be prompted three ways: with the name only, with boxes only, or with both. With boxes only, the generic mode (Visual-G) averages the visual embeddings of n example boxes, each from a different image (Eq. 11). With both, it averages the two vectors (Eq. 12):

\htmlData{step=1, link=visual}{\htmlClass{t-blue}{V} = \frac{1}{n} \sum_{i=1}^{n} V_i}, \qquad \htmlData{step=2, link=mixed}{P_{\text{mixed}} = \frac{\htmlClass{t-yellow}{T} + \htmlClass{t-blue}{V}}{2}}

Eq. 11 and 12 in T-Rex2 (2403.14610v1).

  • V_i: the visual embedding from example image i, for n examples. The paper's default is 16.
  • P_{\text{mixed}}: the average of the name's vector and the box vector. It takes the place of \htmlClass{t-blue}{V} in Eq. 8, as in the toy's Both mode.

What the benchmarks say

Read T-Rex2's box-prompt numbers with their setting in mind. Visual-G takes 16 images per class from each benchmark's training split, with one labelled box each, and averages their embeddings (Sec. 4.3). The weights do not change, so the paper calls the result zero-shot. our reading It is zero-shot for the weights, but it uses 16 labelled examples per class that a name never sees, so it is closer to a few-shot method than to a text prompt. With one example instead, Visual-G scores 29.2 AP on COCO, against 45.8 for the names (Swin-T, Tables 5 and 1).

The left panel holds T-Rex2's headline claim: names for common classes, boxes for rare ones. On LVIS val, Visual-G beats the names on the rare classes, 32.4 against 29.0 APr, and a per-class count agrees: the box wins on 253 rare classes and the name on 84 (Fig. 4). On LVIS minival the same model flips: names 37.4, boxes 29.9. Swin-L flips the same way (val 43.8 for boxes against 42.7 for names; minival 45.4 against 49.2). The two splits are not comparable: val has 337 rare classes and minival only 70.

Part of the val gap comes from the names getting worse, not from the boxes getting better. A T-Rex2 trained on text alone scores 32.1 APr on LVIS val with names; joint training brings its names down to 29.0 (Table 4). So the text-only model's names nearly match the joint model's boxes.

Away from LVIS, T-Rex2's boxes win clearly. On ODinW-35 the median dataset rises from 4.7 AP with names to 17.5 with boxes. On the original Roboflow100, the mean rises from 8.2 to 17.4 (Swin-L: 10.5 to 18.5). our reading These collections are full of class names that a web-trained model does not know, so labelled examples help more there than on LVIS.

The middle and right panels test a different visual-prompt model on different benchmarks; neither paper tests T-Rex2. Both use MQ-GLIP, which adds MQ-Det's image-prompt module to a frozen GLIP and takes 10 examples per class in context, with no training. In RF100-VL, images alone scored 6.4 AP over 100 datasets, against 12.2 for the class names; on its 22 industrial datasets, 3.9 against 7.8. In FSOD-VLM on nuImages, the rarest classes (the Few cohort) scored 3.34 AP with images and 8.41 with names. For this model, the rarest classes are where images alone did worst.

Adding the name back helps or changes nothing. Names plus images give 12.2 in RF100-VL, the same as names alone, and 10.26 on the nuImages Few cohort, above both single prompts (over all 18 classes: 21.42 against 17.01 for names and 14.07 for images). T-Rex2 shows the same gain on LVIS val rare classes (34.3 APr for both) and a loss on COCO, where both scores 42.5 AP and names alone 45.8. The paper says so itself: visual prompts "may sometimes interfere with text prompts, especially in scenarios involving common objects" (Sec. 5).

our reading "Box prompts help" is a property of a model and a benchmark, not of boxes. T-Rex2 trains its box encoder on 2.4M labelled images plus 0.65M pseudo-labelled ones; MQ-GLIP adds a small module to a frozen detector. Before you trust box prompts for a factory part, test the model you will deploy on your own parts, against a name and against a short fine-tune.

Box prompts now also reach real-time detectors. YOLOE (ICCV 2025), whose design roadmap starts from YOLO-World (chapter 10), keeps one classifier: a dot product between each anchor's object embedding and a prompt embedding. Only the way it makes the prompt changes. A name goes through a small network that folds into the last convolution after training. A box or mask goes through a light two-branch encoder (SAVPE). With no prompt at all, one learned embedding fires on every object, and a built-in list of 4585 names labels it (LRPC). YOLOE also drops YOLO-World's text fusion in the neck, so names and boxes enter only at the classifier, as in T-Rex2.

So a box is a real answer when a part has no name, with two conditions: the model's box encoder must be good, and you need more than one example to cover how the part varies. Chapter 12 asks the next question: once you have ten labelled examples, should you prompt with them or fine-tune on them?
