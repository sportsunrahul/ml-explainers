Grounding DINO: DINO-DETR that reads

Where text enters Grounding DINO: in the encoder (a feature enhancer), in the choice of the decoder's starting boxes, in every decoder layer, and at the final score.

GLIP let the prompt change the image features inside the encoder. Grounding DINO starts from DINO, a DETR-style detector, and lets the prompt in at two more places; the most visible one is that the prompt now chooses where the decoder starts to look.

Guess first. The prompt ladder names nothing in this warehouse, but query selection always keeps a fixed number of tokens. Before you press ladder, decide where those tokens will go, and what must then stop them from turning into false detections.

They land on the shelf, the thing that looks most like a ladder, with low scores. The selection has no "nothing here" answer: it keeps the top tokens whatever their scores are. Press 3 Decoder and the final score rejects every one of them. In a real model that last check can fail. The paper lists false positives, which it calls hallucination, as a limitation (Sec. 5), and a false box has to start from some selected token (our reading). Try traffic cone too: the cone covers only four tokens, so the remaining queries go to the next-best region.

DINO in one paragraph

Your DETR explainer built DINO step by step, so here is only the outline. DETR treats detection as set prediction: a fixed set of object queries reads the image through a transformer decoder, and each query outputs one box and one class (object queries). Deformable attention lets each query look at a few sampled points on several feature scales instead of at every pixel (Deformable DETR). DAB-DETR splits each query into a content part and a positional part, and makes the positional part an explicit anchor box (DAB-DETR). DINO adds denoising training and mixed query selection: the anchor boxes start from the encoder's best-scoring locations for this image, while the content part stays a learned vector (DN-DETR and DINO). Grounding DINO keeps all of this and adds text.

Text chooses the queries

In DINO, the encoder's class head ranks the image tokens, and the best tokens give the anchor boxes. A closed-set class head cannot rank tokens for a name it never learned. Grounding DINO ranks each image token by its best match with any token of the prompt (Sec. 3.2):

  • \htmlClass{t-yellow}{\mathbf{X}_{T}}: the text tokens after the enhancer, N_T \times d, with at most 256 tokens.
  • \htmlClass{t-blue}{\mathbf{X}_{I}}\htmlClass{t-yellow}{\mathbf{X}_{T}^{\intercal}}: every image token scored against every text token, N_I \times N_T.
  • \texttt{Max}^{(-1)}: the maximum along the last axis, the text axis. Each image token keeps its best match with any word: the heat in the figure.
  • \texttt{Top}_{N_q} and \mathbf{I}_{N_q}: the indices of the N_q = 900 hottest image tokens, the same query count as DINO.

The paper's Algorithm 1 writes the same thing in three lines of PyTorch (one variable name made consistent here):

logits = torch.einsum("bic,btc->bit", image_feat, text_feat)   # bs, num_img_tokens, num_text_tokens
logits_per_img_feat = logits.max(-1)[0]                        # bs, num_img_tokens
topk_idx = torch.topk(logits_per_img_feat, num_query, dim=1)[1]  # bs, num_query

The selected tokens fill only half of each query. Grounding DINO follows DINO's mixed query selection: the positional part, a dynamic anchor box, is "initialized with encoder outputs" at the selected tokens, and the content part is "set to be learnable" (Sec. 3.2). So the prompt decides where the queries start, not what they carry. The figure's query list shows this split. The paper's Fig. 7 shows the selected boxes move when only the prompt changes.

Three more places for text

Encoder fusion: the feature enhancer. Before any selection, the image and text features meet in a stack of feature enhancer layers, 6 of them (Sec. 3.1, Fig. 3). In each layer, the image tokens run deformable self-attention and the text tokens run ordinary self-attention; an image-to-text and a text-to-image cross-attention, "inspired by GLIP", exchange information between them; then each side has a feed-forward network (FFN). So the \htmlClass{t-blue}{\mathbf{X}_{I}} in Eq. 1 already depends on the prompt. Press 1 Encoder fusion to see each word reach into the image.

The cross-modality decoder. Each of the 6 decoder layers runs self-attention among the queries, a deformable cross-attention into the image tokens, a cross-attention into the text tokens, and an FFN (Sec. 3.3). In the paper's words, "each decoder layer has an extra text cross-attention layer compared with the DINO decoder layer". Each layer also refines the boxes, as in DINO.

The score. There is no class matrix at the end. As in GLIP (chapter 7), each output query takes a dot product with every text token, which gives one logit per token, and a phrase wins when its tokens light up (Sec. 3.5).

Sub-sentence prompts: names that do not talk to each other

For detection data, the category names are joined into one prompt, as in GLIP. BERT then lets every word attend to every other word, so "pallet" gets mixed with whatever names happen to share its prompt. During training the names are sampled at random for each image (App. B), so the same word would get a different feature in every prompt. Grounding DINO adds an attention mask that blocks attention between different category names (Sec. 3.4).

In the toy at word level, "pallet" spends about half of its attention on other names, so its feature changes when its neighbours change. With the mask, it sees only its own words, and its feature is the same in every prompt. A two-word name such as "traffic cone" still keeps one feature per word, which a single sentence-level vector, as in OWL-ViT, would lose. The paper calls this the sub-sentence level representation. Removing it costs the least of the four pieces in the table above.

The paper does freeze parts in one experiment (App. C.1, Table 9). It starts from a DINO already trained on O365, freezes "the modules co-existing in DINO and Grounding DINO", and trains only the new text and fusion parts. With Swin-T and O365 data, this reaches 17.9 zero-shot AP on LVIS minival, against 16.2 for the same model trained from scratch; COCO and ODinW come out about the same or slightly lower. A trained closed-set detector can learn to read with most of its weights fixed.

Read the table with four cautions.

  • Two different L models. The headline 52.5 COCO AP and the LVIS 33.9 and ODinW 26.1 come from different checkpoints. No single Grounding DINO L has all three numbers.
  • COCO "zero-shot" means no COCO images, not new names. O365 covers (approximately) all of COCO's categories; the paper even maps O365 categories to COCO to evaluate DINO the same way.
  • Rare classes go the other way. With the same data, Grounding DINO T beats GLIP-T on LVIS AP (27.4 against 26.0) but loses on the rare classes (APr 18.1 against 20.8). The paper suggests this "may be a characteristic limitation" of DETR-like models (Sec. 4.2). Its LVIS numbers are on MDETR's minival, and it does not say whether it uses the fixed-AP protocol that later papers use, so do not set them beside other papers' LVIS columns.
  • The ODinW mean hides a long tail. The paper's ODinW numbers average 35 datasets (we recomputed them from its per-dataset Tables 12 to 14). The medians are much lower: 9.5, 11.9 and 18.4 for the three rows above. Half of these small, real-world datasets score below that. Chapter 12 looks at them one by one.
