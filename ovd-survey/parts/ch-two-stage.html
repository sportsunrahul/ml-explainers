How a two-stage detector finds boxes

The first open-vocabulary detectors were built on a two-stage detector, so this chapter builds one from scratch. The first stage finds boxes without asking what is in them; the second stage crops each box and names it.

Guess first. Suppose this network learned objectness from labelled boxes of people, pallets and cones. In its training images, forklifts were never labelled, so they counted as background. Before you press 3 Objectness, decide: does the forklift light up?

In the toy it does, a little dimmer than the others. The toy assumes that answer, so do not trust it yet; ViLD measured it, and the table at the end of this chapter has the real result. First, the machinery.

Stage one: a grid of features

A backbone network turns the image into a grid. Each cell holds a vector of numbers, its channels, that describes the patch of the image under it. The grid is coarse: one cell covers a square of many pixels, and the side of that square is the stride. ViLD uses a ResNet backbone with a feature pyramid network (FPN), which outputs several grids at different strides, so small objects get a fine grid and large objects a coarse one. The figure shows one grid.

Anchors: boxes fixed in advance

At every cell the detector places the same small set of reference boxes, called anchors: some small, some large, some tall, some wide. An anchor is not a prediction. It is a starting point that the network will score and correct.

The region proposal network: is there an object here?

The region proposal network (RPN) is a small convolutional head that slides over the grid. For every anchor at every cell it outputs two things. The first is an objectness score: the probability that the anchor covers some object, of any kind. The second is four box deltas that move and resize the anchor: d_x, d_y shift its centre by a fraction of its width and height, and d_w, d_h scale its width and height by e^{d_w} and e^{d_h}.

In Faster R-CNN and Mask R-CNN, training labels each anchor by its overlap with the labelled boxes. An anchor that overlaps a labelled box well is a positive and gets that box as its regression target. An anchor that overlaps nothing is a negative. The class of the labelled box plays no part. This is the key fact for this act: the RPN learns what objects look like in general, not what they are called.

Top-k: from thousands of anchors to a short list

Most anchors score near zero. The detector applies the deltas, sorts all boxes by objectness, removes any box that overlaps a better-scoring box too much (non-maximum suppression, NMS), and keeps the top k. These survivors are the proposals. Move the slider in the figure: with too few proposals some objects are missed, and with many the list fills with fragments of background. The field grades this stage by recall: the share of real objects that at least one proposal covers.

Stage two: crop, then name

Each proposal now gets a small feature map of its own. RoIAlign cuts the proposal's rectangle out of the backbone grid and samples it on a fixed grid of bins, interpolating between cells, so the box edges need not fall on cell boundaries. The figure uses 7 x 7 bins; the size is a design choice of the detector. Every box, large or small, becomes a tensor of the same shape.

A region head, a few fully connected layers, turns that tensor into one region feature. From it, the head computes refined box deltas, a mask in Mask R-CNN, and the class scores. The class scores are where the closed list lives: they come from the matrix W of chapter 1, one row per training class plus background. ViLD makes the box and mask outputs class-agnostic, one box and one mask per proposal for all classes (ViLD Sec. 3.1), so only the class scores depend on names.

Proposals do not need names

Back to the guess. An RPN trained on base classes treats an unlabelled forklift as background. Does it then miss forklifts at test time? ViLD measured this on LVIS with a ResNet-50 Mask R-CNN. It trained one RPN on the 866 base classes and one on all classes, then measured how well each recovers objects of the 337 rare classes that the base-only RPN never saw labelled:

The base-only RPN is worse by about 2 AR at every budget (Sec. 4.2): it boxes almost as many forklifts as an RPN that was shown them. Detic finds the same pattern with a different detector and a different recall measure: rare-class recall at IoU 0.5 with a thousand proposals is 78.5 for a base-only RPN and 79.7 for one trained on all classes (CenterNet2, Detic App. A, Table 8(a)). The two tables measure different things, so compare within each, never across.

So the first stage already finds novel objects. They get lost in the second stage: the head has no row for them, and in training it learned to call them background. The next chapter fixes the second stage.
