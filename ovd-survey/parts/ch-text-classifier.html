The class list becomes a text encoder

A detector does two jobs: it puts a box around each object, and it gives each box a score for every class it knows. The second job ends in a short list of names that is fixed when you train the model, and everything on this page starts by replacing that list with a text encoder.

Guess first. The forklift box gets "background" because no row points its way. Before you press Add forklift, decide what must change on the image side of the network to fix this. Then press it.

Nothing on the image side changes. The box was always found; its feature was always there. Only a new row appeared, and the row came from a sentence instead of from training. That is the whole idea of open-vocabulary detection, and the rest of the page is about making it work.

The last layer is a list of names

Take any detector you have seen. A backbone turns the image into features, some machinery proposes boxes, and each box ends up as one feature vector. The classifier is then one matrix with one row per class. GLIP writes it this way (Sec. 3.1, Eq. 2 of v2):

\htmlData{step=1, link=regions}{\htmlClass{t-blue}{O} = \mathrm{Enc}_I(\text{image})}, \qquad \htmlData{step=2, link=rows}{\htmlClass{t-green}{S_{\rm cls}} = \htmlClass{t-blue}{O}\,W^{\top}}, \qquad \htmlData{step=3, link=scores}{\htmlClass{t-red}{\mathcal{L}_{\rm cls}} = \mathrm{loss}(\htmlClass{t-green}{S_{\rm cls}};\, T)}

Eq. 2 in GLIP (2112.03857v2). Bias terms are left out, as in the paper.

  • \htmlClass{t-blue}{O}: the box features, one row per box. With N boxes and feature width d, it is N \times d.
  • W: the classifier, one learned row per class, c \times d for c classes.
  • \htmlClass{t-green}{S_{\rm cls}}: every box scored against every class, N \times c. The best entry in a row names that box.
  • T: the targets, a 0/1 matrix that says which class each box should have; \htmlClass{t-red}{\mathcal{L}_{\rm cls}} pushes the scores toward it.

Read the shapes and the problem is plain. W has exactly c rows. A class that was not in the training labels has no row, and the only way to get one is to label images of it and train again.

Swap the rows for sentences

Your CLIP explainer (VLM survey, chapter 1) showed the other half of the trick. CLIP trains an image encoder and a text encoder together until a photo and its caption land close in one shared space. In that space, the text vector for a name points the same way as the images of that thing. So a text vector can do a classifier row's job.

Write the class names into a prompt, run the text encoder, and use its output where W was (GLIP Eq. 3):

\htmlData{step=1, link=text}{\htmlClass{t-yellow}{P} = \mathrm{Enc}_L(\text{prompt})}, \qquad \htmlData{step=2, link=text scores}{\htmlClass{t-green}{S_{\rm ground}} = \htmlClass{t-blue}{O}\,\htmlClass{t-yellow}{P}^{\top}}

Eq. 3 in GLIP (2112.03857v2).

  • \htmlClass{t-yellow}{P}: the text features, M \times d, one row per token of the prompt. It plays the role of W.
  • \htmlClass{t-green}{S_{\rm ground}}: every box scored against every token, N \times M. A new class is a new phrase in the prompt; no weight changes.

The text encoder must share a space with images; a language-only one is not enough. ViLD tested this directly. With CLIP's text encoder as the classifier, a detector trained only on the 866 base classes (frequent and common) reached 10.1 AP on the held-out rare classes; with GloVe word vectors, trained on text alone, it reached 3.0 (ViLD Table 3, ResNet-50, mask AP).

How the field measures "open"

The papers on this page share one test bed, LVIS, a dataset with 1,203 categories that is split by how often each class appears in training. The open-vocabulary protocol from ViLD trains on the 866 frequent and common classes, hides the labels of the 337 rare ones, and reports APr: average precision on the rare classes only. A high APr means the model names things that it never saw a box for.

You will meet two other tests. Zero-shot transfer evaluates on a dataset whose images the model never trained on, such as COCO. Object Detection in the Wild (ODinW) collects many small datasets from other domains, such as drone footage, aquariums and potholes. These three tests measure different things, and chapter 12 shows that only the last one looks like a factory.
