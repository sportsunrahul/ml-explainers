A detector used to know a fixed list of names. Give it a text encoder and the list becomes whatever you type. This tour follows that one change through five designs, then asks when typing a name can replace labelling data.

Where text enters

One change, five designs

A finds boxes and names them. The naming step ends in a fixed list of classes. In the warehouse on the stage, the detector finds the forklift, but its list has no row for it, so it calls the box background.

Replace the list with a text encoder and the forklift is one typed word away. Every model in this tour does that. They differ in where the text enters the network:

  • ViLD and OWL-ViT: only at the final score.
  • GLIP: also inside the encoder, so the image features depend on the prompt.
  • Grounding DINO: in the encoder, in the choice of queries, and in the decoder.
  • YOLO-World: in the neck, then folded into the weights before deployment.

The stage is a toy drawing; the scores on it are made up to show the mechanism. The strip at the bottom is the map for the rest of the tour.

Every open-vocabulary detector replaces the class list with text. The design question is how early the text gets in.

The class list becomes a text encoder

A new class is a new sentence

A list fixed at training time

Each box becomes a feature vector (blue point). The classifier is one learned row per class (grey arrow). A box's score for a class is how well its point lines up with that row. The forklift box lines up with nothing, so "background" wins.

Drag any point and watch its scores. To add a class to a closed-set detector you must label images of it and train again.

Rows that come from words

A , as CLIP learns it, puts a name's text vector where pictures of that thing land. So the text encoder's output can stand in for the learned rows. Nothing on the image side changes.

The language matters. In ViLD, CLIP's text vectors as the classifier gave 10.1 AP on held-out rare classes; GloVe word vectors, learned from text alone, gave 3.0 (ViLD Table 3).

Type a name

Type forklift and the text encoder adds a row. The forklift box now matches it. No image was labelled and no weight changed.

The field tests this on : train on 866 frequent and common classes, hide the labels of 337 rare ones, and score the rare ones only.

The image side was never the problem. The list of names was.

Find boxes first, then borrow CLIP's names

Two-stage detection and ViLD

The first stage boxes objects it cannot name

A two-stage first turns the image into a grid of features. At every grid cell it places a few fixed boxes, called anchors. A scores each anchor for "is there an object here?" and nudges it onto the object. The best boxes survive as proposals. Then cuts each proposal out of the feature grid, and a small head names it from a fixed list.

The forklift gets a box although no training label said "forklift": the network learned what objects look like, not what they are called. Then the head calls it background. ViLD measured the real effect: a proposal network trained without the rare classes recalls them only about 2 points worse (ViLD Table 1).

Swap the fixed list for CLIP text vectors

ViLD keeps the two-stage detector and replaces the head's class rows with CLIP text vectors of the 866 base class names (yellow), plus one learned background vector (brown). Each box becomes a region embedding (blue), scored by cosine against those rows in a . Training pulls each labelled box toward its name.

A box on an unlabelled forklift matches no labelled box, so this loss calls it background and pulls it toward the brown point. Text alone reaches 10.1 rare-class AP.

Copy CLIP's view of every box

The second loss uses no labels. Before training, CLIP embeds a crop of every proposal (small faded blue points). ViLD trains each region embedding to match its crop's CLIP embedding: . CLIP's view of a forklift crop sits near the word "forklift", so the forklift boxes land there too.

At test time CLIP is gone. The detector names every box in one pass, by cosine with the text vectors of all 1,203 class names.

Make CLIP the detector

Every patch is a candidate object

Query

Drop the pooling, keep every token

CLIP's image tower is a : it cuts the image into patches and turns each patch into a token. CLIP then pools all the tokens into one vector per image. OWL-ViT (2022) removes that pooling. Every output token now predicts one box and one embedding.

The stage is a toy grid of 144 tokens over a drawn warehouse; a real ViT-B/32 at 768 x 768 pixels has 576. Click a token to see the box it predicts. Nothing has a name yet: names come from queries.

A query is one more dot product

Pick a class name. The text tower turns it into a vector, and every token's embedding is scored against it: a dot product, then a sigmoid. Pick another name and the scores change, but no box moves. The image tower never sees the text, so thousands of queries cost almost nothing. Later chapters mix text into the image encoder instead.

Training follows DETR: gives each labelled object one token, and the rest learn "no object". Nothing is frozen, but the text tower trains at a learning rate far below the image tower's.

The slider sets which boxes you keep. The rare name delineator barely matches the cone in this toy. OWL-ViT's own Fig. 2 shows the real case: a text query fails on a rare moth species.

Show it an example

The query does not have to come from text. Cut a box from another image, take the model's embedding for it, and use that as the query: one-shot detection. On COCO classes held out from training, OWL-ViT reaches 41.8 one-shot AP50, against 24.3 for the best earlier method (means over four splits, from an R50+H/32 model).

The stage scores every token against the embedding of a cone cut from another image. The embeddings are six-dimensional toys.

OWLv2: let the detector label the web

Human boxes are scarce: OWL-ViT trained on about 2 million images. OWLv2 (2023) runs OWL-ViT L/14 over about 10B web images, with every word N-gram of each image's alt text as a query. It keeps the confident boxes as and trains a new detector on them. Self-training alone lifts the B/16 model from 20.6 to 29.6 rare-class AP on LVIS val.

To afford billions of images, training drops the flattest 50% of patches and grades only the tokens most likely to be objects. At inference nothing is dropped: the model is the same as OWL-ViT.

Replay walks through the five steps. The boxes and scores are toys; the N-gram count follows the paper's rule. The paper labels the web once and does not let the student relabel it.

Fine-tuning trades breadth for a benchmark

A short fine-tune on the LVIS base classes raises LVIS rare-class AP at every model size. It also lowers the median AP over the 35 datasets at every size. the two checkpoints recovers part of the loss, not all of it.

GLIP: detection as grounding

One prompt, every token, fused early

Targets
Fusion

The prompt is the classifier

GLIP (Grounded Language-Image Pre-training) writes the class names into one prompt, "person. traffic cone. toothbrush", and scores every box against it. Each phrase does the job of one class row, so the stage shows one column per phrase. Detection becomes .

The pallet and the forklift match no phrase. For this prompt, they are background.

Every token gets a target

A text encoder reads , not phrases. "traffic cone" is two tokens, and the paper splits "toothbrush" into "tooth#" and "#brush". GLIP copies each box's label to every token of its phrase. Added tokens are always negative. No box shows a toothbrush, so its tokens are negative for every box: a name in the prompt with nothing in the image teaches the model to say no.

Any captioned image with boxes is now training data. GLIP's human grounding data alone has 44,518 unique phrases in Flickr30K and 110,689 in VG Caption; the largest detection datasets have no more than 2,000 categories.

Words change the image features

In late fusion the image side never reads the prompt, and part of the "stingray" score leaks onto the fish. GLIP adds in the last encoder layers. Each region takes in the words it matches best, and each word takes in the regions that match it, so the leak shrinks layer by layer.

The price is speed: GLIP-T runs at 4.84 frames per second without fusion and 2.52 with it, because the fusion layers run for every new pair of image and prompt.

Grounding DINO: text in three places

The prompt picks where the decoder looks

prompt

Words reach into the image

Grounding DINO builds on , a transformer detector. Before it picks any boxes, six fusion layers let the image and the prompt read each other through . The yellow lines show the image tokens that each word reads most.

After these layers, the image features depend on the prompt. The same photo gives different features for forklift and for ladder.

The prompt picks where to look

Each small square is an image token. Its heat (green) is its best score against any word of the prompt. The hottest tokens become the starting boxes of the decoder's : 900 of them in the paper, out of more than 10,000 tokens.

A token sets only where its query starts. What the query carries is learned, the same for every image. Try ladder: nothing in the scene matches, yet the selection still keeps its quota, on the shelf.

The queries read the image and the text

Six decoder layers move each starting box onto an object. Each layer reads the image and, new in Grounding DINO, the text too. At the end, each query is scored against the words of the prompt. One query per object claims it (green); the others score low (brown).

With ladder, every query scores low, so nothing is detected. A real model can fail this last check; the paper lists false positives as a limitation.

YOLO-World: fold the vocabulary into the weights

A real-time detector that reads a prompt

Prompts

Every cell predicts

("You Only Look Once") has no proposal stage. A backbone turns the image into three grids of feature vectors, a path aggregation network (the ) mixes the grids, and every cell predicts one box and its class scores. At a 640 by 640 input that is 8400 predictions per image (our reading of the YOLOv8 convention; the paper states no input size).

During training, picks the few cells that should fire for each object (green dots). The class scores come from fixed rows, so the forklift finds no row and counts as background.

The prompts gate the neck

YOLO-World replaces the class rows with the vectors of a frozen CLIP text encoder. During training each mosaic of 4 images gets its own vocabulary of at most 80 nouns.

Inside the neck, every cell's features are multiplied by a gate: the sigmoid of the cell's best similarity to any prompt. The blue fill on the stage is that gate. Press Drop forklift: the forklift's cells lose their best match and the neck damps them before the head sees them. The image features now depend on the prompt.

The text also looks back: it attends to 27 tokens, the three maps max-pooled to 3 by 3 each.

Run the text encoder once

At deployment the vocabulary is fixed for a while, so the text encoder runs once, offline. Its vectors become the weights of a in the gate and of the classifier. The gate of every cell stays the same number; only the text encoder leaves the per-image path.

One part still reads each image: the small attention over 27 pooled tokens. On one V100 GPU without TensorRT, YOLO-World-L runs at 52.0 frames per second folded and 17.6 unfolded, at 35.0 zero-shot Fixed AP (average precision) on minival.

The tray holds three copies of an odd part that has no common name. The closest word is bracket. A text encoder trained on web captions knows what "bracket" means on the web: the angle bracket. So the prompt claims the angle bracket and misses all three odd parts.

When can a prompt replace training?

Four measurements, one answer

Ten boxes per class beat any prompt

RF100-VL collects 100 datasets of things the web rarely shows. On its Industrial group, the best prompt-only detector scores 10.3 AP. The same detector fine-tuned on 10 boxes per class scores 37.8. Detectors trained on all labels reach 64.3 to 68.2.

The usual average hides the failures

Papers report the mean over 13 ODinW datasets. On those, OWL-ST L/14 averages 53.0 AP. Over all 35 datasets its median is 16.2, and after fine-tuning on LVIS it falls to 6.3.

The name means something else on the web

A text encoder places "porosity" where the web uses it: rock, skin, foam. The weld pores sit elsewhere. A plain description, "small round holes in a weld", lands near them. GLIP measured the effect: on one dataset, describing the look raised zero-shot AP from 13.6 to 73.8.

Object detector

A detector takes an image and returns a set of boxes. Each box has a position, a class name and a score. Most detectors first make many candidate boxes, then score each candidate against every class they know, then drop overlapping duplicates. The class list is fixed when the model is trained.

Shared embedding space

CLIP trains an image encoder and a text encoder together on image-caption pairs from the web. Training pulls each image toward its own caption and pushes it away from other captions. Afterwards, the text vector for "forklift" points the same way as the vectors of forklift photos. A detector can use those text vectors as its class rows.

LVIS and rare-class AP

LVIS is a detection dataset with 1,203 categories. Many categories have very few training images. The open-vocabulary test from ViLD trains on the 866 frequent and common categories, hides the labels of the 337 rare ones, and reports APr: average precision on the rare categories only.

DINO, the detector

DINO is a detector from the DETR family. A transformer encoder turns the image into tokens. A decoder holds a fixed set of queries, and each query outputs one box and one class. During training, a matching step pairs each real object with exactly one query, so the model needs no duplicate removal afterwards. DINO adds training tricks and starts each query's box at a location that the encoder scores highly. It shares its name with an unrelated self-supervised image model.

Cross-attention

Attention lets each token collect information from other tokens, weighted by how well they match. In cross-attention the two groups differ: image tokens collect from the text tokens, and text tokens collect from the image tokens. After a few such layers, an image token on a forklift carries some of the word "forklift", so the image features depend on the prompt.

Queries and anchor boxes

A query is one slot in the decoder that becomes at most one detection. In Grounding DINO each query has two parts. The position part is an anchor box: where the query starts to look. The content part is a learned vector. Query selection fills the position part from the image tokens that match the prompt best; the content part is the same for every image.

Phrase grounding

Phrase grounding takes an image and a caption and finds the box that each phrase of the caption refers to. In "a man walks a dog", it boxes the man and the dog. GLIP's insight is that detection is the same task: write the class names as a caption, "person. car. dog.", and ground each name. Detection data, grounding data and web captions with boxes can then train one model with one loss.

Tokens and subwords

A text encoder such as BERT does not read whole words. A tokenizer first cuts the text into tokens from a fixed vocabulary. Common words are one token; rare words become several subword pieces. The encoder also adds special tokens of its own, for example one at the start and one at the end. GLIP scores each box against each token, so a phrase of three tokens gets three scores, and GLIP averages them.

Cross-attention and deep fusion

In attention, each item computes a weighted average of other items, with weights from how well they match. In cross-attention, the items come from two different sources: here, image regions and text tokens. Each region reads from the tokens, and each token reads from the regions. GLIP puts this block before each of the last encoder layers, so the image features change with the prompt. Without it, text and image meet only in the final score; that design is called late fusion.

Vision Transformer tokens

A Vision Transformer (ViT) cuts an image into square patches, for example 32 x 32 pixels, and turns each patch into a vector called a token. Attention layers then let every token look at every other token. The number of tokens is the number of patches, so it grows with the square of the image size. CLIP pools the final tokens into one vector per image; OWL-ViT keeps them all.

Bipartite matching

DETR-style detectors make a fixed number of predictions, many more than there are objects. During training, a matching step pairs each labelled object with exactly one prediction, the one that fits it best in class and box. Matched predictions learn that object; all the others learn "no object". So the detector needs no duplicate removal step afterwards.

Pseudo-labels and self-training

A pseudo-label is a label made by a model instead of a person. Self-training uses an existing model, the teacher, to label unlabelled data, keeps the labels it is confident about, and trains a new model, the student, on them. The labels contain mistakes; the bet is that a very large amount of noisy data teaches more than a small amount of clean data.

ODinW

Object Detection in the Wild is a collection of 35 small detection datasets from domains far from everyday photos: drone footage, aquariums, potholes, hard hats, playing cards and more. Models are tested on it zero-shot, with only the class names as prompts. Many papers report the average over a 13-dataset subset; the full 35 are harder.

Weight averaging

Take two checkpoints of the same model, for example before and after fine-tuning, and average their weights number by number. The averaged model often keeps part of what each checkpoint was good at. OWLv2 puts weight 0.4 on the fine-tuned checkpoint.

Visual prompt

A visual prompt is a box (or a point) drawn on an example image instead of a typed name. The detector reads the image features around the box and turns them into one vector, in the same space as its text vectors. That vector then scores every candidate box, exactly as a class name would. OWL-ViT did this with one example image; T-Rex2 trains names and boxes together so that their vectors line up.

In-context examples

An in-context example is a labelled example that you show the model at test time, without training it. The weights stay fixed, so papers often call the result zero-shot. But the model still sees labelled examples of the class, which a typed name does not need. So compare it with few-shot methods, which get the same examples, not with a plain name.

RF100-VL and nuImages

RF100-VL (Roboflow100 Vision-Language) collects 100 small detection datasets from domains such as industry, medicine and aerial images, chosen to hold concepts that are rare on the web. FSOD-VLM reuses nuImages, a driving dataset, as a few-shot test; its "Few" group holds the classes with the fewest examples. Both measure average precision (AP).

Region proposal network

The first stage of a two-stage detector. At every cell of the backbone's feature grid it places a few fixed reference boxes (anchors) and predicts two things for each: an objectness score, the chance that the anchor covers some object of any kind, and four numbers that move and resize the anchor onto it. It trains on labelled boxes, but the class of a box plays no part, so it learns what objects look like rather than their names. The top-scoring boxes, after duplicates are removed, are the proposals.

RoIAlign

The step that gives every proposal its own small feature map. It cuts the proposal's rectangle out of the backbone's feature grid and samples it on a fixed grid of bins, interpolating between cells so the box edges need not line up with cell boundaries. Every box, large or small, comes out with the same shape, so one small network (the region head) can process them all.

Knowledge distillation

Training one model (the student) to copy the outputs of another (the teacher) instead of, or as well as, human labels. In ViLD the teacher is CLIP's image encoder and the outputs are its embeddings of cropped proposals, computed once before training. The student is the detector's region head. Because copying needs no labels, the student also learns from boxes on objects that no one labelled.

Average precision (AP)

A detector returns boxes with scores. Sort them by score; a box counts as correct when it overlaps a true box of the same class enough. Precision is the share of returned boxes that are correct; recall is the share of true boxes found. AP averages precision over all recall levels, and COCO-style AP also averages over several overlap thresholds. 100 is perfect; a model that finds nothing scores 0.

YOLO, a one-stage detector

YOLO stands for "You Only Look Once". A two-stage detector first proposes candidate boxes, then classifies each one. A one-stage detector like YOLO skips the proposals: every cell of its feature grids predicts a box and class scores in one pass. That makes it fast enough for video. YOLO-World builds on YOLOv8.

PAN neck

The backbone gives three feature maps, from fine (small cells, local detail) to coarse (large cells, more context). A path aggregation network (PAN) mixes them: a top-down path passes coarse, high-level features down to the finer maps, then a bottom-up path passes fine detail back up. The neck outputs three maps, P3, P4 and P5, and the head predicts on every cell of each.

Task-aligned assignment

A YOLO makes thousands of predictions per image but sees only a few objects, so training must decide which predictions should fire. Task-aligned assignment, from the TOOD paper, ranks the cells for each object by how good both their class score and their box overlap are, and marks the top few as positives. Every other cell learns "no object". DETR-style detectors (detection transformers) instead match exactly one query to each object.

1x1 convolution

A 1x1 convolution applies the same small matrix to the feature vector of every cell. With C filters, each filter a vector as long as the features, it outputs C numbers per cell: the dot product of the cell with each filter. If the filters are the C prompt vectors, the output is every cell's similarity to every prompt, which is exactly what YOLO-World's text gate needs.
