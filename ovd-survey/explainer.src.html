Act IA detector that reads

The class list becomes a text encoder

A detector does two jobs: it puts a box around each object, and it gives each box a score for every class it knows. The second job ends in a short list of names that is fixed when you train the model, and everything on this page starts by replacing that list with a text encoder.

Guess first. The forklift box gets "background" because no row points its way. Before you press Add forklift, decide what must change on the image side of the network to fix this. Then press it.

Nothing on the image side changes. The box was always found; its feature was always there. Only a new row appeared, and the row came from a sentence instead of from training. That is the whole idea of open-vocabulary detection, and the rest of the page is about making it work.

The last layer is a list of names

Take any detector you have seen. A backbone turns the image into features, some machinery proposes boxes, and each box ends up as one feature vector. The classifier is then one matrix with one row per class. GLIP writes it this way (Sec. 3.1, Eq. 2 of v2):

\htmlData{step=1, link=regions}{\htmlClass{t-blue}{O} = \mathrm{Enc}_I(\text{image})}, \qquad \htmlData{step=2, link=rows}{\htmlClass{t-green}{S_{\rm cls}} = \htmlClass{t-blue}{O}\,W^{\top}}, \qquad \htmlData{step=3, link=scores}{\htmlClass{t-red}{\mathcal{L}_{\rm cls}} = \mathrm{loss}(\htmlClass{t-green}{S_{\rm cls}};\, T)}

Eq. 2 in GLIP (2112.03857v2). Bias terms are left out, as in the paper.

  • \htmlClass{t-blue}{O}: the box features, one row per box. With N boxes and feature width d, it is N \times d.
  • W: the classifier, one learned row per class, c \times d for c classes.
  • \htmlClass{t-green}{S_{\rm cls}}: every box scored against every class, N \times c. The best entry in a row names that box.
  • T: the targets, a 0/1 matrix that says which class each box should have; \htmlClass{t-red}{\mathcal{L}_{\rm cls}} pushes the scores toward it.

Read the shapes and the problem is plain. W has exactly c rows. A class that was not in the training labels has no row, and the only way to get one is to label images of it and train again.

Swap the rows for sentences

Your CLIP explainer (VLM survey, chapter 1) showed the other half of the trick. CLIP trains an image encoder and a text encoder together until a photo and its caption land close in one shared space. In that space, the text vector for a name points the same way as the images of that thing. So a text vector can do a classifier row's job.

Write the class names into a prompt, run the text encoder, and use its output where W was (GLIP Eq. 3):

\htmlData{step=1, link=text}{\htmlClass{t-yellow}{P} = \mathrm{Enc}_L(\text{prompt})}, \qquad \htmlData{step=2, link=text scores}{\htmlClass{t-green}{S_{\rm ground}} = \htmlClass{t-blue}{O}\,\htmlClass{t-yellow}{P}^{\top}}

Eq. 3 in GLIP (2112.03857v2).

  • \htmlClass{t-yellow}{P}: the text features, M \times d, one row per token of the prompt. It plays the role of W.
  • \htmlClass{t-green}{S_{\rm ground}}: every box scored against every token, N \times M. A new class is a new phrase in the prompt; no weight changes.

The text encoder must share a space with images; a language-only one is not enough. ViLD tested this directly. With CLIP's text encoder as the classifier, a detector trained only on the 866 base classes (frequent and common) reached 10.1 AP on the held-out rare classes; with GloVe word vectors, trained on text alone, it reached 3.0 (ViLD Table 3, ResNet-50, mask AP).

How the field measures "open"

The papers on this page share one test bed, LVIS, a dataset with 1,203 categories that is split by how often each class appears in training. The open-vocabulary protocol from ViLD trains on the 866 frequent and common classes, hides the labels of the 337 rare ones, and reports APr: average precision on the rare classes only. A high APr means the model names things that it never saw a box for.

You will meet two other tests. Zero-shot transfer evaluates on a dataset whose images the model never trained on, such as COCO. Object Detection in the Wild (ODinW) collects many small datasets from other domains, such as drone footage, aquariums and potholes. These three tests measure different things, and chapter 12 shows that only the last one looks like a factory.

Act IIBorrow CLIP's eyes (2020-2021)

How a two-stage detector finds boxes

The first open-vocabulary detectors were built on a two-stage detector, so this chapter builds one from scratch. The first stage finds boxes without asking what is in them; the second stage crops each box and names it.

Guess first. Suppose this network learned objectness from labelled boxes of people, pallets and cones. In its training images, forklifts were never labelled, so they counted as background. Before you press 3 Objectness, decide: does the forklift light up?

In the toy it does, a little dimmer than the others. The toy assumes that answer, so do not trust it yet; ViLD measured it, and the table at the end of this chapter has the real result. First, the machinery.

Stage one: a grid of features

A backbone network turns the image into a grid. Each cell holds a vector of numbers, its channels, that describes the patch of the image under it. The grid is coarse: one cell covers a square of many pixels, and the side of that square is the stride. ViLD uses a ResNet backbone with a feature pyramid network (FPN), which outputs several grids at different strides, so small objects get a fine grid and large objects a coarse one. The figure shows one grid.

Anchors: boxes fixed in advance

At every cell the detector places the same small set of reference boxes, called anchors: some small, some large, some tall, some wide. An anchor is not a prediction. It is a starting point that the network will score and correct.

The region proposal network: is there an object here?

The region proposal network (RPN) is a small convolutional head that slides over the grid. For every anchor at every cell it outputs two things. The first is an objectness score: the probability that the anchor covers some object, of any kind. The second is four box deltas that move and resize the anchor: d_x, d_y shift its centre by a fraction of its width and height, and d_w, d_h scale its width and height by e^{d_w} and e^{d_h}.

In Faster R-CNN and Mask R-CNN, training labels each anchor by its overlap with the labelled boxes. An anchor that overlaps a labelled box well is a positive and gets that box as its regression target. An anchor that overlaps nothing is a negative. The class of the labelled box plays no part. This is the key fact for this act: the RPN learns what objects look like in general, not what they are called.

Top-k: from thousands of anchors to a short list

Most anchors score near zero. The detector applies the deltas, sorts all boxes by objectness, removes any box that overlaps a better-scoring box too much (non-maximum suppression, NMS), and keeps the top k. These survivors are the proposals. Move the slider in the figure: with too few proposals some objects are missed, and with many the list fills with fragments of background. The field grades this stage by recall: the share of real objects that at least one proposal covers.

Stage two: crop, then name

Each proposal now gets a small feature map of its own. RoIAlign cuts the proposal's rectangle out of the backbone grid and samples it on a fixed grid of bins, interpolating between cells, so the box edges need not fall on cell boundaries. The figure uses 7 x 7 bins; the size is a design choice of the detector. Every box, large or small, becomes a tensor of the same shape.

A region head, a few fully connected layers, turns that tensor into one region feature. From it, the head computes refined box deltas, a mask in Mask R-CNN, and the class scores. The class scores are where the closed list lives: they come from the matrix W of chapter 1, one row per training class plus background. ViLD makes the box and mask outputs class-agnostic, one box and one mask per proposal for all classes (ViLD Sec. 3.1), so only the class scores depend on names.

Proposals do not need names

Back to the guess. An RPN trained on base classes treats an unlabelled forklift as background. Does it then miss forklifts at test time? ViLD measured this on LVIS with a ResNet-50 Mask R-CNN. It trained one RPN on the 866 base classes and one on all classes, then measured how well each recovers objects of the 337 rare classes that the base-only RPN never saw labelled:

So the first stage already finds novel objects. They get lost in the second stage: the head has no row for them, and in training it learned to call them background. The next chapter fixes the second stage.

ViLD: teach the region head to see like CLIP

Where text enters ViLD: only at the classifier. CLIP's text encoder embeds the class names once, before training, and the detector compares each region embedding with those stored vectors.

Chapter 3 ended with a detector that boxes a forklift and then calls it background. CLIP can name that crop. ViLD (Gu et al., 2021) trains the detector's region embeddings to land where CLIP would put them, so the detector can name every proposal in one pass.

Guess first. The forklift regions have no label in the training data. Before you press Text loss only, decide where that loss will send them. Then press Image loss only and compare.

With the text loss alone, the forklift regions drift toward the learned background vector: a proposal that matches no labelled box is, by definition, background. The image loss uses no labels at all. It asks each region to copy CLIP's view of its crop, and CLIP's view of a forklift crop sits near the word "forklift". That is how ViLD reaches classes that no box label ever touches.

The slow way: ask CLIP about every box

The direct approach needs no new training. Take the class-agnostic proposals of chapter 3, crop each one out of the image, and give the crop to CLIP's image encoder (CLIP is recapped in chapter 1). Compare the result with the text vector of every class name, and the best match names the box. ViLD tries this first, with one refinement: it embeds each box twice, once tight and once enlarged 1.5x for context, and adds the two:

\htmlData{step=1, link=image}{\htmlClass{t-blue}{\mathcal{V}(\text{crop}(I, \tilde{r}_{\{1\times, 1.5\times\}}))}} = \htmlData{step=3, link=sphere}{\frac{\mathbf{v}}{\|\mathbf{v}\|}}, ~\text{where}~ \htmlData{step=2, link=image}{\mathbf{v} = \mathcal{V}(\text{crop}(I, \tilde{r}_{1\times})) + \mathcal{V}(\text{crop}(I, \tilde{r}_{1.5\times}))}

Eq. 1 in ViLD (2104.13921v3).

  • I: the image; \tilde{r}: one proposal box, computed offline.
  • \text{crop}(I, \tilde{r}_{1\times}): the box itself; \tilde{r}_{1.5\times}: the same box enlarged for context. Each crop is resized to 224x224.
  • \mathcal{V}: CLIP's frozen image encoder (ViT-B/32). The two embeddings are summed into \mathbf{v}.
  • \mathbf{v}/\|\mathbf{v}\|: the sum rescaled to unit length, a point on the sphere in the figure (the small faded blue points).

It works. On LVIS, CLIP on cropped proposals, combined with the RPN objectness score, reaches 18.9 APr (mask AP, ViLD Table 3), with no rare-class label at all; CLIP alone scores 13.0 (ViLD Table 2). But every proposal is a separate CLIP forward pass, and the paper reports the runtime of this R-CNN-style method as 630x that of a Mask R-CNN-style detector. CLIP's scores also ignore box quality: it often gives its highest score to a box that covers only part of an object (ViLD App. B), so the paper combines them with the RPN's objectness. ViLD's aim is to keep CLIP's knowledge and drop the per-box cost.

ViLD-text: the class rows become CLIP text vectors

First, replace the classifier. ViLD-text drops the learned matrix W and uses CLIP text embeddings of the 866 base class names as the class rows. Each name fills 63 prompt templates, such as a photo of {category} in the scene, and the template embeddings are averaged. A projection layer resizes the region embedding to the text width. One row stays learned: background. The word "background" does not describe the clutter in unmatched proposals, so ViLD gives background its own trainable vector \mathbf{e}_{bg}:

\begin{aligned} &\htmlData{step=1, link=regions}{\htmlClass{t-blue}{\mathbf{e}_r} = \mathcal{R}(\phi(I), r)} \\ &\htmlData{step=2, link=background text}{\mathbf{z}(r) = \begin{bmatrix} \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-brown}{\mathbf{e}_{bg}}), & \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-yellow}{\mathbf{t}_1}), & \cdots, & \mathrm{sim}(\htmlClass{t-blue}{\mathbf{e}_r}, \htmlClass{t-yellow}{\mathbf{t}_{|C_B|}}) \end{bmatrix}} \\ &\htmlData{step=3, link=text}{\htmlClass{t-red}{\mathcal{L}_{\text{ViLD-text}}} = \frac{1}{N}\sum_{r \in P}\mathcal{L}_\text{CE}\Big(\operatorname{softmax}\big(\mathbf{z}(r) / \tau \big), y_r \Big)} \end{aligned}

Eq. 2 in ViLD (2104.13921v3). The first two lines are definitions; the number belongs to the loss.

  • \phi(I): the backbone features; r: one proposal from the online RPN, out of the set P, with N = |P| per image (the paper does not give N).
  • \mathcal{R}: the region head with its projection layer; \htmlClass{t-blue}{\mathbf{e}_r}: the region embedding, a blue point in the figure.
  • \mathrm{sim}(\mathbf{a}, \mathbf{b}) = \mathbf{a}^\top \mathbf{b} / (\|\mathbf{a}\|\|\mathbf{b}\|): cosine similarity.
  • \htmlClass{t-yellow}{\mathbf{t}_i}: the stored CLIP text embedding of base class i, one of |C_B| = 866. \htmlClass{t-brown}{\mathbf{e}_{bg}}: the learned background row.
  • \tau = 0.01: the temperature. Cosines lie between -1 and 1; dividing by it stretches the logits enough for a confident softmax.
  • y_r: the base class of the labelled box that r matches, or background if it matches none. \mathcal{L}_\text{CE}: cross-entropy.

This is chapter 1's idea applied to a two-stage detector, and it already transfers: 10.1 APr. But the loss only ever sees base classes. Look at y_r: a proposal on an unlabelled forklift gets the label background, and the loss pushes it toward \mathbf{e}_{bg}, as the figure shows.

ViLD-image: copy CLIP's view of each proposal

The second loss needs no labels. Before training, ViLD stores the CLIP embeddings (Eq. 1) of M proposals per training image. During training, the detector's region embedding for each of those boxes must match the stored vector:

\htmlData{step=3, link=regions}{\htmlClass{t-red}{\mathcal{L}_{\text{ViLD-image}}} = \frac{1}{M} \sum_{\tilde{r} \in \widetilde{P}} \|} \htmlData{step=1, link=image}{\htmlClass{t-blue}{\mathcal{V}(\text{crop}(I, \tilde{r}_{\{1\times, 1.5\times\}}))}} - \htmlData{step=2, link=regions}{\htmlClass{t-blue}{\mathcal{R}(\phi(I), \tilde{r})}} \htmlData{step=3, link=regions}{\|_1}

Eq. 3 in ViLD (2104.13921v3).

  • \widetilde{P}: the M offline boxes of this image, from a first-stage RPN trained on base classes (the paper does not give M).
  • The first term is the stored teacher vector from Eq. 1 (small faded blue point); the second is the student's region embedding for the same box (blue point).
  • \|\cdot\|_1: the sum of absolute differences, averaged over the M boxes. The paper's sweep found L1 better than L2 for rare classes (16.3 vs 13.7 APr at the same weight, Table 7).

Those boxes come from an RPN, and chapter 3 showed that an RPN boxes novel objects too. So the image loss reaches forklifts, which no label does. ViLD-image alone reaches 11.2 APr. Its weakness is the frequent classes, where it drops to 11.1 APf, because copying CLIP ignores the base labels.

Both losses, and an ensemble

The full loss adds the two:

\htmlClass{t-red}{\mathcal{L}_{\text{ViLD}}} = \htmlData{step=1, link=text}{\mathcal{L}_{\text{ViLD-text}}} + \htmlData{step=2, link=image}{w \cdot \mathcal{L}_{\text{ViLD-image}}}

Eq. 4 in ViLD (2104.13921v3).

  • w: the weight of distillation, 0.5 for the ResNet-50 model.

The two terms pull the same region embedding in two directions, as Both losses shows: toward its class name and toward CLIP's view of its crop. The paper's sweep (Table 7, a shorter schedule of 84,375 iterations) shows the trade. Raising w from 0.05 to 1.0 lifts APr from 12.9 to 17.3 and drops APf from 31.7 to 25.1.

ViLD-ensemble removes the tug of war. It trains two heads of the same shape, one per loss, and mixes their class scores with a weighted geometric mean:

p_{i, \text{ensemble}} = \begin{cases} \htmlData{step=1, link=text}{p_{i, \text{ViLD-text}}^\lambda \cdot p_{i, \text{cls}}^{(1-\lambda)} \quad \text{if } i \in C_B} \\ \htmlData{step=2, link=novel}{p_{i, \text{ViLD-text}}^{(1-\lambda)} \cdot p_{i, \text{cls}}^\lambda \quad \text{if } i \in C_N} \end{cases}

Eq. 5 in ViLD (2104.13921v3).

  • p_{i, \text{ViLD-text}}: the score for class i from the head trained with Eq. 2.
  • p_{i, \text{cls}}: in ViLD-ensemble, the score from the head trained with Eq. 3. (The paper first defines it as CLIP's own score on the crop, which brings back the slow per-box pass.)
  • \lambda = 2/3: base classes C_B trust the text-trained head more, novel classes C_N trust the distilled head more.

Three branches

OVR-CNN (Zareian et al., first posted 2020-11-20) came before CLIP and set up the task. It pretrains a ResNet and a vision-to-language projection on image captions, grounding caption words to image regions, with frozen BERT word embeddings. The detector then uses that projection and the word embeddings as a fixed classifier, with a fixed all-zero background vector where ViLD learns \mathbf{e}_{bg}. On COCO's 48 base and 17 novel classes it reaches 22.8 box AP50 on the novel classes in the generalized setting (base and novel classes scored together), the number that ViLD's Table 4 compares against.

RegionCLIP (Zhong et al., 2021-12-16) pretrains on region-text pairs instead of distilling into a detector. It parses 6,790 concepts from CC3M captions, proposes regions with an RPN, lets CLIP pick the best concept for each region as a pseudo-label, and trains a region-level image encoder, initialized from CLIP, on those pairs. That encoder becomes the detector's backbone, again with an all-zero background. Its LVIS APr is 17.1 with ResNet-50 and 22.0 with ResNet-50x4. These are box AP (our reading: the ViLD rows in its table equal ViLD's box AP), so the fair ViLD number is 16.3 box APr (ViLD Table 8), not the mask 16.1; the detectors and schedules also differ.

Detic (Zhou et al., 2022-01-07) keeps the ViLD-text classifier and adds image-level labels. For an ImageNet image labelled "x", it applies the label to the largest proposal and trains only the classifier on it. No prediction decides which box gets the label: the largest proposal covers the target object in 92.8% of an annotated sample, against 69.0% for a prediction-based choice. In ViLD's own setting (Mask R-CNN ResNet-50, trained from scratch on LVIS base classes) and with IN-L, the 997 ImageNet-21K classes that overlap LVIS, Detic reaches 17.8 mask APr against ViLD's 16.1, a like-for-like comparison (Detic Table 2).

Act IIIMake CLIP the detector (2022-2023)

OWL-ViT: every patch is a candidate object

Where text enters: only at the final score. The image tower never sees the query, so one pass over the image serves any number of queries.

ViLD kept a two-stage detector and taught its region head to imitate CLIP. OWL-ViT goes the other way: it takes CLIP's own image tower and lets every token that comes out of it be a detection.

Guess first. Press Query forklift. Before you press Query pallet, decide which boxes will move. Then press it.

None of them move. Each box and each embedding comes from the image alone. A new query adds one new column of dot products against embeddings that already exist. The paper calls this "no fusion between image and text encoders", and it is why a query costs almost nothing.

Take away the pooling

CLIP's image tower is a Vision Transformer (ViT). It cuts the image into square patches, turns each patch into a token, and runs attention layers over all the tokens (VLM survey, patches). At the top, CLIP pools the tokens into one vector and matches that vector to a caption (the shared space). One vector per image is right for classification. A detector needs one vector per object.

OWL-ViT removes the pooling and the final projection (Sec. 3.1). Each output token then feeds two small heads: a linear class head that gives one embedding per token, and a small MLP that gives one box per token. A ViT-B/32 at 768 x 768 pixels has 576 tokens, so it predicts 576 boxes. LVIS images hold at most 294 objects, so the tokens are enough. The two heads hold at most 1.1% of the parameters; everything else comes pretrained.

One box per token, anchored to its own patch

The box MLP predicts four numbers per token. A fixed bias puts each token's default box on its own patch of the grid, and the MLP learns only the offset, like the anchor offsets of a region proposal network (chapter 3). The bias matters most for a pure ViT: without it, ViT-B/32 lost -2.8 AP and -2.9 APr, and the hybrid R26+B/32 lost -1.2 and -1.1 (LVIS, Tables 3 and A5).

The score, in chapter 1's notation

Neither OWL paper prints an equation: they describe the heads and the loss in words. The score is the dot product from chapter 1, computed for every token and every query, with a sigmoid in place of a softmax. In our notation:

\begin{gathered} \htmlData{step=1, link=tokens}{\htmlClass{t-blue}{O} = \mathrm{head}_{\mathrm{cls}}\big(\mathrm{ViT}(\text{image})\big)} \qquad \htmlData{step=2, link=boxes}{\htmlClass{t-blue}{B} = \mathrm{MLP}\big(\mathrm{ViT}(\text{image})\big) + b_{\mathrm{grid}}} \\ \htmlData{step=3, link=queries}{\htmlClass{t-yellow}{Q} = \big[\mathrm{Enc}(q_1); \ldots; \mathrm{Enc}(q_m)\big]} \qquad \htmlData{step=4, link=scores}{\htmlClass{t-green}{S} = \sigma\big(\htmlClass{t-blue}{O}\,\htmlClass{t-yellow}{Q}^{\top}\big)} \end{gathered}

Our notation, after GLIP Eq. 3 in chapter 1. OWL-ViT (2205.06230v2) describes this head in words in Sec. 3.1 and prints no equation.

  • \htmlClass{t-blue}{O}: one class embedding per token, N \times d for N tokens.
  • \htmlClass{t-blue}{B}: one box per token, N \times 4. b_{\mathrm{grid}} places each default box on its token's own patch.
  • \htmlClass{t-yellow}{Q}: one embedding per query, m \times d. The text tower encodes each query alone, at most 16 text tokens long. A query can also be an image embedding (below).
  • \htmlClass{t-green}{S}: N \times m probabilities. \sigma is a sigmoid on each entry, so a box can match several queries, or none. You keep the boxes whose score passes your threshold.

The sigmoid also suits the training data. Large detection sets such as LVIS label each image in a federated way: some classes are marked present, some absent, and the rest are unknown. A softmax would force each box to pick exactly one class; a sigmoid per query does not (Sec. 3.2).

No fusion, so queries are cheap

GLIP (chapters 7 and 8) joins all class names into one sentence and mixes it into the image encoder; MDETR also fuses text into the image side, and for detection runs one pass per class name. Their image features then depend on the prompt, and a new prompt means a new pass through the fusion layers. OWL-ViT encodes each query alone and never mixes text into the image tower. So it can use thousands of queries per image (Sec. 3.1). In the LVIS test, every image gets all 1203 class names as queries, each written in 7 prompt templates whose scores are averaged. Chapter 8 measures what fusion buys in exchange.

Training: DETR's matching, and a careful text tower

Training follows DETR (DETR family, matching): a bipartite matching gives each labelled object exactly one prediction, and every other prediction learns "no object". OWL-ViT keeps the matching but has no decoder; the tokens are the predictions. The loss adds an L1 box loss, a generalized IoU loss and a focal sigmoid classification loss, with equal weights (focal alpha 0.3, gamma 2.0). Each training image gets its positive and known-absent classes as queries, plus classes sampled by frequency until it has at least 50 negatives.

Nothing is frozen. Both towers train end to end on about 2 million detection images, but the text tower's learning rate is 2e-6, 100x below the image tower's in the ablation baseline (Sec. 4.6). The paper suggests the small rate keeps the text tower from forgetting what it learned from captions. Its ablation table (Table A5, R26+B/32) shows the trade: training the text tower at the image rate changes AP by -3.0 and APr by -8.5; freezing it changes them by -1.5 and -2.3. The text calls full freezing "poor"; the table shows it is less bad than a full learning rate.

OWLv2: label the web with yourself

Where text enters: the same place as in OWL-ViT, the final score. OWLv2 changes the training data and the training cost, not the graph; at inference it is the same model (Sec. 3.2).

OWL-ViT trained on about 2 million images with human boxes, and chapter 5 ended on the suspicion that data was its limit. The web has billions of captioned images and no boxes, so OWLv2 lets OWL-ViT draw the boxes and trains a new detector on them.

Three ways to make billions of images affordable

Self-training only pays if the student sees far more images than any human-labelled set holds. OWLv2 makes each training example cheaper in three ways (Sec. 3.2):

  • Drop flat patches. A ViT's tokens form an unordered set, so some can be left out. OWLv2 drops the 50% of patches with the lowest pixel variance: sky, plain walls and padding. It does this only in training.
  • Grade only likely objects. A new objectness head scores each token, and boxes, class scores and losses are computed only for the top tokens, about 10%. For L/14 at 1008 pixels the image has 5184 tokens and the top 512 are kept (Table A2). At inference all tokens are used.
  • Pack many images into one. Mosaics with grids up to 6x6 put 13.2 web images into one training example on average.

Together these cut training FLOPs by about 50% and raise throughput 2x: for L/14 at 840 pixels, 11945.4 GFLOPs per example for OWL-ViT against 5357.9 for OWLv2. The paper says that at inference "the model is identical to the original OWL-ViT".

The chart is the evidence for dropping half. Rare-class AP is 31.8 with no dropping and 30.8 with half the patches gone, but the no-drop runs alone vary with a standard deviation of 1.16. At 70% the loss is real: AP falls from 33.3 to 30.4 and rare-class AP to 28.2 (LVIS val). Remember the last button: a deployed OWLv2 drops nothing.

Act IVDetection as grounding (2021-2023)

GLIP: a detector is a grounding model

Where text enters GLIP: at the score, where every box meets every token of the prompt, and in the last encoder layers (chapter 8).

Chapter 1 replaced the class rows with text vectors, one vector per class name. GLIP (Li et al., CVPR 2022) writes all the class names into one sentence, person. bicycle. car., and scores every box against every token of that sentence. Detection then becomes phrase grounding: find the box that each phrase of a caption refers to.

Guess first. toothbrush is in the prompt, but no box shows one. Which cells in its two columns become positive targets? Decide, then press Target: toothbrush.

None of them. Both subword tokens are negative targets for every box. This detail makes a prompt work as a classifier: a class name with no object in the image teaches the model to say no. The forklift row is the mirror case. The box is there, but no phrase names it, so for this prompt it is background.

From phrases to tokens

A classifier has one column per class. A text encoder does not see classes; it sees tokens, and a prompt has more tokens than phrases. GLIP gives four reasons (Sec. 3.1):

  • a phrase can have several words, such as "traffic light" (the toy uses "traffic cone");
  • the tokenizer splits some words into subwords: "toothbrush" becomes "tooth#" and "#brush";
  • the language model adds tokens of its own, such as separators and special tokens;
  • GLIP appends one [NoObj] token at the end of the sequence.

So the score matrix has M token columns, with M larger than the number of classes c, but the detection labels give a target with c columns. GLIP widens the target to the token level:

\begin{gathered} \htmlData{step=1, link=scores}{\htmlClass{t-green}{S_{\rm ground}} = \htmlClass{t-blue}{O}\,\htmlClass{t-yellow}{P}^{\top} \in \mathbb{R}^{N\times M}} \\[4pt] \htmlData{step=2, link=targets}{T \in \{0,1\}^{N\times c} \;\longrightarrow\; \htmlClass{t-green}{T'} \in \{0,1\}^{N\times M}, \qquad \htmlClass{t-green}{T'_{ij}} = \begin{cases} T_{ik} & \text{token } j \text{ belongs to phrase } k \\ 0 & \text{token } j \text{ is an added token} \end{cases}} \\[4pt] \htmlData{step=3, link=loss}{\htmlClass{t-red}{\mathcal{L}_{\rm cls}} = \mathrm{loss}(\htmlClass{t-green}{S_{\rm ground}};\, \htmlClass{t-green}{T'})} \end{gathered}

Eq. 3 in GLIP (2112.03857v2), then the target expansion of Sec. 3.1, which the paper states in words; the case notation is ours.

  • \htmlClass{t-blue}{O}: one feature row per N boxes (regions). \htmlClass{t-yellow}{P}: one feature row per token of the prompt, M rows.
  • \htmlClass{t-green}{S_{\rm ground}}: every box against every token, the matrix in the figure.
  • T: the detection label, which class each box is. \htmlClass{t-green}{T'}: the same label copied to every token of that class's phrase; added tokens are 0 for every box.
  • \htmlClass{t-red}{\mathcal{L}_{\rm cls}}: a focal sigmoid loss over every cell, the loss of a one-stage detector. Only the target got wider.

At test time, each phrase needs one score. GLIP averages the token probabilities of the phrase (Sec. 3.1):

\htmlData{step=1, link=phrase}{p(\text{box } i,\ \text{phrase } k) = \frac{1}{|k|}\sum_{j \in k} \sigma\!\left(\htmlClass{t-green}{S_{{\rm ground},\,ij}}\right)}

The inference rule of GLIP Sec. 3.1, written as a formula (our notation).

  • |k|: the number of tokens in phrase k; \sigma: the sigmoid. The cone box in the figure shows the arithmetic.

Does the rewrite cost accuracy? GLIP tested it on COCO with all 80 class names in one prompt. The same DyHead detector with a Swin-T backbone scores 49.4 AP on COCO val2017 both as a detector and as a grounding model (App. B).

The prompt has a budget. BERT can read 512 tokens, and GLIP limits the prompt to 256. Objects365 has 365 classes, too many for one prompt, so in pre-training each prompt holds at most 85 category names: every class present in the image, plus random absent classes as negatives (App. C.1). On LVIS, GLIP splits the 1,203 categories into prompts of 40 and runs the model once per prompt (App. C.2). The format matters too: with BERT as the text encoder, person. bicycle. car. works better than the friendlier Detect: person, bicycle, car. The paper gives no number for this.

Any captioned box is now training data

Once detection is grounding, three kinds of data train one model with one loss. Detection labels become prompts of class names. Human grounding data gives a caption with a box for each phrase. Web image-caption pairs get boxes from a teacher model. The vocabulary grows by orders of magnitude. The largest detection datasets have no more than 2,000 categories. The gold grounding data has 44,518 unique phrases in Flickr30K and 110,689 in VG Caption (Sec. 3.3).

The web data comes from self-training. A GLIP trained on gold data is the teacher. A language parser finds the noun phrases in each caption, and the teacher boxes them. The student trains on the gold data plus these pseudo labels. On the 24M web pairs of GLIP-L, the teacher kept 78.1M phrase-box pairs with confidence above 0.5, which cover 58.4M unique noun phrases (Sec. 1).

Branches

MDETR: the grounding ancestor

MDETR (Kamath et al., 2104.12763v2) came first. It is DETR whose encoder reads the image features and the RoBERTa token features as one joined sequence. Each matched query predicts which tokens its box refers to, and a contrastive loss pulls query and token embeddings together. GLIP says its token-level target follows MDETR (Sec. 3.1). MDETR trained on 1.3M aligned image-text pairs. It cannot be tested zero-shot: every training text has a box, which biases the model "to always predict boxes for a given text" (Sec. 3.2.1). On LVIS it asks for one class name per forward pass, about 10s per image on a GPU. GLIP's detection prompts list absent classes, so its model learns to answer "no box" (our reading).

GLIPv2: more negatives, same tap

GLIPv2 (2206.05836v2) keeps GLIP's architecture, so text still enters at the fusion layers. It changes the loss: it adds negatives from the other images in the batch, scored on the features before fusion, and a masked-language loss on the text. At the Tiny size, zero-shot ODinW-13 (the average AP over GLIP's 13 ODinW datasets) goes from 46.5 to 48.5, and LVIS minival AP from 26.0 to 29.0 (GLIPv2 Table 2).

Deep fusion: words change what the image encoder sees

Where text enters here: the cross-attention inside each DyHead module, before the score.

In late fusion, the image encoder never sees the prompt. The box features are the same whatever you ask, and text meets image only in the final dot product. GLIP adds cross-attention between the image and text features in the last encoder layers, so the image features become a function of the prompt.

Guess first. In late fusion, part of the "stingray" score leaks onto the fish, because the word alone does not say what a stingray looks like. Can a better dot product at the very end remove the leak, or must the image features themselves change? Decide, then press Deep fusion.

The features must change. In deep mode, each region takes in the words that it matches best, and each word takes in the regions that match it. After a few layers, the stingray regions look more like "stingray" and the fish look more like "fish", and the leak shrinks layer by layer. In late mode nothing moves, because the image side never reads the prompt. The text side changes too: watch the five bars of the token vector in deep mode.

The fusion equations, term by term

GLIP's image encoder ends in L DyHead modules, and its text encoder BERT gets newly added layers on top, one per fusion step in Eq. 6, so L of them (our reading; the paper and config never state the count). Before each pair of modules, a cross-modal attention block (X-MHA) computes a context vector for each side from the other side. Each side adds its context and runs its own module (Sec. 3.2):

\begin{aligned} &\htmlData{step=1, link=xmha}{\htmlClass{t-yellow}{O^i_{\rm t2i}},\ \htmlClass{t-blue}{P^i_{\rm i2t}} = \text{X-MHA}(\htmlClass{t-blue}{O^i}, \htmlClass{t-yellow}{P^i}), \quad i \in \{0, 1, \dots, L-1\}} \\ &\htmlData{step=2, link=image t2i}{\htmlClass{t-blue}{O^{i+1}} = \text{DyHeadModule}(\htmlClass{t-blue}{O^i} + \htmlClass{t-yellow}{O^i_{\rm t2i}}), \quad \htmlClass{t-blue}{O} = \htmlClass{t-blue}{O^{L}}} \\ &\htmlData{step=3, link=text i2t}{\htmlClass{t-yellow}{P^{i+1}} = \text{BERTLayer}(\htmlClass{t-yellow}{P^i} + \htmlClass{t-blue}{P^i_{\rm i2t}}), \quad \htmlClass{t-yellow}{P} = \htmlClass{t-yellow}{P^{L}}} \end{aligned}

Eq. 4 to 6 in GLIP (2112.03857v2). The paper prints the two context terms in red; here each takes the color of the side it carries information from, because red means loss on this page.

  • \htmlClass{t-blue}{O^i}: the image features entering module i; \htmlClass{t-blue}{O^0} comes from the vision backbone. \htmlClass{t-yellow}{P^i}: the token features; \htmlClass{t-yellow}{P^0} comes from BERT.
  • \htmlClass{t-yellow}{O^i_{\rm t2i}}: text-to-image context, what each region reads from the tokens. \htmlClass{t-blue}{P^i_{\rm i2t}}: image-to-text context, what each token reads from the regions.

  • Delete the two context terms and the model is late fusion (the paper's words): the same encoders, scored only by O P^{\top} at the end. That is GLIP-T (A) in the table of chapter 7.

Inside X-MHA, one score matrix serves both directions. Each head projects the image and text features, takes their scaled dot products, and normalizes them one way for the image side and the other way for the text side:

Grounding DINO: DINO-DETR that reads

Where text enters Grounding DINO: in the encoder (a feature enhancer), in the choice of the decoder's starting boxes, in every decoder layer, and at the final score.

GLIP let the prompt change the image features inside the encoder. Grounding DINO starts from DINO, a DETR-style detector, and lets the prompt in at two more places; the most visible one is that the prompt now chooses where the decoder starts to look.

Guess first. The prompt ladder names nothing in this warehouse, but query selection always keeps a fixed number of tokens. Before you press ladder, decide where those tokens will go, and what must then stop them from turning into false detections.

They land on the shelf, the thing that looks most like a ladder, with low scores. The selection has no "nothing here" answer: it keeps the top tokens whatever their scores are. Press 3 Decoder and the final score rejects every one of them. In a real model that last check can fail. The paper lists false positives, which it calls hallucination, as a limitation (Sec. 5), and a false box has to start from some selected token (our reading). Try traffic cone too: the cone covers only four tokens, so the remaining queries go to the next-best region.

DINO in one paragraph

Your DETR explainer built DINO step by step, so here is only the outline. DETR treats detection as set prediction: a fixed set of object queries reads the image through a transformer decoder, and each query outputs one box and one class (object queries). Deformable attention lets each query look at a few sampled points on several feature scales instead of at every pixel (Deformable DETR). DAB-DETR splits each query into a content part and a positional part, and makes the positional part an explicit anchor box (DAB-DETR). DINO adds denoising training and mixed query selection: the anchor boxes start from the encoder's best-scoring locations for this image, while the content part stays a learned vector (DN-DETR and DINO). Grounding DINO keeps all of this and adds text.

Text chooses the queries

In DINO, the encoder's class head ranks the image tokens, and the best tokens give the anchor boxes. A closed-set class head cannot rank tokens for a name it never learned. Grounding DINO ranks each image token by its best match with any token of the prompt (Sec. 3.2):

\htmlData{step=4, link=topk}{\mathbf{I}_{N_q} = \texttt{Top}_{N_q}\big(}\htmlData{step=3, link=max}{\texttt{Max}^{(-1)}(}\htmlData{step=1, link=image}{\htmlClass{t-blue}{\mathbf{X}_{I}}}\,\htmlData{step=2, link=text scores}{\htmlClass{t-yellow}{\mathbf{X}_{T}^{\intercal}}}\htmlData{step=3, link=max}{)}\htmlData{step=4, link=topk}{\big)}

Eq. 1 in Grounding DINO (2303.05499v5).

  • \htmlClass{t-blue}{\mathbf{X}_{I}}: the image tokens after the feature enhancer, all scales flattened into one list, N_I \times d. The paper gives N_I as more than 10,000 and d = 256.
  • \htmlClass{t-yellow}{\mathbf{X}_{T}}: the text tokens after the enhancer, N_T \times d, with at most 256 tokens.
  • \htmlClass{t-blue}{\mathbf{X}_{I}}\htmlClass{t-yellow}{\mathbf{X}_{T}^{\intercal}}: every image token scored against every text token, N_I \times N_T.
  • \texttt{Max}^{(-1)}: the maximum along the last axis, the text axis. Each image token keeps its best match with any word: the heat in the figure.
  • \texttt{Top}_{N_q} and \mathbf{I}_{N_q}: the indices of the N_q = 900 hottest image tokens, the same query count as DINO.

The selected tokens fill only half of each query. Grounding DINO follows DINO's mixed query selection: the positional part, a dynamic anchor box, is "initialized with encoder outputs" at the selected tokens, and the content part is "set to be learnable" (Sec. 3.2). So the prompt decides where the queries start, not what they carry. The figure's query list shows this split. The paper's Fig. 7 shows the selected boxes move when only the prompt changes.

Three more places for text

Encoder fusion: the feature enhancer. Before any selection, the image and text features meet in a stack of feature enhancer layers, 6 of them (Sec. 3.1, Fig. 3). In each layer, the image tokens run deformable self-attention and the text tokens run ordinary self-attention; an image-to-text and a text-to-image cross-attention, "inspired by GLIP", exchange information between them; then each side has a feed-forward network (FFN). So the \htmlClass{t-blue}{\mathbf{X}_{I}} in Eq. 1 already depends on the prompt. Press 1 Encoder fusion to see each word reach into the image.

The cross-modality decoder. Each of the 6 decoder layers runs self-attention among the queries, a deformable cross-attention into the image tokens, a cross-attention into the text tokens, and an FFN (Sec. 3.3). In the paper's words, "each decoder layer has an extra text cross-attention layer compared with the DINO decoder layer". Each layer also refines the boxes, as in DINO.

The score. There is no class matrix at the end. As in GLIP (chapter 7), each output query takes a dot product with every text token, which gives one logit per token, and a phrase wins when its tokens light up (Sec. 3.5).

Sub-sentence prompts: names that do not talk to each other

For detection data, the category names are joined into one prompt, as in GLIP. BERT then lets every word attend to every other word, so "pallet" gets mixed with whatever names happen to share its prompt. During training the names are sampled at random for each image (App. B), so the same word would get a different feature in every prompt. Grounding DINO adds an attention mask that blocks attention between different category names (Sec. 3.4).

In the toy at word level, "pallet" spends about half of its attention on other names, so its feature changes when its neighbours change. With the mask, it sees only its own words, and its feature is the same in every prompt. A two-word name such as "traffic cone" still keeps one feature per word, which a single sentence-level vector, as in OWL-ViT, would lose. The paper calls this the sub-sentence level representation. Removing it costs the least of the four pieces in the table above.

Act VReal time (2024)

YOLO-World: fold the vocabulary into the weights

Where text enters YOLO-World: in the neck, where the prompts gate the features of every cell and a small attention lets the text look back at the image, and again at the score. For deployment the text encoder runs once, and its output becomes ordinary convolution weights.

Every earlier detector in this chart runs at a few frames per second or less, as YOLO-World's authors measured them (chart below). YOLO-World starts from a real-time detector, YOLOv8, and asks how little it must change to read a prompt. The figure walks through the answer in three steps.

What YOLO is, from scratch

The two-stage detector of chapter 3 first proposes boxes, then names each one. A one-stage detector skips the proposals. The network turns the image into grids of feature vectors, and every cell of every grid predicts a box and class scores at once. The name says it: YOLO is short for "You Only Look Once". YOLO-World builds on YOLOv8, and its paper names the parts that matter here:

  • Three feature maps. The backbone, a convolutional network called Darknet, produces maps C3, C4 and C5, each a coarser grid than the one before. For an input of 640x640 pixels (the size of the released models, official code; the paper states no input size) they are 80x80, 40x40 and 20x20 cells our reading, from the YOLOv8 convention of strides 8, 16 and 32.
  • A neck that mixes the maps. A path aggregation network (PAN) runs a top-down path, which passes coarse, high-level features down to the fine map, then a bottom-up path, which passes fine detail back up. Its outputs are P3, P4 and P5, on the same three grids.
  • Dense predictions. Every cell of P3, P4 and P5 makes one prediction: 6400 + 1600 + 400 = 8400 per image at that size our reading. Compare 900 queries in Grounding DINO.
  • A decoupled head. Each cell feeds two separate branches, each with two 3x3 convs (the paper says "two 3x3 convs"; two per branch is the YOLOv8 convention and our reading). One branch regresses the box as four distances from the cell to the box edges; the other gives the class output.
  • Which cells should fire. Thousands of cells and a handful of objects: training must decide which cells are positives. DETR answers with Hungarian matching, exactly one query per object (DETR family, matching). YOLOv8 uses task-aligned label assignment: for each object it ranks the cells by how good both their class score and their box overlap are, and the top few become positives; every other cell learns "no object". Several cells can claim one object, so duplicates are removed after prediction.
  • Box losses. An IoU loss penalizes low overlap with the true box. A distribution focal loss (DFL) lets the head predict each edge distance as a small probability distribution instead of one number, and pushes that distribution toward the true distance.
  • Mosaics. Training images arrive as mosaics: 4 images tiled into one, plus color changes, random affine warps and flips.

YOLO-World names task-aligned assignment, the IoU loss, DFL and the mosaic, but does not restate how they work. The one-line descriptions above, and the duplicate removal, come from the YOLOv8 line of work and are background, not claims of this paper.

Press 1 Plain YOLO. The green dots are the positives that assignment picks for each object; the selected cell on the forklift predicts a box (blue corners, with its four edge distances dashed). Its class branch has one score per class row, and no row is "forklift", so nothing fires. This is chapter 1's closed-set problem, now in a real-time detector.

Text in the neck

The first change is the one every chapter makes. The class branch becomes an embedding branch, and the class rows become text vectors. YOLO-World encodes the prompts with CLIP's text encoder, \htmlClass{t-yellow}{W} = \texttt{TextEncoder}(T) \in \mathbb{R}^{C\times D}: one D-dimensional row for each of the C nouns. The paper calls it CLIP-base (ViT-base) and keeps it frozen during pretraining. Its width D is not stated, so this page keeps it symbolic.

During training, each mosaic gets its own vocabulary: all the nouns of its 4 images, plus random negative nouns from the same dataset, at most 80 in all. Captions and referring expressions are cut into noun phrases first.

The second change is new. Inside the neck, the text gets a say in which image features survive. After the last bottleneck of each C2f block, YOLO-World multiplies every cell's feature vector by one number between 0 and 1: the sigmoid of that cell's best similarity to any prompt. The block is renamed a text-guided CSPLayer (T-CSPLayer), and the operation is a max-sigmoid gate:

\htmlData{step=4, link=features}{\htmlClass{t-blue}{X_l'} = \htmlClass{t-blue}{X_l}\cdot} \htmlData{step=3, link=gate}{\delta\Big(} \htmlData{step=2, link=max}{\max_{j\in\{1..C\}}} \htmlData{step=1, link=sims}{\big(\htmlClass{t-blue}{X_l}\htmlClass{t-yellow}{W_j}^{\top}\big)} \htmlData{step=3, link=gate}{\Big)^{\top}}

Eq. 2 in YOLO-World (2401.17270v3).

  • \htmlClass{t-blue}{X_l}: the image features at level l \in \{3,4,5\}, an H\times W\times D map: one D-vector per cell.
  • \htmlClass{t-blue}{X_l}\htmlClass{t-yellow}{W_j}^{\top}: every cell's dot product with prompt j, an H\times W map. The figure's bars show these numbers for the selected cell.
  • \max_j: per cell, keep only the best-matching prompt.
  • \delta: the sigmoid, which turns that score into a gate between 0 and 1.
  • \htmlClass{t-blue}{X_l'}: the gated features. A cell that matches any prompt keeps its features; a cell that matches none is damped. The gated map is then concatenated with the block's cross-stage features, as in a plain C2f block.

Press 2 Text in the neck. The blue fill is the gate: it is bright on the four objects and dim on the shelf and the floor. Then press Drop forklift. The forklift's cells lose their best match, their gate falls, and the neck damps them before the head ever sees them. This is the difference from late fusion (chapter 8): the image features now depend on the prompt.

The text also looks back at the image. Image-Pooling Attention (I-Pooling) max-pools each of the three maps to a 3x3 grid, which gives 27 image tokens, and lets the text vectors attend to them:

\htmlData{step=1, link=text}{\htmlClass{t-yellow}{W'} = \htmlClass{t-yellow}{W}} + \htmlData{step=2, link=pooled}{\texttt{MultiHead-Attention}(\htmlClass{t-yellow}{W}, \htmlClass{t-blue}{\tilde{X}}, \htmlClass{t-blue}{\tilde{X}})}

Eq. 3 in YOLO-World (2401.17270v3).

  • \htmlClass{t-yellow}{W}: the text vectors, used as the attention queries.
  • \htmlClass{t-blue}{\tilde{X}}: the 27 pooled image tokens, a 27\times D matrix, used as keys and values. Pooling first keeps the attention tiny: 27 tokens instead of thousands of cells.
  • \htmlClass{t-yellow}{W'}: image-aware text vectors, added back as a residual. The head scores against these.

Last, the head scores each prediction against each prompt, much as in chapter 1, but with both vectors normalized and a learned scale and shift:

\htmlData{step=3, link=score}{\htmlClass{t-green}{s_{k,j}} = \alpha\cdot} \htmlData{step=1, link=cells}{\texttt{L2-Norm}(\htmlClass{t-blue}{e_k})} \cdot \htmlData{step=2, link=text}{\texttt{L2-Norm}(\htmlClass{t-yellow}{w_j})^{\top}} \htmlData{step=3, link=score}{+ \beta}

Eq. 1 in YOLO-World (2401.17270v3).

  • \htmlClass{t-blue}{e_k}: the object embedding of prediction k, from the embedding branch. There is one per cell.
  • \htmlClass{t-yellow}{w_j}: the vector of prompt j. With both vectors scaled to unit length, their product is a cosine.
  • \alpha, \beta: a learned scale and shift. The paper says the normalization and this affine step "are important for stabilizing the region-text training".
  • \htmlClass{t-green}{s_{k,j}}: the score of prediction k for prompt j, the tags on the figure's boxes.

The training loss adds the box losses to a region-text contrastive loss: \mathcal{L}(I) = \htmlClass{t-red}{\mathcal{L}_{\text{con}}} + \lambda_I\cdot(\htmlClass{t-red}{\mathcal{L}_{\text{iou}}} + \htmlClass{t-red}{\mathcal{L}_{\text{dfl}}}). The contrastive term is a cross entropy between the scores and the assignment, which gives each positive cell the index of its noun. \lambda_I is 1 for detection and grounding images and 0 for image-text data, whose boxes are noisy. That image-text data is 246k CC3M images that GLIP-L labelled automatically, a teacher-student loop like OWLv2's (chapter 6).

Both neck paths pay off, a little. In the paper's ablation (YOLO-World-L pretrained on Objects365 alone, zero-shot LVIS minival AP), adding both paths raises AP from 22.4 to 23.5; with GQA grounding data added, from 29.7 to 31.9 (Table 4). Freezing the text encoder matters more, on either metric: on AP the neck paths add 1.1 while fine-tuning the encoder costs 3.1, and on rare classes the neck adds 1.7 while fine-tuning costs 5.9. In the same setting without the neck paths, fine-tuning CLIP's text encoder drops rare-class AP from 14.5 to 8.6 (Table 5): training on 365 class names erodes what CLIP knows about the rest. Chapter 12 finds the same trade in OWLv2. our reading: these ablations use a shorter setting than the main results, so their numbers do not compare with the chart below.

Fold the vocabulary into the weights

At deployment the user's vocabulary is fixed for a while: the same twenty part names, all shift. YOLO-World calls this "prompt-then-detect". The text encoder runs once on the prompts, offline, and the resulting \htmlClass{t-yellow}{W} is stored. Stored text vectors are just numbers, and a dot product of every cell with each of C stored vectors is exactly what a 1x1 convolution with C filters computes.

Guess first. Press 2 Text in the neck and note the gate of the selected forklift cell. When the text encoder is folded into a 1x1 convolution, will that gate change? Decide, then press 3 Fold into weights.

It does not change. Folding moves where \htmlClass{t-yellow}{W} is computed, not its value, because the text encoder never sees the image our reading. The paper writes the folded gate this way, reshaping \htmlClass{t-yellow}{W} to C\times D\times 1\times 1, the weights of a 1x1 convolution:

\htmlData{step=4, link=features}{\htmlClass{t-blue}{X'} = \htmlClass{t-blue}{X} \odot} \htmlData{step=3, link=gate}{\texttt{Sigmoid}(} \htmlData{step=2, link=max}{\texttt{max}(} \htmlData{step=1, link=conv}{\texttt{Conv}(\htmlClass{t-blue}{X}, \htmlClass{t-yellow}{W})} \htmlData{step=2, link=max}{, \texttt{dim=1})} \htmlData{step=3, link=gate}{)}

Eq. 4 in YOLO-World (2401.17270v3), Appendix A.1.

  • \texttt{Conv}(\htmlClass{t-blue}{X}, \htmlClass{t-yellow}{W}): a 1x1 convolution whose C filters are the stored text vectors. It outputs C similarity maps, one per prompt, for a batch of B images: B\times C\times H\times W.
  • \texttt{max}(\cdot, \texttt{dim=1}): the max over the prompts, per cell. \texttt{Sigmoid}: the gate.
  • \odot: the paper calls it "matrix multiplication with reshape or transpose"; in effect it scales each cell's features by its gate. \htmlClass{t-blue}{X} and \htmlClass{t-blue}{X'} are B\times D\times H\times W.

The classifier folds the same way: after fine-tuning, the paper stores the class text vectors "into the weights of the classification layers" (Appendix A.2). One part does not fold. I-Pooling reads the 27 pooled tokens of the current image, so the update to the text vectors still runs on every image after folding (Appendix A.1, Eq. 5 and 6). Eq. 6 is printed with an unbalanced parenthesis and does not match Eq. 3, so this page quotes neither and does not repair it. The deployed network is a YOLO with a few extra 1x1 convolutions and one tiny attention, and no text encoder.

The first box prompt: an image as the query

Chapter 5 met this idea already. OWL-ViT scores every image token against a query embedding, and the query does not have to come from text. Give it a reference image with a box, and it runs its image tower on that image. Among the predicted boxes that overlap the query box with an IoU above 0.65, it keeps the embedding that is most unlike the others, because one foreground embedding stands out from many similar background ones. In about 10% of cases no predicted box overlaps enough, and it falls back to a generic text query (App. A1.7).

On COCO classes held out from training, this one-shot query reached 41.8 AP50, against 24.3 for AIT, the best earlier one-shot detector (Table 2: means over four class splits, each split averaged over three runs). That model is a hybrid of ResNet-50 and ViT-H/32 at 960 pixels, not the CLIP L/14 model of chapter 5. With ten example images averaged per class, it reached 46.8. The paper's Fig. 2 shows why this matters: the text query "luna moth" finds nothing, and an image of the moth as the query finds it.

T-Rex2: names and boxes in one space

T-Rex2 (2024) builds both kinds of prompt into one detector. Its body is DINO, a DETR-style detector with deformable attention and denoising queries (recap in the DETR family explainer), plus the language-guided query selection of Grounding DINO from chapter 9. A Swin backbone and 6 encoder layers make multi-scale image features. Two prompt encoders feed one classifier.

The text side is simple. A CLIP-B text encoder turns each category name or short phrase into one vector \htmlClass{t-yellow}{T}. T-Rex2 fine-tunes this encoder, at the learning rate of the backbone, 1e-5.

The box side needs more work, because a box is four numbers, not a picture. T-Rex2 turns each of the K boxes (or points) into a fixed sine-cosine position code, and a linear layer maps the code to the model width D (Eq. 1 and 2). Each box also gets a learned content vector, and one extra global query stands for the whole class (Eq. 3). Then each query looks at the image around its own box:

\htmlData{step=1, link=exemplar}{Q'_j = \operatorname{MSDeformAttn}(Q_j,\ \htmlClass{t-yellow}{b_j},} \htmlData{step=2, link=features}{\{\htmlClass{t-blue}{\boldsymbol{f}_i}\}_{i=1}^L)}, \qquad \htmlData{step=3, link=visual}{\htmlClass{t-blue}{V}=\operatorname{FFN}(\operatorname{SelfAttn}(Q'))[-1]}

Box case of Eq. 4, and Eq. 5, in T-Rex2 (2403.14610v1). The point case puts the point p_j in place of b_j.

  • Q_j: the query of the j-th box, its position code joined with the learned content vector.
  • \htmlClass{t-yellow}{b_j}: the user's box, (x, y, w, h) normalized. It is the reference location, so the query reads features near it.
  • \htmlClass{t-blue}{\boldsymbol{f}_i}: the encoder's feature map at scale i, for L scales.
  • \operatorname{MSDeformAttn}: multi-scale deformable attention. Each query reads a few learned sampling points near its box instead of the whole image. The encoder stacks 3 such layers.
  • \htmlClass{t-blue}{V}: after self-attention among the K+1 queries and a feed-forward layer (hidden width 1024), the output of the global query (index -1, the last one) is the visual prompt embedding: one vector per class per image.

From here on, a box prompt and a name are the same kind of object. Both become a row of the classifier, which is the swap this page started with in chapter 1:

\htmlData{step=1, link=scores}{\htmlClass{t-green}{\operatorname{Label}}} = \htmlData{step=2, link=visual}{\htmlClass{t-blue}{V}} \cdot \htmlData{step=3, link=regions}{Q_{dec}^T} : \mathbb{R}^{C \times D} \times \mathbb{R}^{D \times N} \rightarrow \mathbb{R}^{C \times N}

Eq. 8 in T-Rex2 (2403.14610v1). A text prompt uses \htmlClass{t-yellow}{T} in place of \htmlClass{t-blue}{V}.

  • \htmlClass{t-blue}{V}: the prompt embeddings, one row per class, C \times D. The paper does not state D.
  • Q_{dec}: the features of the decoder's N queries, one per candidate box. The top 900 encoder tokens by similarity to the prompts set their starting boxes.
  • \htmlClass{t-green}{\operatorname{Label}}: every candidate box scored against every prompt, C \times N. In the toy, these are the score bars.

Training alternates between the two prompt types: one iteration uses names, the next uses boxes. In a box iteration the prompts come from the training image itself. For each category, the model takes one to all of its ground-truth boxes, and with a 50% chance it turns them into center points (Sec. 3.3). A contrastive loss ties the two prompt types together. For the K prompted regions of an image, it pulls each region's visual embedding toward the text embedding of its class and away from the other classes' text:

\htmlData{step=1, link=align}{\htmlClass{t-red}{\mathcal{L}_{align}} = -\frac{1}{K} \sum_{i=1}^K \log} \frac{\exp(\htmlData{step=2, link=visual}{\htmlClass{t-blue}{v_i}} \cdot \htmlData{step=3, link=text}{\htmlClass{t-yellow}{t_i}})}{\sum_{j=1}^K \exp(\htmlClass{t-blue}{v_i} \cdot \htmlClass{t-yellow}{t_j})}

Eq. 9 in T-Rex2 (2403.14610v1).

  • \htmlClass{t-blue}{v_i}: the visual prompt embedding of region i.
  • \htmlClass{t-yellow}{t_i}: the text embedding of the class name of region i; the \htmlClass{t-yellow}{t_j} are the class names of the other regions in the same image.
  • \htmlClass{t-red}{\mathcal{L}_{align}}: a softmax over the K text embeddings, in one direction (visual to text), with no temperature written. The paper calls it a mutual distillation (Sec. 3.2). Without it, the two embeddings of one class sit apart, and the name prompts score lower (Table 4).

Once trained, a class can be prompted three ways: with the name only, with boxes only, or with both. With boxes only, the generic mode (Visual-G) averages the visual embeddings of n example boxes, each from a different image (Eq. 11). With both, it averages the two vectors (Eq. 12):

\htmlData{step=1, link=visual}{\htmlClass{t-blue}{V} = \frac{1}{n} \sum_{i=1}^{n} V_i}, \qquad \htmlData{step=2, link=mixed}{P_{\text{mixed}} = \frac{\htmlClass{t-yellow}{T} + \htmlClass{t-blue}{V}}{2}}

Eq. 11 and 12 in T-Rex2 (2403.14610v1).

  • V_i: the visual embedding from example image i, for n examples. The paper's default is 16.
  • P_{\text{mixed}}: the average of the name's vector and the box vector. It takes the place of \htmlClass{t-blue}{V} in Eq. 8, as in the toy's Both mode.

What the benchmarks say

Read T-Rex2's box-prompt numbers with their setting in mind. Visual-G takes 16 images per class from each benchmark's training split, with one labelled box each, and averages their embeddings (Sec. 4.3). The weights do not change, so the paper calls the result zero-shot. our reading It is zero-shot for the weights, but it uses 16 labelled examples per class that a name never sees, so it is closer to a few-shot method than to a text prompt. With one example instead, Visual-G scores 29.2 AP on COCO, against 45.8 for the names (Swin-T, Tables 5 and 1).

The left panel holds T-Rex2's headline claim: names for common classes, boxes for rare ones. On LVIS val, Visual-G beats the names on the rare classes, 32.4 against 29.0 APr, and a per-class count agrees: the box wins on 253 rare classes and the name on 84 (Fig. 4). On LVIS minival the same model flips: names 37.4, boxes 29.9. Swin-L flips the same way (val 43.8 for boxes against 42.7 for names; minival 45.4 against 49.2). The two splits are not comparable: val has 337 rare classes and minival only 70.

Part of the val gap comes from the names getting worse, not from the boxes getting better. A T-Rex2 trained on text alone scores 32.1 APr on LVIS val with names; joint training brings its names down to 29.0 (Table 4). So the text-only model's names nearly match the joint model's boxes.

Away from LVIS, T-Rex2's boxes win clearly. On ODinW-35 the median dataset rises from 4.7 AP with names to 17.5 with boxes. On the original Roboflow100, the mean rises from 8.2 to 17.4 (Swin-L: 10.5 to 18.5). our reading These collections are full of class names that a web-trained model does not know, so labelled examples help more there than on LVIS.

The middle and right panels test a different visual-prompt model on different benchmarks; neither paper tests T-Rex2. Both use MQ-GLIP, which adds MQ-Det's image-prompt module to a frozen GLIP and takes 10 examples per class in context, with no training. In RF100-VL, images alone scored 6.4 AP over 100 datasets, against 12.2 for the class names; on its 22 industrial datasets, 3.9 against 7.8. In FSOD-VLM on nuImages, the rarest classes (the Few cohort) scored 3.34 AP with images and 8.41 with names. For this model, the rarest classes are where images alone did worst.

Adding the name back helps or changes nothing. Names plus images give 12.2 in RF100-VL, the same as names alone, and 10.26 on the nuImages Few cohort, above both single prompts (over all 18 classes: 21.42 against 17.01 for names and 14.07 for images). T-Rex2 shows the same gain on LVIS val rare classes (34.3 APr for both) and a loss on COCO, where both scores 42.5 AP and names alone 45.8. The paper says so itself: visual prompts "may sometimes interfere with text prompts, especially in scenarios involving common objects" (Sec. 5).

our reading "Box prompts help" is a property of a model and a benchmark, not of boxes. T-Rex2 trains its box encoder on 2.4M labelled images plus 0.65M pseudo-labelled ones; MQ-GLIP adds a small module to a frozen detector. Before you trust box prompts for a factory part, test the model you will deploy on your own parts, against a name and against a short fine-tune.

Box prompts now also reach real-time detectors. YOLOE (ICCV 2025), whose design roadmap starts from YOLO-World (chapter 10), keeps one classifier: a dot product between each anchor's object embedding and a prompt embedding. Only the way it makes the prompt changes. A name goes through a small network that folds into the last convolution after training. A box or mask goes through a light two-branch encoder (SAVPE). With no prompt at all, one learned embedding fires on every object, and a built-in list of 4585 names labels it (LRPC). YOLOE also drops YOLO-World's text fusion in the neck, so names and boxes enter only at the classifier, as in T-Rex2.

So a box is a real answer when a part has no name, with two conditions: the model's box encoder must be good, and you need more than one example to cover how the part varies. Chapter 12 asks the next question: once you have ten labelled examples, should you prompt with them or fine-tune on them?

When can a prompt replace a custom detector?

Every model on this page can be run on your images today with nothing but a list of names. The question is how close that gets you to a detector trained on your own labels. Four independent measurements answer it, and they agree.

Guess first. On industrial images, how many labelled boxes per class does a fine-tuned detector need before it beats the best prompt-only model? A hundred? A thousand? Pick a number, then look at the second column of the chart.

Read the Industrial column from left to right. The best prompt-only model, Grounding DINO with every class name in one prompt, averages 10.3 AP. The same model fine-tuned on 10 boxes per class reaches 37.8. Even YOLOv8n, a small detector with no text encoder at all, trained on those same ten boxes, scores 28.1, which beats every model that only reads a prompt. The last two columns come from closed-set detectors (YOLOv8, YOLOv11 and LW-DETR), because RF100-VL did not run Grounding DINO with more labels. With 10% of the training images labelled they reach 50.7 to 52.9, and with all labels 64.3 to 68.2. So the answer to the guess is ten. Ten labelled boxes per class beat the prompt by a wide margin, and every further step up in labels still pays. Read the columns as label budgets, not as one model's learning curve: the units differ (ten boxes per class, a random tenth of the training images, all of them), and a single 10-shot run is noisy.

A decision guide

The four cards turn into a short checklist. This is our reading of the evidence, not a result from any one paper.

How they fail on rare industrial objects

Chapter 12 measured how far a prompt falls short on unfamiliar data. This chapter asks why. The papers point to seven separate causes, and each has a different fix, so it pays to know which one you are hitting.

Guess first. You type porosity, the welder's word for small gas holes in a weld. Where will its text vector land: near the image features of weld pores, or somewhere else? Press Type the jargon name and see.

1. The name is jargon, an acronym or a word with another meaning

A text encoder learned each word from web captions. "Porosity" in a caption usually means rock or skin, not a weld. RF100-VL chose its datasets to make exactly this hard: it lists context-dependent names such as "Thunderbolt", a defect on a wire rope, scientific acronyms, and catch-all classes such as "Soft Plastic" (RF100-VL Fig. 2). The cheapest fix is to describe the look in common words, and GLIP measured it.

On the Mushrooms dataset the original labels were the species names Cow. Chanterelle, which scored 13.6 AP. The prompt flat mushroom. yellow mushroom scored 73.8. hand of a person instead of hand took EgoHands from 22.1 to 50.0. Rewriting does not always help: Pothole stayed at 17.8 to 17.7. When the labels are not words at all, a prompt has nothing to work with: MM-Grounding-DINO scores 0.4 AP zero-shot on a brain-tumour dataset whose classes are numeric codes, and 47.5 after fine-tuning. Grounding DINO's own worst ODinW case is PlantDoc, with names such as "Tomato leaf mosaic virus": 0.36 AP for the T model trained with Cap4M.

2. Your label policy is not the web's meaning

A class name is short; an annotation guide is long. The Foundational Few-Shot paper shows the gap on nuImages, a driving dataset with 18 classes: its guide boxes only the cab of a truck, and counts a rider as part of a bicycle (2312.14494v4, Fig. 1). A model that learned "truck" from the web boxes the whole vehicle and is scored as wrong. Every inspection line has rules like this: where a scratch ends, whether two touching pores are one defect, which side of a part counts. No prompt carries them; a few labelled examples do.

3. A defect is often a texture, not an object

Every model on this page learned to box things with edges: people, cars, pallets. Its proposals, queries or objectness scores were trained on such boxes. A stain, a corrosion patch or a faint surface scratch has no clear boundary and often fills the whole view. our reading: expect such targets to be missed or boxed arbitrarily, and treat them as a segmentation or anomaly-detection problem rather than a prompt problem. The sources measure this only indirectly; ViLD's most common failure on rare LVIS classes is a missed object, not a wrong name (ViLD App. A).

4. Small defects vanish when the image is resized

These models do not see your camera's full resolution. OWL-ViT B/32 resizes to 768 pixels and reads 32 pixel patches; OWLv2 L/14 uses 1008 pixels and 14 pixel patches; GLIP-T tests at 800 by 1333 with a finest stride of 8 in its official config; YOLO-World's released models take 640 pixels (official code).

A twenty-pixel defect in a 4,096-pixel frame becomes a few pixels at the model's input, a small fraction of one patch. The token that should report it is mostly background. The fix is not a better prompt: crop or tile the image so the defect stays large, or fine-tune at a higher resolution.

5. The score does not tell you when to stop

An inspection system needs a threshold: above it, reject the part. Open-vocabulary scores make that hard. With no threshold, a detector always returns its best boxes, so it fires on every image, including parts with no defect. Described Object Detection measured what a threshold buys for Grounding DINO.

Without a threshold, false alarms on clean images are at 100.0%. At 0.5 they fall to 60.6% while mAP drops from 20.7 to 18.4; at 0.9 they reach 8.5%, and mAP collapses to 3.8. No threshold gives both. The papers add two warnings. CLIP's score for a crop does not reflect how well the box fits (ViLD App. B). Fine-tuned models' scores on unfamiliar queries "may be poorly calibrated and may depend on the precise wording of the query" (OWLv2 Sec. 5). our reading: a threshold tuned for one prompt will not transfer to the next one, so set it per class, on your own labelled images.

6. Attributes and "not" are mostly ignored

7. Fine-tuning fixes your classes and costs the rest

Chapter 12's last card is the seventh cause. Once you fine-tune on your defects, the model's open-vocabulary behaviour on other domains drops: OWL-ST L/14's median over 35 ODinW datasets fell from 16.2 to 6.3. If you need both, keep the original weights next to the fine-tuned ones.

What to do on a new inspection task

our reading, combining the seven causes:

  1. Label a test set first: a few hundred images including clean parts, so false alarms are counted.
  2. Try the prompt as a plain description of the look, one class per prompt and one at a time, and measure.
  3. Crop or tile so the smallest defect covers at least a patch at the model's input.
  4. If the prompt falls short, label about ten boxes per class and fine-tune an open-vocabulary detector; it was the best few-shot learner in RF100-VL.
  5. Set thresholds per class on your clean and defective images, never once for all prompts.

Family tree

Six papers carried this page, and a family grew around them. Here are 22 of them on one time axis: each sits at the date of its first arXiv version, in a lane for where text enters the network.

Guess first. Between 2021 and 2025, did text move deeper into the detector, or back out of it? Press Spine only, then Add the branches, and read each lane from left to right.

It did both. From 2021 to 2023 the grounding line pushed text deep into the network: MDETR (2021-04-26) reads image and text tokens in one joint encoder, GLIP (2021-12-07) fuses them in its top encoder layers, and Grounding DINO (2023-03-09) adds text at three places. Then the cost of fusion pulled text back out. The classifier-only lane never went away. It runs from OVR-CNN (2020-11-20), which named the task, through ViLD and Detic to OWL-ViT and OWLv2. These models pay the least for a new prompt, because the text encoder runs once per class name, whatever the image. Summary

An open-vocabulary detector is an ordinary detector whose class list has been replaced by a text encoder, so a new class is a new sentence instead of a new training run. The five designs on this page differ in where the text enters. ViLD and OWL-ViT use it only at the final score, which keeps the image side fixed and makes thousands of queries cheap. GLIP and Grounding DINO fuse it into the encoder, and Grounding DINO also uses it to choose its queries and inside its decoder, which makes the image features depend on the prompt. YOLO-World fuses it into the neck and then folds the vocabulary into the weights for speed. All of them inherit what the text encoder learned from web captions. That is their strength on common objects and their weakness on yours: on rare domains a prompt alone scores far below a model fine-tuned on ten boxes per class, and the failures have specific causes (jargon names, label policies, texture-like targets, small defects, uncalibrated scores, ignored modifiers, forgetting) with specific fixes. Start with a prompt, judge it on a labelled test set that includes clean parts, and fine-tune an open-vocabulary detector when it falls short.
